## §0 정의 — 4.0이란 무엇인가

3.0에서 채널별로 병렬 구축한 디자인 자산을 **한 척추(디자인 코어 CT)**에 다시 걸고, 그 위에서 ②**정예 골든 템플릿 체계**와 ③**행사 자동 완성 엔진**을 완성한다. 신기능 개발이 아니라 기존 부품의 재배선+승격이다.

### 품질 헌장 (Harold 명시 2026-07-14 — 본 설계 전체를 지배)

1. **템플릿은 색깔놀이가 아니다.** 테마(색·서체)만 바꾼 변형은 템플릿으로 세지 않는다. 템플릿의 정의 = **목적(전환 목표) × 스토리 구조(콘텐츠 골격) × 조판 × 데이터 슬롯(상품·개인화·행사)**. 네 축 중 목적·스토리가 다를 때만 별개 템플릿이다.
2. **수량보다 품질.** "제대로 된 10개가 숫자만 많은 50개를 이긴다." 1차 목표 = 정예 10종(각각 §3.4 품질 게이트 통과 + Harold 시각 승인). 확장은 10종이 검증된 후에만.
3. **단순 양산 금지 장치**: 각 템플릿은 등록 시 "이 템플릿이 만드는 차이"(어떤 목적에서 왜 다른 템플릿보다 나은가) 서술을 의무 필드로 갖는다. 이 서술이 기존 템플릿과 구분되지 않으면 등록 불가.

## §3 정예 골든 템플릿 체계 (본체)

### 3.1 리서치 근거 (2026-07-14 웹 실측 — 출처는 문서 말미)
- **캔바**: 템플릿을 색이 아니라 **업종 × 이메일 타입(용도) × 콘텐츠 성격**(이미지 중심/텍스트 중심/혼합)으로 분류. 수백 종의 실체는 이 3축 조합.
- **이커머스 ESP(Klaviyo 계열)**: 고전환 템플릿의 해부학 = **약속(훅·히어로) → 증거(가치 제안·사회적 증거) → 행동(CTA)** 시퀀스. 사회적 증거는 스크롤 전+CTA 근처 이중 배치, CTA는 primary/secondary 2단 규율, 동적 상품 피드 슬롯 내장. 낱장 템플릿보다 **"마스터 템플릿 시스템"**(브랜드 일관성)을 상위 개념으로 둠.
- **Braze 인앱**: 템플릿의 정체가 형태(모달/슬라이드)가 아니라 **유즈케이스**(온보딩 플로우·선호 수집 설문)이며, **발동 타이밍**(의미 있는 순간 뒤)이 템플릿 정의에 포함됨.

→ 종합: 좋은 템플릿 = "형태·색"이 아니라 **"목적 있는 스토리 구조 + 데이터 슬롯 + 발동 맥락"**. 우리 우위는 여기서 나온다 — 캔바 템플릿엔 데이터 슬롯(고객·상품)이 없고, 우리 것엔 실데이터가 흐른다.

### 3.2 템플릿 스키마 (채널 중립)

```
GoldenTemplate {
  id, label,
  purpose:        전환 목표 (첫구매 | 재구매 | 회복 | 관계 | 공지 | 긴급성),
  difference:     "이 템플릿이 만드는 차이" 서술 (의무 — 품질 헌장 3),
  story:          스토리 구조 (블록 시퀀스의 논리 — 훅→맥락→증거→혜택→행동 등 명시),
  data_slots:     [상품(live), 개인화 변수, 행사 원문, 사회적 증거(후기·판매수)] 중 사용 슬롯,
  trigger_hint:   권장 발동 맥락 (인앱=트리거, 이메일/DM=발송 시점),
  design:         테마·구도·모션 큐레이션 (코어 팔레트 참조 — 리터럴 금지),
  channels:       파생 가능 채널 + 채널별 조정 규칙 (예: 인앱=압축 스토리, 이메일=증거 확장)
}
```

### 3.3 1차 정예 10종 후보 (구현 세션에서 각각 difference 서술과 함께 확정 — Harold 컨펌 대상)

| # | 목적 | 스토리 구조 (골격) | 핵심 데이터 슬롯 |
|---|---|---|---|
| 1 | 첫구매 (신규 환영) | 환영 → 브랜드 서사 → 첫 방문 길잡이 → 부담 없는 행동 | 개인화(이름)·브랜드킷 |
| 2 | 회복 (장바구니) | 담아둔 것 상기 → 상품 실물(살아있는 카드) → 망설임 해소(증거) → 행동 | **상품 live**·개인화 |
| 3 | 회복 (휴면) | 안부 → 그동안의 변화(신상 축약) → 다시 올 이유 → 행동 | 상품 live·개인화 |
| 4 | 재구매 (소모 주기) | 지난 구매 상기 → 재구매 시점 논리 → 원클릭 행동 | 구매이력·상품 live |
| 5 | 긴급성 (마감 세일) | 시한 선언(카운트다운) → 대상 상품 → 놓치면 잃는 것 → 행동 | 행사 원문·상품·카운트다운 |
| 6 | 관계 (VIP 프라이빗) | 자격 인정 → 프라이빗 제안 → 격조 있는 행동 | 등급·개인화 |
| 7 | 공지 (신상 발표) | 기대감 훅 → 신상 공개(비주얼) → 첫 반응 유도 | 상품 live·행사 원문 |
| 8 | 증거 (후기·신뢰) | 사회적 증거 선행(별점·판매수) → 대상 상품 → 행동 | 후기 데이터·상품 |
| 9 | 관계 (구매 후 팔로업) | 감사 → 사용 가이드/케어 → 다음 단계 제안 | 구매이력 |
| 10 | 공지 (행사 초대) | 초대 서사 → 행사 핵심(원문 기반) → 참여 행동 | 행사 원문·상품 |

각 템플릿은 3채널 파생 규칙 포함(= 산출물 최대 30종이지만 **템플릿은 10개**로 센다). 기존 3.0 골든 12종×3채널은 유지하되, 4.0 정예 10종이 검증되면 구식 항목을 단계적 대체.

### 3.4 품질 게이트 (등록 조건 — 전 항목 통과만 등록)

1. difference 서술이 기존 템플릿과 명확히 구분되는가
2. 스토리 구조가 목적에서 논리적으로 도출되는가 (블록 나열이 아니라 시퀀스 논리)
3. 데이터 슬롯을 최소 1개 실사용하는가 (정적 디자인 = 탈락 — 캔바와의 차별 축)
4. 실데이터 미리보기에서 성립하는가 (긴 상품명·무이미지·변수 빈값 엣지)
5. 3채널 파생이 각 채널 제약 안에서 성립하는가 (안 되는 채널은 명시 제외 — 억지 파생 금지)
6. 혜택 수치 0 (placeholder 규약 — AI 임의 혜택 영구 룰)
7. **Harold 시각 승인** (스크린샷 제출 → 승인 후 등록)

### 3.5 양산 확장 정책
10종 전부 게이트 통과 후에만 확장 논의. 확장 시에도 게이트 동일 적용 — "숫자 채우기" 배치 작업 금지, 회당 최대 5종.

## §4 행사 자동 완성 엔진 (기존 부품 재배선)

**목표**: 행사 입력(텍스트 or 이미지) 1회 → 3채널 캠페인 패키지(문안+디자인+상품 매핑+템플릿 선택) 자동 완성 → 각 채널 편집기로 1클릭 진입.

```
입력(텍스트/이미지)
  → [기존] 이미지 판독(원클릭 캠페인) ─┐
  → [기존] normalizeEventText          ├→ 행사 브리프(단일 정규화 객체 — 신설: design-core/event-package.ts)
  → [기존] extractEventProducts        │    상품(name·가격·link_url·og image) + 기간 + 혜택(원문 verbatim)
  → [기존] fetchProductOgImages       ─┘
  → [신설] 템플릿 선택기: 브리프 성격 → §3 정예 10종 중 결정적 매칭(임의 산식 0 — 매핑표)
  → [기존] 채널 생성기 3벌(dm-ai·email-ai·inapp-ai-generator)에 브리프+템플릿 주입
  → 산출: 3채널 초안 (기존 행사 초안 배관 재사용 — EVENT_*_DRAFT_KEY·편집 진입)
```

원칙: 채널 생성기 내부는 무접촉(3.0에서 검증·적대 리뷰 통과분). 신설은 "브리프 정규화 객체"와 "템플릿 선택기" 두 조각뿐이며, 검증(가격·URL verbatim·혜택 실존)은 기존 event-brief 게이트를 그대로 통과한다.

- 아트디렉션 리터럴 이관: dm-viewer·dm-canvas·email 렌더러·인앱 테마 — 값 무변 이관이므로 M0 스냅샷이 판정.

- 템플릿 레지스트리: 각 채널 편집기 골든 모달 + (DM) buildStyledSections — 스키마 어댑터로 흡수.
- AI 추천 코어화: 3 생성기의 추천 상수 — 값 무변 이관.
- SDK: 번들 크기 예산 재확인(현 78.7KB, 상한 85KB — 코어 미러는 값이라 증가 미미 예상, 실측 의무).
- 크레딧·발송·트리거·법 준수 로직: 전부 무접촉.
