# 싱크에이전트 사전 질의서 — SoT (v1.0 · 2026-08-13)

> **출고 게이트다.** 신규 고객사 출고는 이 질의서 회신 → 회신대로 리허설 구성 재현 → 마법사 전 구간 자동 주행 → smoke → 등재 → 출고 순서만 탄다. **회신 없이 출고하지 않는다.**
>
> 기원 — 리허설(VM·smoke)은 픽스처에 넣은 구성만 지킨다. 이새(Oracle·뷰·2008R2)와 아난티(Aurora·크로스 DB 뷰·뷰 전용 계정)
> 모두 우리가 픽스처에 안 넣은 구성에서 터졌다. 질문 세 줄이면 설치 전에 나왔을 것들이다.
>
> 고객 전달본은 `build-questionnaire.js`로 생성한다(`SyncAgent_사전질의서_v1_0.docx`). **이 MD를 고치면 docx도 재생성한다 — zip·매뉴얼과 같은 세트 규칙.**

## §2 내부 처리표 — 회신 항목이 무엇을 결정하는가 (고객 전달본에는 넣지 않는다)

| 회신 | 결정하는 것 | 어긋났을 때의 실사고 |
|---|---|---|
| 1-1 OS 버전 | **빌드 티어**(win-modern/2012/2008r2) — `agent-build-tiers.ts` 판정 축 | 2008 R2에 node20 빌드 = 실행 불가 |
| 1-2 OS 언어 | **리허설 콘솔 로케일** — 한국어판이면 CP949 콘솔에서 한글 표시까지 밟는다 | 아난티 한글 전멸(영문 VM에서는 증상이 안 난다) |
| 2-1~2-3 DB·클라우드·TLS | 드라이버 zip 선택 · 마법사 TLS 항목 사전 안내 | Aurora TLS 강제 = 평문 접속 서버 거부(3159) |
| 3-1~3-3 테이블/뷰·크로스 DB | **리허설 픽스처의 형태** — 뷰면 뷰로, 뷰 전용 계정으로 재현해 마법사 자동 주행 | 아난티 뷰 0개 감지·무한 재질문 |
| 3-4 행수 | 유일성 검사(COUNT DISTINCT)·전량 동기화 소요 예측 — 수백만 행이면 검사 타임아웃(30초) 사전 판단 | 미실측 잔여 위험(1.7.1 §7) |
| 3-5 고유 컬럼 | **지정 키 후보** — 뷰(PK 메타 없음)면 설치 중 이 컬럼을 고르게 된다. 없다는 답이 오면 **출고 전에** 뷰에 키 컬럼 추가를 요청한다 | 키 없이 설치 = 최초 전량 후 갱신 영구 0건(이새식 조용한 정지) |
| 3-6 일시 컬럼·시각 유무 | 증분 기준 컬럼 사전 확정. **날짜만**이어도 1.7.0 커서(닫힌 버킷)가 처리하지만 리허설 픽스처에 같은 형태로 넣는다 | 이새 한 달 유실(시각 없는 판매일 × 옛 커서) |
| 4-1~4-3 계정·허용 호스트 | 매뉴얼 GRANT 문 실값 제공(원격 IP — localhost 예시 금지) · 리허설 계정도 같은 권한 폭으로 | 아난티 초기 오진(권한 vs 뷰) 왕복 |
| 5-* | 검수·설치 일정 역산 | — |

**출고 판정** — §1 회신이 전부 채워지고, 3-5에 고유 컬럼이 실재하고, 회신 구성 그대로의 리허설(마법사 자동 주행 + smoke)이 통과했을 때만 zip이 나간다. 회신과 실환경이 다르면 그 차이는 고객 책임이 아니라 **질의서 문항 결함**으로 본다 — 문항을 고치고 버전을 올린다.
