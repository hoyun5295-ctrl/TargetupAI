### 0-2. "행사내용을 아무리 넣어도 상품 카탈로그만 반영"의 근본 (코드 확정)
- 흐름: `routes/dm.ts one-shot-generate` → `oneShotGenerate`(dm-ai.ts:621) → ① `parsePrompt` = 행사 원문을 **CampaignSpec(목적·톤·혜택 1개·타겟) 요약으로 압축** ② 섹션 체인 설계 ③ 섹션별 `generateCopy(spec, section)` — **spec 요약만 입력, 행사 원문은 안 받음**.
- 즉 행사 원문의 일정·품목별 혜택·유의사항·장소·링크가 **CampaignSpec 병목에서 소실**된다. 예외는 상품뿐 — `extractEventProducts`가 원문에서 직접 추출해 product_carousel에 주입(2026-07-08). 그래서 "상품만 반영"이 정확한 체감.
- 이미지 입력: 편집기 AI 경로에는 이미지 이해 입력 자체가 없음(원클릭 캠페인의 이미지 판독은 별도 흐름).

### 0-3. "슬라이드형은 공간이 비어 나온다"의 근본 (코드 확정)
- 슬라이드는 **생성 후 규칙 분할**(dm-page-split.ts — 시각 섹션 있으면 slides, 페이지 쪼개기)과 **이미지 전용 페이지 펼치기**(dm-slides-expand.ts)뿐.
- "슬라이드 한 장 = 하나의 완성된 화면"을 설계하는 단계(장별 역할·콘텐츠 밀도)가 없다 → 섹션 1개짜리 헐렁한 장이 나온다.

### 0-4. "히어로만 궁서체"의 근본 (코드 확정)
- hero 헤드라인만 `font-family:var(--dm-font-display)` 소비(dm-section-renderer.ts:208·227). 본문·다른 섹션은 시스템 산세리프.
- 디스플레이 서체(명조 계열 추천 잦음)가 뷰어에서 **로딩 실패하면 브라우저 기본 세리프(바탕=궁서 체감) 폴백** → "히어로만 궁서체".
- 근본 수정 = 2026-07-16 서체 자가호스팅(커밋 e1e3c61b·24b4e9e8 — 구글CDN 의존 제거, 우리 서버 woff2 서빙 + 재발 게이트). **코드는 완료됐으나 서버 미배포 상태라 계속 재발처럼 보임.**
- 처방(2겹): ① 이번 배포에 자가호스팅 포함(1순위) ② 뷰어 CSS의 `--dm-font-display` 폴백 스택 끝을 명시 산세리프(Pretendard 계열)로 종료 — 어떤 실패에도 세리프 폴백 자체가 불가능하게(구조적 차단). 재발 게이트(커밋 내 포함)로 고정.

## 1. 새 편집기 — 3층 구조 (IA)

> 목표: "**붙여넣고 → 확인하고 → 발행한다**". 학습이 필요한 메뉴 0.

```
[1층 만들기]  AI 브리프 입력기 (단일 진입) ── 행사내용 장문 + 이미지 통업로드 + URL
      ↓ 완성 DM (스토리보드 기반, 브리프 반영 검증 통과)
[2층 다듬기]  캔버스 직접 편집 + 전역 퀵바 (서체·색·테마·모션 1클릭)
      ↓
[3층 내보내기] [발행] 단일 버튼 = 자동 검수 → 발행 → 발송/테스트 발송
```

### 1-1. 상단 바 (재설계)
`← 뒤로 | 제목 | 저장상태 ·· undo/redo | 스크롤/슬라이드 토글 | [⚡ AI로 만들기] | [발행]`
- **[도구] 드롭다운 폐기. [정예 템플릿] 폐기**(Harold 명시).
- [⚡ AI로 만들기] = 1층 AI 브리프 입력기(§2). 상단 바에서 가장 눈에 띄는 버튼.
- [저장]은 자동 저장으로 전환(현행 store 기반 — 수동 버튼 제거, 저장상태 라벨만 유지). 발행 DM 수정 시 "저장해야 URL 반영" 라벨은 유지.
- [발행] = 검수 내장(§1-4).

### 1-2. 기존 도구 9종 처치표 (심플≠비우기 — 진입점은 자연스러운 자리로 이동)
| 기존 | 처치 | 이동 위치 |
|------|------|-----------|
| 프롬프트로 AI 초안 | **승격** | [⚡ AI로 만들기] (브리프 입력기로 전면 재설계) |
| AI 문안 개선 | 이동 | 섹션 선택 시 캔버스 인라인 [✨ 다듬기] 버튼 (전역 메뉴 아님) |
| 브랜드 킷 | 자동화 | AI 생성 시 자동 적용 + 전역 퀵바 [브랜드 색]. 편집 모달 진입은 퀵바 안 "관리" |
| 디자인 테마 | 이동 | 전역 퀵바 [테마] (기존 비파괴 테마 모달 그대로 — 색·서체만 패치) |
| 정예 템플릿 | **폐기** | (EliteTemplateModal·golden-templates DM 노출 제거. 서버 정의는 이메일·인앱 공용이라 보존) |
| 자동 검수 | 내장 | [발행] 클릭 시 자동 실행 — 통과=발행 진행, 실패=문제 항목+바로가기 표시 |
| 버전 히스토리 | 후퇴 | 자동 저장 이력은 백그라운드 유지. 진입은 목록 카드 '⋯ 더보기'로 이동 |
| A/B 테스트 | 이동 | 발송 모달(DmSendAndTrackModal) 단계로 이동 — "발송 방식" 선택지 |
| 테스트 발송 | 내장 | 발행 완료 화면 + 발송 모달의 [내 폰으로 테스트] 버튼 |

### 1-3. 전역 퀵바 (Harold 예시 "폰트 정정" 일반화 — 죽은 컨트롤 금지)
데스크탑 = 캔버스 상단 얇은 바 / 모바일 = 하단 메뉴 교체. 항목 4개 고정:
1. **[서체]** — 무료 글꼴 12종 그리드. 선택 즉시 **전 섹션 display+body 일괄 적용**(brand_kit.art_direction 갱신 → 캔버스/SSR 동시 반영). "Pretendard 누르면 전부 적용"이 정확히 이것.
2. **[색]** — 브랜드 색 1클릭 복원 + 팔레트 (accent 일괄).
3. **[테마]** — 기존 디자인 테마(비파괴) 모달.
4. **[모션]** — 켬/끔.
- 모바일 하단 메뉴의 "섹션 추가"는 유지(캔버스 편집의 본질 기능) — 나머지 나열 제거.
- 원칙: 퀵바 항목은 dm-property-contract 계약표에 "실소비 검증"이 있는 속성만. 컨트롤 신설 = 계약표 등재 의무(기존 게이트 재사용).

### 1-4. 발행 플로우 (검수 내장)
[발행] 클릭 → ① 자동 검수(dm-validate — 현행) 인라인 실행 → ② 실패: 항목별 "바로 고치기" 점프 / 통과: 발행(100크레딧 모달 현행) → ③ 완료 화면에 [내 폰으로 테스트] [발송하기] [주소 복사].

### 1-5. 세부편집 재설계 — "보이는 걸 만진다" (초등학생 조작성 기준)
> 판정 기준: **설명 없이, 처음 보는 사람이, 보이는 것을 눌러서 고칠 수 있는가.** (서수란 피드백 직접 대응)

1. **캔버스 직접 조작이 1급 편집기.** 텍스트 = 캔버스에서 바로 타이핑(InlineEditable 현행 확장 — 전 텍스트 요소), 이미지 = 탭 → [교체/업로드/삭제] 3버튼, 섹션 = 드래그로 순서·길게 눌러 삭제. 우패널 폼을 열지 않고도 내용 편집이 전부 가능해야 한다.
2. **속성 폼 나열 폐지 → 핵심 3컨트롤.** 섹션 선택 시 우패널(모바일=바텀시트)에는 그 섹션의 **최중요 3개만**(예: 히어로 = 이미지·헤드라인·버튼) + [고급 ▾] 접힘(나머지 전부 — 기존 기능 보존, 기본 은닉). 어떤 섹션도 접기 전 컨트롤 3개 초과 금지(기계 검증 가능한 규칙).
3. **개발자 용어 노출 0.** `beauty-elegant`류 코드값·영문 enum이 사용자에게 보이는 것 전면 금지 — 선택지는 전부 한국어 라벨+미니 썸네일 카드로. 재발 게이트: 편집기 select/option/라벨의 영문 코드값 노출 grep 테스트.
4. **죽은 컨트롤 제거.** dm-property-contract "실소비 검증" 없는 컨트롤은 노출 금지(있는데 안 먹는 컨트롤 = "기능적 뒷받침이 안 된다"는 직원 체감의 근본). 공통 속성 중 소비처가 특정 구도뿐인 것(하단 연결부·위 섹션 겹침 등)은 해당 구도에서만 [고급]에 노출.
5. **AI 재생성 제외·표시 토글** 같은 운영성 속성은 섹션 우클릭(모바일 길게 누름) 컨텍스트 메뉴로 이동 — 편집 화면에서 항상 보일 이유가 없다.

## 2. AI 브리프 입력기 — "행사내용을 완벽하게 이해" (기술 핵심)

### 2-1. 입력 3종 (한 화면)
- **행사내용 붙여넣기** (장문 그대로 — 글자수 제한 2,000 → 8,000 확대)
- **이미지 통업로드** (행사 포스터·상품컷 N장 — 멀티모달 판독으로 텍스트·상품·혜택 추출. 원클릭 캠페인의 이미지 판독 파이프라인 재사용)
- **행사 URL** (페이지 본문·og 메타 수집 — 기존 상품 og:image 수집기 확장)
- 셋 다 선택적·병합 가능. 추가 요청(톤·강조점) 한 줄 입력란.

### 2-2. 정보 병목 제거 — EventBrief 구조화 계약 (CampaignSpec 요약 경유 폐지)
```
원문(텍스트+이미지 판독+URL 본문)
  → [추출] EventBrief {
      행사명, 기간(시작/종료), 장소/채널, 핵심 혜택 목록[{대상 품목/조건, 내용}],
      상품[{이름, 가격, 할인, 링크}], 공지·유의사항[], 링크[], 톤 힌트, 브랜드
    }   ← 없는 항목은 null 정직(임의 생성 금지 — AI 혜택 생성 금지 영구 룰 준수)
  → [설계] 스토리보드: 장(페이지)별 역할·콘텐츠 배정 (§2-3)
  → [작성] 섹션 카피: 입력 = EventBrief 전체 + 원문 + 해당 장의 배정 콘텐츠
            (현행처럼 spec 요약만 주지 않는다 — 소실 지점 제거)
  → [검증] 반영 커버리지 게이트 (§2-4)
```
- `utils/event-brief.ts`(기존)를 EventBrief 추출 CT로 확장 — **DM·이메일·인앱 3채널 공용**(§4).
- 상품 추출·URL 실존 검증·og 이미지(기존 검증 로직)는 EventBrief.상품[]으로 흡수.

### 2-3. 슬라이드 스토리보드 (빈 슬라이드 구조적 차단)
- 생성 시 레이아웃 모드를 먼저 확정(내용 기반 — 현행 decideLayoutMode 유지)하고, **슬라이드면 "장별 설계"를 AI 산출물로 받는다**: `[{장 역할: cover|benefit|products|notice|closing, 배정 콘텐츠, 섹션 구성}]`.
- 장별 최소 밀도 규칙(기계 검증): cover=헤드라인+기간+비주얼, benefit=혜택≥1+설명, products=상품≥2 또는 1+상세, closing=CTA+마감. 미달 장 = 인접 장과 병합(빈 장 발행 자체가 불가).
- 스크롤 모드는 현행 섹션 체인 + 카피(입력만 EventBrief로 교체).

### 2-4. 반영 커버리지 게이트 (겉만 화려한 빈껍데기 차단 — 인앱과 같은 철학)
- 생성 직후 기계 검증: EventBrief 핵심 항목(기간·혜택 각각·상품·유의사항·링크)이 섹션 props 어디에 반영됐는지 매핑 → **미반영 항목은 1회 자동 보강 생성 → 그래도 남으면 적용 화면에 "미반영 항목" 명시**(조용한 누락 금지 — 정직 피드백 원칙).
- 계약 테스트: 골든 입력으로 커버리지 하한 고정. **골든 1호 = 시세이도 실브리프**(Harold 제공 2026-07-16 — 상품 5종(정가→15% 할인가·네이버 링크) + 얼티뮨×LISA 이벤트(구매 조건 증정·포토엽서 1매 랜덤·한정 수량 유의)). 기대 산출(브로셔 기준):
  - 상품 5종 → 상품 카드(이름·정가 취소선→할인가·15% 뱃지·링크 연결·og 이미지 자동) 전원 반영 — 누락 0
  - 얼티뮨×LISA → **별도 이벤트 섹션**(증정 조건·랜덤 1매·한정 수량이 유의 문구로) — 상품 카드에 뭉개지 않는다
  - 헤드라인·기간·브랜드 톤 자동 — 사용자가 할 일은 "약간의 수정"뿐
  - 골든 2·3호 = 신메뉴 출시·멤버십 감사 원문.

### 2-5. 상품 이미지 자동 확보 — 폴백 체인 CT (Harold 질의 2026-07-16 검증 결과)
> **실측**: brand.naver.com(스마트스토어) 상품 페이지는 서버 fetch에 **HTTP 429(봇 차단)** — 현행 og:image 수집기(fetchProductOgImages)가 네이버 링크에서 **구조적으로 실패**한다. "링크를 줬는데 이미지가 안 채워지는" 원인.
> **선례**: 한줄전단 CT-F17(flyer-naver-search.ts)이 네이버 쇼핑 검색 API(openapi.naver.com/v1/search/shop.json, 무료 일 25,000건)로 상품명→이미지 자동 매칭을 운영 검증함. 격리 원칙에 따라 코드 이식이 아니라 패턴만 미러해 targetup CT 신설.

**대원칙 (Harold 확정 2026-07-16): 발행물에 자동으로 실리는 이미지는 "그 상품임이 기계적으로 확정"될 때만. 이름 유사도(90%든 99%든)는 확률이지 확정 근거가 아니다 — 자동 채택 기준에서 폐기. 오매칭의 구조적 0가 목표.**

**자동 삽입 = 확정 근거 3가지만:**
1. **자사몰 연동 상품 ID 일치 — 주력 경로.** 고객사가 붙여넣은 스마트스토어 링크(`…/products/{번호}`)의 번호가 곧 커머스 API의 channelProductNo(현행 naver-commerce-client·mall-product-normalize가 이미 이 축으로 동작) → **링크에서 번호 파싱 → 연동된 본인 스토어에서 직조회** = 이름 매칭조차 불필요, 원본 화질 + 정확 가격까지 확정. 카페24 등 타 몰도 같은 원리(링크의 상품 번호 축). ※ 2026-07-16 시세이도 예시가 안 뜬 것은 연동 스토어가 테스트 계정 본인 스토어라 해당 상품이 없어서 — 메커니즘 정상, 실고객(자기 스토어 연동)에게는 이 경로가 기본 동작.
2. **고객 제공 링크의 og:image** (그 페이지의 대표 이미지 = 정의상 그 상품. 네이버 외 몰에서 유효 — 네이버는 429 차단 실측)
3. **검색 API 결과의 상품 ID가 고객 제공 URL의 상품 ID와 일치** — 스마트스토어 URL(products/{id})의 ID와 검색 결과 링크 축이 기계 대조로 일치할 때만. ※ 검색 API link 필드가 ID 대조 가능한 구조인지 **raw 응답 실측 후 확정**(외부 API 응답 추측 금지 영구 룰) — 불가 판명 시 3번 경로 자체를 폐기(1·2·후보 UI로 충분)

**확정 근거가 없으면 자동 삽입 금지 → 원탭 선택 UI:**
- 네이버 쇼핑 검색 API로 후보 이미지 5장을 상품 카드 옆에 제시 + AI가 상품명과 시각 일치 최상 1장을 맨 앞 추천 표시 → **사용자가 탭 1번으로 확정**(선택 순간이 확정 근거 — 정확성과 책임 소재 동시 해결, 초등학생 조작성 유지)
- 발행 검수(dm-validate)에 "이미지 미확정 상품 카드 잔존" 항목 추가 — 빈 이미지로 발행되는 것을 게이트에서 안내

**부가:**
- 근본 확대 = 네이버 커머스 연동 유도: 브리프 입력기에 "스토어 연동 시 원본 이미지 자동" 안내 1줄(연동이 최상 경로임을 사용자에게)
- 검색 API 썸네일 화질 한계 — 1·2순위 존재 시 항상 우선
- 키 = NAVER_CLIENT_ID/SECRET env 신규(한줄전단과 쿼터 분리 — 별도 앱 등록 권장), 초당 제한 스로틀
- 약관: 네이버 오픈API 상업 서비스 허용. 사용 주체 = 고객사 본인 상품 기본

## 6. 성공 기준 (Harold 언어로)
1. 행사내용을 통째로 붙여넣으면(또는 포스터 이미지만 올려도) 기간·혜택·상품·유의사항이 **전부 자리 잡은** DM이 나온다 — 미반영 항목은 숨기지 않고 보여준다. (골든 1호 = 시세이도 브리프가 그대로 브로셔로)
2. 슬라이드마다 알차다 — 빈 장이 구조적으로 안 나온다.
3. **초등학생도 설명 없이 조작한다** — 보이는 걸 눌러 고치고, 섹션당 접기 전 컨트롤 3개, 개발자 용어 노출 0. 직원이 매뉴얼 없이 비슷한 방향으로 만들 수 있다(서수란 기준).
4. 편집기에서 배울 메뉴가 없다 — 만들기(1버튼)·다듬기(퀵바 4개+캔버스)·발행(1버튼).
5. 히어로 궁서체를 다시는 보지 않는다.
6. 같은 골격을 이메일·인앱에 그대로 이식할 수 있다.
