# 문안 퀄리티 엔진 (Cold-start) 설계서

> 작성일 2026-07-04 · 상태: 설계(승인 대기) · 범위: cold-start 문안 퀄리티 엔진 + 라벨 캡처 배관
> 후속 별도 설계: 성과 기반 Tier 2 귀속 엔진(데이터 축적 후) · 예측 '일반' 클릭 base 0.12 통일(소규모 버그, 별건)

## 1. 배경·목표

**문제**: 한줄로 AI 문안이 무료 GPT와 차별화되지 않는다는 고객 인식. 우리 무기(9천+ 실전 캠페인 코퍼스 + 메시징 도메인 지식 + 스팸필터 라벨)가 생성기에 제대로 안 먹여지고 있음.

**확인된 구조적 원인 (2026-07-04 코드 감사)**:
- 브랜드보이스 없는 업체: 검색기가 업종 원문을 생성기에 안 넣음 — Phase 4 격리(`copy-rag-retriever.ts:182` `examples = ranked.filter(e => e.source === 'company')`)가 타사 원문을 전부 제거하고 얇은 통계만 남김 → 모델이 참고할 실전 문안 부재 → GPT 기본값 출력.
- 검색 후보가 성과순이 아니라 최근순(`ORDER BY created_at DESC`).
- KAKAO/브랜드 결과 라벨이 접미사 키 불일치로 안 붙음(발견 1) → "베스트" 선별 근거 부족.

**목표**: 성과 데이터가 아직 없는 지금도 GPT와 차별화된 문안을 생성한다. 두 트랙(브랜드보이스 등록/미등록)에서 각각 만족스러운 퀄리티. 스팸필터 회피를 생성 단계에 내재화.

**비목표(YAGNI)**: GPT 대조 검증 하네스 없음(Harold 명시 2026-07-04 — 완성도만 끌어올림). 성과 기반 자동 랭킹 승급의 Tier 2(전환 귀속)는 후속 설계.

## 2. 핵심 철학 — cold-start → trained

예측 suite의 `v1.1-cold → v1.0-trained` 방식을 문안에 그대로 적용한다. **처음부터 좋고, 데이터가 쌓일수록 더 좋아진다.** "베스트"의 정의를 성과 하나에 걸지 않고, 지금 쓸 수 있는 신호로 정의하되, 성과 신호가 쌓이면 가중치가 자동으로 상위 tier로 이동하도록 설계한다.

해자 = 모델이 아니라 라벨된 데이터. 그래서 (a) 지금 있는 라벨(사람 선택 finalSource, 스팸필터 결과)을 즉시 활용하고, (b) 미래 라벨(클릭·전환)이 새지 않게 캡처 배관을 지금 고친다.

## 3. 두 트랙

- **Track A — 브랜드보이스 등록 업체**: 브랜드보이스를 강한 생성 규칙(톤·금지어·시그니처·문장 리듬)으로 적용 + 그 회사 자신의 베스트 문안을 few-shot. 생성→적합도 채점→미달 시 자동 재생성(사용자에겐 통과분만).
- **Track B — 브랜드보이스 미등록 업체**: 같은 업종 베스트 N을 **탈색(de-brand)** 하여 실제 패턴+예시를 주입. 출처 = 하이브리드(9천 건 자동 채굴 후보 + 상위 사람 검수·보정, 검수 단계에서 탈색·시그니처 제거 겸함).

공통: 도메인 규칙층 + 스팸 위험 회피 + 채점→재생성 루프.

## 4. 아키텍처 — 8 컴포넌트

각 컴포넌트는 단일 목적·명확한 인터페이스·독립 테스트 가능. 신규는 `utils/`의 컨트롤타워로 정의(인라인/중복 금지 룰 준수), 기존은 확장.

### 4.1 베스트 랭커 (신규 CT `utils/copy-best-ranker.ts`)
- 목적: 후보 문안을 "지금 쓸 수 있는 가장 강한 신호"로 점수화 → 베스트 N 반환.
- Tier 0 신호(지금): 사람 선택(`final_source` = selected/edited 가중) + 규정·스팸 통과 + 구조 루브릭 점수 + 큐레이션 검수 플래그.
- Tier 1(몇 주 후 자동): 클릭·열람. Tier 2(성숙): 전환 귀속.
- 설계 요건: tier별 가중치가 데이터 가용량(신뢰도)에 따라 자동 이동. 신호 없으면 하위 tier로 폴백(중립).
- 입력: 후보 rows(문안+메타+라벨). 출력: 점수·정렬된 베스트 N. 의존: 루브릭·스팸 위험 점수.

### 4.2 탈색 모듈 (신규 CT `utils/copy-deidentify.ts`)
- 목적: 타사 문안에서 회사명·시그니처 표현·고유 혜택/숫자·연락처를 제거하고 "먹히는 구조"만 남김(훅·길이·CTA·감정선·오퍼 프레이밍).
- 사용처: (1) 하이브리드 검수 파이프라인, (2) 검색 시점 안전망(이중 방어).
- 불변식: **시그니처 누출 0** — 출력에 원 회사 식별정보가 남으면 안 됨(테스트로 강제).

### 4.3 검색 업그레이드 (기존 `copy-rag-retriever.ts` 확장)
- Track B: 현재의 "업종 원문 통삭제"를 **"탈색된 업종 베스트 N + 패턴 주입"** 으로 교체. 격리(시그니처 누출 0)는 탈색으로 유지하되 품질 복원.
- Track A: 자사 코퍼스에서 베스트 랭커로 베스트 우선 주입(최근순 → 베스트순 보정).
- 정직 폴백 유지: 표본 부족 시 빈 결과(가짜 예시 금지) — 기존 `MIN_TOTAL_SAMPLE` 로직 계승.

### 4.4 도메인 규칙층 (신규 CT `utils/copy-domain-rules.ts`)
- 목적: 채널별 제약 — SMS 바이트 한도, 광고표기·무료수신거부 규정, 카카오 템플릿 규칙, 구조 루브릭, 그리고 4.8의 스팸 위험 사전.
- 적용: (a) 프롬프트 제약("이런 표현 피하라"), (b) 생성 후 로컬 검증(빠른 스캔).
- 채널별 모듈 분리(SMS/LMS/MMS/KAKAO/EMAIL/DM), 공용 인터페이스.

### 4.5 채점→재생성 루프 (신규 오케스트레이터 `utils/copy-quality-loop.ts`, `composeCopyBrain` 호출부에 접합)
- 목적: 초안 생성 → 채점(Track A 브랜드보이스 적합도 + 도메인 규칙 통과 + 루브릭 + 스팸 위험) → 미달 시 피드백 담아 재생성 → 통과분 반환.
- 재생성 상한 = 2회(무한 루프·지연 방지). 상한 도달 시 최고점 초안 반환.
- 문안 생성 모델 사용(백엔드 파라미터, UI 모델명 노출 금지 룰 준수).

### 4.6 큐레이션 시드 저장 (`ai_training_logs` 플래그 확장 — 새 테이블 최소화)
- 하이브리드 검수를 통과한 업종 베스트에 검수·베스트 플래그. 컬럼 추가 여부·명칭은 구현 전 information_schema 확인 후 확정(§15).

### 4.7 라벨 캡처 배관 수정 (발견 1 — 데이터 안 버리기)
- 문제: KAKAO 로그 source_ref = `hmac(appEtc1:kakao)`(`sms-queue.ts:1002`) / `hmac(campaignId:brand)`(`brand-message.ts:390`), 결과 환류는 `hmac(campaign.id)`/`hmac(run.id)` 평문만 → 접미사 행 영구 무라벨.
- 수정 방향: 결과 동기화가 캠페인의 KAKAO/브랜드 성적을 집계할 때, 대응 접미사 source_ref(`:kakao`·`:brand`)로도 `updateTrainingMetrics`를 호출(접미사 규칙 기지 → 재구성 가능). 스키마 변경 최소. 정확한 접합점·키 재구성은 구현 계획에서 확정.
- 목적: 첫 실전 코호트 결과를 첫날부터 깨끗이 담아 4.1 랭커의 미래 승급 연료로.

### 4.8 스팸 위험 분석기 (신규 — 오프라인 배치 + 런타임 스캔)
- 오프라인(신규 워커 `utils/copy-spam-analyzer-worker.ts`): 스팸필터 기록을 주기 채굴 → 스팸 유발 신호(단어·문구·특수문자·과장·URL 패턴)를 "스팸 위험 사전"으로 정리. 새 기록으로 사전 지속 개선(flywheel).
- 런타임(신규 CT `utils/copy-spam-risk.ts`): 실제 스팸필터를 부르지 않고 사전 기반 **로컬 초고속 스캔**(정규식/사전, 수 ms). 4.4·4.5에 스팸 위험 점수 한 축으로 제공 → 추가 지연 사실상 0.
- 정직: 로컬 사전은 위험을 "최대한 낮춤"이지 100% 보장 아님(통신사 룰 비공개). 실제 스팸필터 테스트는 사용자 별도 동작으로 유지(핫패스 제외).

## 5. 데이터 흐름

**생성 경로(런타임)**:
```
생성 요청(채널·companyId·isAd·브랜드보이스 유무)
 → composeCopyBrain 조립:
     브랜드보이스(있으면) + 베스트 예시(A=자사 베스트 / B=탈색된 업종 베스트) + 채널 도메인 규칙 + 스팸 위험 사전
 → 초안 생성(문안 모델)
 → 채점(브랜드보이스 적합도[A] + 도메인 규칙 통과 + 루브릭 + 스팸 위험)
 → 미달 & 재생성 여유 → 피드백 담아 재생성(상한 2)
 → 통과분(또는 최고점) 반환
```

**학습 경로(비동기, fire-and-forget)**:
```
발송마다: 문안 적재(기존 logCampaignTraining) 
결과 동기화: updateTrainingMetrics — 평문 키 + (수정) 접미사 키(:kakao/:brand)
스팸필터 결과: 스팸 위험 사전에 반영(오프라인 배치)
→ 시간이 갈수록 베스트 랭커가 Tier 1→2로 자동 승급
```

## 6. 신호 계층 & 랭킹 (자동 승급)

| Tier | 신호 | 가용 시점 |
|------|------|-----------|
| 0 | 사람 선택(final_source) · 규정/스팸 통과 · 구조 루브릭 · 큐레이션 검수 | 지금 |
| 1 | 클릭·열람 | 실전 몇 주 |
| 2 | 전환 귀속 | 성숙기(후속 설계) |

랭커는 tier별 표본 신뢰도로 가중치를 자동 조정. 상위 tier 데이터가 충분해지면 그쪽으로 무게 이동, 부족하면 하위 tier로 폴백.

## 7. 에러 처리·안전 (절대 원칙)

- 모든 신규 단계는 **추가형 + 실패 시 현재 동작으로 폴백**: 랭커/탈색/스팸스캔 실패 → 기존 검색 결과, 채점/재생성 실패 → 초안 그대로 반환. **생성 자체를 절대 막지 않음.**
- 발송·돈·큐 코드 0줄 변경. 학습·라벨 경로는 전부 fire-and-forget + try-catch 이중 격리(기존 패턴 계승).
- tsc 타입 에러 0. SQL 신규 컬럼/테이블은 §15 검증 후에만 작성.

## 8. 테스트 전략

- 단위: 베스트 랭커 점수/tier 폴백, 탈색(시그니처 누출 0 단언), 도메인 규칙 검증기(채널별), 스팸 위험 스캔(알려진 스팸 문구 탐지), 채점→재생성(미달 시 재생성 트리거·상한 준수).
- 통합: Track A/B 각 채널 생성 경로 스모크(폴백 포함).
- 회귀: 기존 `rankExamples`·`retrieveCopyExamples` 소비처 결과 불변 확인(격리 방식만 탈색으로 교체).

## 9. 구현 전 검증 체크리스트 (information_schema — db_column_verify_before_code)

구현 착수 전 Harold님께 검증 SQL 제공 후 실제 확인:
- `ai_training_logs` 현재 컬럼(final_source·source_ref·message_type·success_count 등) + 큐레이션/베스트 플래그 추가 필요 컬럼
- 스팸필터 기록 테이블·컬럼(정확 명칭·구조)
- KAKAO/브랜드 결과 집계 경로의 campaign 식별 컬럼(접미사 키 재구성용)
