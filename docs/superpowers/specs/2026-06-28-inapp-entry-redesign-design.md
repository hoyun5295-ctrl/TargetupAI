# 인앱 메시지 진입 화면 재설계 설계서 (2026-06-28, Harold 합의)

> 다음 세션이 그대로 구현할 수준의 상세 설계. 인앱 메시지 진입(채널 선택) 화면이 카드 2개만 있어 허전한 문제 해결.

## 0. 배경

인앱 메시지 진입 화면 = "웹 자사몰 팝업 / 모바일 앱 인앱" 카드 2개만 가로로 크게 놓여 하단이 텅 빔. Harold 격분 디자인 철학([[feedback_design_modal_first_simplicity]]) 적용 대상 — 늘어놓지 말고 모달화, 효율 배치, 데이터 적응, 가로 긴 띠 버튼 금지.

## 1. 핵심 결정 (Harold 합의 2026-06-28)

- **빠른 시작은 채널(웹/앱) 무관 1세트.** 시나리오는 "무엇을 보낼지"라 웹·앱 공통. 웹/앱으로 나눠 2배로 만들지 않는다. 시나리오 클릭 → 그때 채널 선택(작게) → AI 템플릿 → 편집기.
- **가로 긴 띠 버튼 금지.** 채널 2카드는 현재보다 컴팩트(높이·폭 축소). 빠른 시작은 적당한 그리드 카드(3열, 정사각에 가까운 형태, 아이콘+제목+한 줄).
- **데이터 적응.** 최근 만든 인앱이 있으면 목록 노출, 없으면 빠른 시작만(거대 빈 영역 금지).

## 2. 화면 구성 (위→아래)

1. **헤더(유지)**: "인앱 메시지 BETA" + 뒤로가기. 기존 그대로.
2. **채널 선택 2카드(컴팩트화)**: 웹 자사몰 팝업 / 모바일 앱 인앱. 각 카드에 **미니 미리보기 썸네일**(웹 = 브라우저 팝업 축소 도형, 앱 = 폰 인앱 축소 도형)을 넣어 카드 자체를 덜 허전하게. 현재의 큰 카드 → 높이·폭 줄인 적당한 크기.
3. **빠른 시작 시나리오(채널 무관)**: 6개 카드 3열 그리드. 시나리오 = 장바구니 이탈 / 첫 구매 유도 / 이벤트·공지 / 휴면 복귀 / 리뷰 요청 / 가입 환영. 각 카드 = 고유 아이콘 + 제목 + 한 줄 설명. 클릭 → **채널 선택 모달(웹/앱 2버튼)** → AI 템플릿 생성 → 편집기 진입(1클릭, [[feedback_marketing_user_ux_priority]]).
4. **최근 인앱 메시지(데이터 있으면)**: 작은 요약 카드 그리드(이름·상태·노출·클릭). 클릭 → **폰 미리보기 모달**(2026-06-27 BrandVoiceCard 폰 프레임 모달 패턴 재사용) + 편집 버튼. 만든 게 없으면 이 섹션 숨김 → 빠른 시작만 표시.

## 3. 흐름 (3개 진입)

- 채널 카드 클릭 → 빈 편집기(직접 만들기, 기존 흐름).
- 빠른 시작 시나리오 클릭 → 채널 선택 모달(웹/앱) → AI 템플릿(scenario) → 편집기.
- 최근 인앱 카드 클릭 → 폰 미리보기 모달 → 편집.

## 4. 컴포넌트 / 구현 단위

- **대상 파일**: `packages/frontend/src/pages/InAppMessagesPage.tsx` (채널 선택 화면 부분). **구현 직전 현재 채널 선택 화면 코드 먼저 확인** — 2026-06-27 대규모 수정분 위에 얹음.
- **채널 선택 모달(신규)**: 빠른 시작 클릭 시 웹/앱 선택. 커스텀 다크 모달(bg-slate-900 + border-white/10 + rounded-2xl, native dialog 0).
- **폰 미리보기 모달**: BrandVoiceCard 폰 프레임 모달 패턴 재사용(slate 폰 프레임 + 말풍선/배너 + 수정·닫기 버튼).
- **빠른 시작 → AI 템플릿**: 기존 `inapp-ai-generator`(scenario 파라미터) 연동. 시나리오 6종 ↔ generator 시나리오 매핑.
- **최근 인앱 목록**: `cdp_inapp_messages` 목록 조회 API(존재 여부 구현 직전 확인, 없으면 신규 GET endpoint — 회사 격리).
