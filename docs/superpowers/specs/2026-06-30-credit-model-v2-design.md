# 한줄로 크레딧 모델 v2 — 기준 문서 (설계도)

> 2026-06-30 Harold ↔ 비토 브레인스토밍 합의 종결. 오픈베타·유료 0 시점에 "흔들리지 않는 기준"으로 확립.
> 1크레딧 = 500원(불변). backend `utils/ai-credit-calc.ts` CREDIT_COST_MAP ↔ frontend `constants/credit.ts` CREDIT_TASK_COSTS 1:1 동기화 의무.

## 0. 배경 / 목표

- 가격 닻 = "마케터 한 명을 AI로 대체하는 값" (브레이즈보다 싸다 ✕). 원가가 아니라 가치로 매긴다.
- 핵심 변화 4가지:
  1. **운영(반복) 과금 도입** — 여정·자동마케팅이 "만들 때 1회"가 아니라 "돌아가는 동안" 값을 낸다.
  2. **DB 규모 분석 과금** — DB 저장 상한 폐지, 매일 분석을 규모 비례로 차감.
  3. **발행 자산 제값** — DM·인앱·이메일·인터랙션 발행 인상.
  4. **0/마이너스 처리 + 슈퍼관리자 위험 관리** — 소진/음수 안전망.

## 1. 크레딧 두 축

- **축1 — 콘텐츠 크레딧 = 요금제 지급(불변)**: 스타터 300 / 베이직 750 / 프로 2,400 / 비즈 7,800 / 엔터 16,500. DB 크기 무관.
- **축2 — DB 일일 분석 = 같은 지갑에서 매일 차감(규모 비례)**. 별도 현금 라인 아님 — 콘텐츠 지갑에서 소모.
- **DB 저장 상한 폐지**: 무제한 저장. 규모가 크면 일일 분석 차감이 커져 자연히 상위 플랜 필요(벽 없는 경제적 게이팅).

## 3. DB 일일 분석 공식

- **매일 차감 = round(3 + (10만블록 − 1) × 1.5)** — 크레딧은 정수라 반올림. `10만블록 = ceil(고객수 ÷ 100,000)`. 홀수 블록은 정확, 짝수 블록만 +0.5 반올림.
- 값(정수):

| DB | 매일 | 월(×30) | 원/월 |
|---|---|---|---|
| ≤10만 | 3 | 90 | 4.5만 |
| 20만 | 5 | 150 | 7.5만 |
| 30만 | 6 | 180 | 9만 |
| 50만 | 9 | 270 | 13.5만 |
| 80만 | 14 | 420 | 21만 |
| 100만 | 17 | 510 | 25.5만 |
| 300만 | 47 | 1,410 | 70.5만 |

- **연동 = 항상 켜짐(토글 폐지)**. "매일 자동 예측" on/off 토글 제거 — 연동이 곧 분석. 유일한 "꺼짐" = 크레딧 0 자동 정지(§6).
- 멱등: 회사 + YYYYMMDD 하루 1회. 그날의 고객 수를 읽어 그날 금액 산정.
- 구현: `ai-credit-calc.ts`에 순수 함수 `dailyDbAnalysisCredits(count: number): number` 신설 + 단위 테스트. 기존 `predictive-daily` 차감 지점의 상수 `3`을 함수값으로 교체(차감 경로·멱등 구조는 그대로).

## 4. 운영 발송 (여정 / 자동마케팅 실행)

- **여정 1개당 하루 1회 10크레딧.** 동일 여정이 하루 여러 번 발사돼도 그 여정은 10/일 상한. N개 활성 = N × 10/일.
- 멱등키 = `journeyId(또는 operatorId):YYYYMMDD`.
- 사다리 예: 5개 매일 → 50/일 → 월 1,500 → 프로(2,400) 이상 필요.

## 5. 활성화

- 여정 활성화 150 → **200** (자동마케팅 200과 통일). draft→active 최초 1회만 멱등(journeyId). paused→active 재개 = 0.

## 6. 0 / 마이너스 처리

원칙: **고객에게 닿는 흐름은 끊지 않고, 내부 계산은 멈춰도 무해하니 멈춘다.**

- **0 도달**: DB 일일 분석 = 자동 정지(무부채) + 생성·발행·신규 활성화 차단.
- **이미 활성인 여정·자동마케팅**: 마이너스 허용(계속 발송). 다음달 grant에서 상계(현금 청구 ✕ — 다음달 크레딧을 그만큼 적게 지급).
- **마이너스 상한 = −1개월 grant.** 상한 도달 시 여정도 정지 + 강경고(폭주 차단).
- **경고**: 80% 소진 / "이 추세면 N일 후 소진" 알림(깜짝 정지 방지).
- 재개 = 업그레이드 또는 충전팩(50/100/300/500).

## 7. 슈퍼관리자 "크레딧 위험 관리" 메뉴 (신설)

- 우측 **"작업당 크레딧" 박스 = §2 신규 기능별 차감표를 깔끔하게** 노출. 카테고리 그룹: 만들기 / 문안·분석 / 꾸미기 / 발행(DM·인앱·이메일·인터랙션) / 활성화 / 운영(실행) / 풀분석 / DB 일일 분석.
- **DB 일일 분석 행 = 내 실제 고객 수 기준 "매일 N크레딧" 개인화 표시** (제거한 DB 바 대신 이게 DB 정보 역할). 예: 20,000명 → 매일 3.

### 8-2. 요금제 비교 카드 (전 카드 공통)
- "이 크레딧으로 풀분석 N회·DM N건·문안 N건" 줄 **제거** (운영·DB 차감 들어오면 거짓).
- "스타터부터 AI 전 기능·전 채널 발송 동일" 줄 **제거**.
- **"관리 가능 DB N명" 줄 제거 (전 카드 — 캡 폐지)**.

- 카드 통일: 동일 높이·동일 구조 [전용 인프라 뱃지 / 플랜명 / 가격 / 서버 tier / 월 크레딧(+보너스) / CTA]. DB 줄 없어짐. 남는 차별점 = 서버 tier(공유→전용→전용 AI) + 크레딧 양.
