# 자동마케팅(Continuous Operator) 재설계 — 설계 문서

작성: 2026-06-27 · 기획: 비토(CTO) · 승인 대기: Harold
대상 화면: `packages/frontend/src/pages/ContinuousOperatorPage.tsx`
엔진(변경 최소): `services/ai-orchestrator.ts` · `utils/continuous-operator.ts` · `routes/ai.ts`

---

## 1. 배경 · 문제

엔진(백엔드)은 이미 브레이즈급이다. 멀티 에이전트(타겟·검증·문안·컴플라이언스·성과추정·인사이트), Bandit 학습, 멀티골 충돌 분석, 예산 가드, 발송 시각 최적화, 다단계 시퀀스, 안전장치(Zero-Count 차단·컴플라이언스 fail-closed·광고/080·임의 혜택 금지)가 모두 있다.

문제는 화면이다. 진단 결과:

1. 신뢰·투명성 취약 — 제안 카드가 "왜 이걸 보내야 하는지"를 안 보여준다. `orchestrate()` 결과 전체가 `proposal_json`에 저장(`continuous-operator.ts:589` `JSON.stringify(orchestratorResult)`)되는데, 화면은 그중 일부만 렌더한다. 버려지는(=화면이 안 그리는) 데이터: 채널 선택 이유, 컴플라이언스 결과·경고, 등급별 전환(`performance.basis.gradeBreakdown`), 추정 신뢰도(`basis.confidence`), AI 진단·전략·리스크(`performance.insight`), 비용 산출 근거, 통합 분석(`meta.aiSynthesis`).
2. 가독성 취약 — 보라→자홍→보라 3색 그라데이션 위에 같은 무게의 작은 흐린 글씨가 흩어져 포인트가 없다.
3. 실행 어려움 — 생성 모달이 18필드를 한 번에 쏟는다. 마케팅 담당자에게 과하다.
4. 여정과 개념 중복 — 자동마케팅과 여정의 역할 경계가 화면·시나리오에서 흐리다.

## 2. 디자인 법칙 (모든 화면 공통)

1. 한 화면 = 포인트 하나. 눈이 가장 먼저 닿는 단일 히어로(숫자 또는 주 액션)를 둔다.
2. 위계 3단. 히어로 → 근거 → 보조. 같은 무게 텍스트를 흩뿌리지 않는다.
3. 버리는 데이터 0. 엔진이 만든 산출물은 전부 화면에 자리를 갖되, 위계로 정돈한다. 숨기지도 흩뿌리지도 않는다.
4. 차분한 다크 + 단일 액센트. 3색 그라데이션을 폐기하고 거의 검정에 가까운 바탕에, 바이올렛 액센트는 포인트(히어로·주 버튼·강조)에만 쓴다. 보조 텍스트 대비를 올려 읽히게 한다. (design_quality_minimum_journey_level 룰의 다크+바이올렛 유지)

## 3. 정보 구조 — 런처 + 4개 화면

메인을 "폼 + 제안 목록"에서 "런처"로 바꾼다.

### 3-1. 런처 (메인)
- 시작 방법 4개를 2×2 타일(가운데 정렬, 아이콘+제목, 부제 없음)로 둔다. 라벨만 있는 액션 타일이라 가운데 정렬.
- 타일 아래에 "이렇게 시작합니다" 브리핑 — 각 버튼이 무엇을 하는지 좌측 정렬 4행. (읽는 글이라 좌측 정렬)
- 4 타일: ① 오늘의 추천 마케팅(featured + 대기 건수 배지) ② 자연어로 시작 ③ 시나리오로 시작 ④ 세부설정으로 시작.

### 3-2. 오늘의 추천 마케팅 (의사결정 카드 — "버리는 데이터 0"의 핵심)
- 히어로: 기대 매출 단일 숫자 + ROI 배수.
- 근거(위계 하강): 왜 지금인가(`performance.insight.diagnosis`, 신뢰도 포함) → 등급별 기대 전환 미니 바(`gradeBreakdown`) → 컴플라이언스 점등 + 채널 선택 사유 + Bandit 추천 변형 → 발송 문안 미리보기.
- 주 액션 하나: 승인하고 발송. 보조: 거부 · 상세.
- 데이터는 거의 전부 이미 `proposal_json`에 있으므로 백엔드 변경 최소(프론트 렌더 중심).

### 3-3. 자연어로 시작
- 입력 한 칸(마케팅 목표 한 줄) + 예시 칩(한 클릭 채움).
- "AI가 자동으로 잡는 항목"(타겟·채널·시각·문안·성과) 칩으로 안내 — 추가 입력 없음.
- 주 버튼 하나: AI가 초안 만들기 → 결과는 3-2 추천 카드와 같은 모양으로 재사용. (marketing_user_ux_priority 룰: 한 줄·추가 입력 최소·한 클릭)

### 3-4. 시나리오로 시작
- 검증된 시나리오 카드 그리드(좌측 정렬, 설명 포함). 고르면 타겟·문안·시각이 미리 채워져 가동 전 한 번 확인.
- 시나리오 목록은 목표·세그먼트형만(§4 경계 룰): VIP 재구매, 휴면 회복, 신규 첫구매 전환, 등급 상승 유도, 계절 프로모션, 재고 소진. (이벤트형 생일·장바구니는 여정으로 이관)

### 3-5. 세부설정으로 시작 (풀 컨트롤)
- 기본 4개만 펼쳐 둔다: 이름, 마케팅 목표, 발송 채널, 추천 주기+시각. AI가 채운 기본값을 보여준다.
- 고급 항목은 접힘 카드(요약 한 줄 표시): 혜택 내용 / 다단계 시퀀스 / 발송 정책·담당자 알림 / 비용 제어. 필요할 때만 펼친다.
- 하단 고정 액션: 취소 / 자동마케팅 시작.

## 4. 여정 vs 자동마케팅 포지셔닝

### 4-1. 정체성
- 자동마케팅 = AI 전략가(탐색). 회사 목표로 작동, AI가 매 주기 회사 데이터·계절을 보고 새 캠페인을 제안, 사람은 승인·감독.
- 여정 = 상시 자동 기계(정착). 개인 이벤트로 작동, 마케터가 한 번 설계하면 같은 흐름이 계속 돈다.

### 4-2. 경계 룰 (마케터 의사결정 한 줄)
- 트리거가 개인의 사건·날짜(가입·구매 후·생일·장바구니) → 여정.
- 트리거가 회사의 목표·세그먼트(VIP 매출·휴면·등급·계절 프로모션·재고) → 자동마케팅.
- 적용: 자동마케팅 시나리오에서 이벤트형(생일·장바구니)을 제거(§3-4).

### 4-3. 승격 다리 (브레이즈에 없는 루프)
- 자동마케팅 제안·성과 화면에 "이 캠페인을 여정으로 굳히기" 1클릭을 둔다.
- 동작: AI가 발견한 잘 되는 캠페인을 여정 초안으로 생성 → 기존 여정 활성화·사전테스트 게이트를 그대로 거침(자동 우회 없음, 안전 설계 유지). 탐색(자동마케팅) → 정착(여정).
- 전제(구현 전 검증): 여정 엔진의 초안 생성 API/스키마. 본 다리는 신규 발송 파이프라인 신설 금지 룰에 맞게 여정 기존 자산을 재사용한다.

## 5. 백엔드 · 데이터 영향

- 3-2 추천 카드의 "버리는 데이터 0": 대부분 이미 `proposal_json`에 저장됨 → 프론트 렌더 추가가 핵심. 신규 SQL/컬럼 없음.
- 3-3/3-4 진입 흐름: 기존 `orchestrate()`/`run-now`/생성 라우트 재사용. 시나리오 = objective·channel 프리필.
- 4-3 승격: 여정 초안 생성 재사용(신규 파이프라인 X). 여정 측 API 확인 후 배선.
- DB 컬럼 추가가 필요해지면 information_schema 검증 SQL 먼저(db_column_verify_before_code).

## 6. 안전 · 룰 준수

- Zero-Count 자동완화 금지 / AI 임의 혜택 생성 금지(혜택은 관리자 입력) / 컴플라이언스 fail-closed / 광고+080 자동 / 추정은 실데이터(임의 상수 금지) — 전부 유지.
- 모델명 UI 노출 0 / native dialog 0(ConfirmModal+useToast) / 다크+바이올렛 / 모바일 반응형 — 전부 유지.
- 신규 발송 파이프라인 신설 금지 — 승격은 여정 기존 게이트 재사용.

## 7. 범위 · 단계

- Phase 1 — 런처(3-1) + 오늘의 추천 의사결정 카드(3-2). 체감 가장 빠르고 위험 가장 낮음(저장된 데이터 렌더 중심).
- Phase 2 — 진입 흐름 3종(3-3 자연어 · 3-4 시나리오 정리 · 3-5 세부설정 정돈).
- Phase 3 — 여정 vs 자동마케팅 경계 반영 + 승격 다리(4-3). 여정 API 검증 선행.

각 Phase는 한 건씩(no_parallel_tasks), tsc 0 + 단위 테스트 + 발송·돈 닿는 부분은 실측 1건.

## 8. 미해결 — 구현 전 확정 필요

1. 승격 다리: 여정 초안 생성 API/스키마(소스 확인 승인 필요).
2. 등급별 전환(`gradeBreakdown`)이 회사별로 항상 채워지는지, 부족 시 카드 표기(insufficient_data 폴백) 방식.
3. 4번째 런처 타일을 "시나리오로 시작"으로 확정(대안: 여러 목표 동시 마케팅) — Harold 확정 대기.
