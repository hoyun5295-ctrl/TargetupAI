## §0 30초 요약

- **무엇**: 모바일 DM · 이메일 · 인앱 한 줄 칸에 행사를 한 줄 치면, 서버 규칙(AI 0 · 무료)이 그 한 줄 · 그 회사 · 그 채널에 **없는 사실과 재료만** 단계 목록으로 내리고, **단계별 모달**이 한 단계에 한 가지씩 묻고 받는다. 마지막 「만들기」 단계가 금액 확인을 겸한다.
- **분기**: 회사 단위 = 「상품을 다시 읽을 수 있는 몰(카페24 활성 · 우커머스) 연동이 있는가」 · 실제 분기는 **상품 낱말마다**(몰에서 찾으면 고르기 · 못 찾으면 사진과 가격 받기).
- **재료는 AI 를 지나지 않는다**: 받은 사진 · 직접 넣은 상품 · 버튼 주소는 생성 뒤(DM 은 장 나누기 전) 코드가 제자리에 놓는다.
- **요금(Harold 2안)**: 한 줄 완성 = 생성비 + 10(DM 15 · 이메일 13 · 인앱 13). 같은 날 같은 한 줄로 다시 만들면 생성비만. 발행 · 게시 · 이메일 완성은 지금 그대로. 묻기 · 몰 찾기 · 사진 올리기 = 0.
- **스위치**: `ONE_LINE_STEPS_COMPANY_IDS`(비면 꺼짐 · `*` = 전 회사) · **`ONE_LINE_FACTS_COMPANY_IDS` 를 켠 회사 안에서만** 동작(좁히기만 · 기존 판정 무변경). **DDL 0.**

## §3 계약 (불변)

1. **판정 = 서버 순수 CT 하나**(`utils/one-line-steps.ts` · AI 0 · DB 0). 라우트가 DB 사실(재조회 몰 유무 · 인앱 표시 가능 · 회사 홈페이지 · 업로드 가능 · 오늘 한 줄 완성 냈는가)을 넣는다. 사실마다 따로 시도하고 실패하면 그 칸만 안전한 기본값(몰 없음 · 홈페이지 없음 · 업로드 불가 · 금액 모름 = null).
2. **화면은 서버 단계 목록만 그린다.** 단계 키 닫힌 목록 = `benefit · product · hero_photo · link · period`. 문구는 화면 원장이 소유(서버는 키 + 낱말만). 동적 조건은 서버가 단계에 실어 보낸 `skip_if` 하나만 화면이 해석한다.
3. **상한 = 질문 4 + 만들기.** 순서 = 혜택 → 상품(낱말마다 · 최대 3 · 인앱 1) → 대표 사진 → 버튼 주소 → 기간. 넘치면 기간 → 3번째 상품 → 2번째 상품 순으로 `later`(만들기 단계 「비워 둠」 줄 · 만든 뒤 편집 화면에서 채움).
4. **상품 낱말이 단계가 되는 조건** = 몰 후보가 있음(고르기) 또는 한 줄에 그 상품의 가격 · 주소가 있음(직접 넣기). 그 밖 낱말은 만들기 단계에 「「니트」 상품을 넣을까요? [넣기]」 한 줄(누르면 직접 넣기 단계가 열린다). 잡음 낱말을 줄이려 검색어 거름 낱말을 보강한다(조사 「께」 · 선착순 · 소진 · 한정 등).
5. **몰 값은 표시용**. 서버는 `{provider, no}` 만 받고 생성 직전 재조회 ok 만 카드(10-10 계약 그대로). 몰 값은 원문(eventText)에 넣지 않는다.
6. **직접 넣은 상품** = 이름(한 줄 낱말을 미리 채움 · 사람이 고칠 수 있음 · 고친 이름 = 사람이 확인한 이름) + 가격(한 줄 금액을 미리 채움) + 사진 1장(선택 · H3). 사진 + 가격 = 상품 카드(이 회사 경로 사진만) · 그 밖 = `[상품] 이름 가격` 원문 줄.
7. **기간** = DM · 이메일만 · 행사 의도 있음 + 기간 낱말이 **전혀** 없을 때만. 감지는 「있음」 쪽으로 넓게(날짜 숫자 · 요일 · 까지 · 주말 · 오늘 · 마감 · 선착순 · 소진 · 한정 · 명절 · 월말 …). 답 = 날짜 하나(`YYYY-MM-DD` 글자 그대로) → 원문 `[기간] 2026년 10월 20일(일)까지` = 한 줄에 날짜를 친 것과 같게 동작(생성기 무변경). 요일은 서버가 `Date.UTC` + `getUTCDay`.
8. **대표 사진** = 업로드 가능할 때만 단계. 건너뜀 조건(`skip_if`): DM · 인앱 = 몰 상품을 담았거나 직접 넣은 상품에 사진이 있음 · 이메일 = 직접 넣은 상품에 사진이 있음(몰 사진은 외부 주소라 메일 첫 화면에 쓰지 않는다 · 아웃룩). 실제로 놓는 사진 = 생성 때 값(몰 = 재조회 사진 · 직접 = 올린 사진). 첫 화면 자격은 렌더러 · 비주얼 디렉터 판단 그대로.
9. **버튼 주소** = 한 줄 안 주소 · 회사 홈페이지(브랜드 킷 연락처) · 연동 몰 첫 화면 중 하나라도 있으면 단계 없이 그 값(만들기 단계에 출처와 함께 보이고 [바꾸기]로 단계를 연다). 상품을 담으면(링크 있는 상품) 건너뛴다(`skip_if`). 최종 주소는 서버가 정한다: 답 → 한 줄 주소 → 첫 확정 상품 링크 → 홈페이지 → 몰 첫 화면. 코드가 CTA(DM · 이메일 `cta.buttons[0].url` 빈칸일 때) · 인앱(첫 버튼 `action_url` · cta_group 첫 버튼)에 놓는다.
10. **묻지 않는 것** = 로고 · 매장 · 색(회사 설정) · 쿠폰 코드 · 후기 · 인앱 표시 조건 · 빈도 · 모양 · 이메일 제목(AI) · 광고성(이메일 한 줄 칸 옆 체크 그대로).
11. **돈** — 한 줄 완성 = 생성비 + 10(`oneline-complete`). 원장 한 행 · 멱등키 = `olc:{회사}:{채널}:{KST 날짜}:{한 줄 지문 12}:{시도 지문 24}`(최대 약 93자 · 시도 지문 = 시도 토큰 + 생성 입력 전체). 「오늘 이 한 줄로 한 줄 완성을 냈는가」 = 같은 접두 + `source='oneline-complete'` 행 존재(원장이 진실 · 조회 실패 = 503). 냈으면 생성비만(원천 = 그 채널 생성 키). 화면이 보인 금액(`expected_cost`)과 서버 금액이 다르면 AI · 차감 전에 409 `PRICE_CHANGED`(새 금액 동봉). 같은 시도 재요청 = 409 `ALREADY_DONE`(DM 착지 = 낸 초안 재사용 · 10-10 그대로). 차감 = 결과가 준비된 뒤 한 번 · 잔액 부족은 결과를 내주지 않는다(`throwOnInsufficient`).
12. **인앱도 같은 돈 계약**: 시도 토큰 · 동시 요청 잠금 · 생성기를 묶음 안에서 불러(안쪽 차감 0) 라우트가 위 키로 1회 차감.
13. **관문은 모달 열기 전**: 고객 데이터 → (인앱) 표시 가능(`plan.block`) → 스위치 → 판정. 다 답한 뒤 막지 않는다.
14. **답 보존** = sessionStorage `oneline-steps:v1:{회사}:{사용자}:{채널}:{한 줄 지문}` · 성공 때만 지움 · 실패 = 만들기 단계로 다시 엶 · 같은 한 줄로 다시 열면 이어서.
15. **모달** = `JourneyModalShell`(바깥 눌러 닫힘 없음 · 닫기 = X) · 층 z-[1500] + 인터럽트 표식(도움말 런처가 바닥 버튼을 덮지 않게) · 한 단계 다섯 가지(단계 이름 · 질문 20px · 이유 14px · 입력 하나 · 바닥 버튼 2개 h-12) · 진행 = 칸 막대 + 단계 이름(숫자 없음) · 색 다섯(남색 지금 · 보라 고객 · 초록 우리 데이터 · 회색 비움 · 앰버 유료 버튼만) · 입력 16px · 단계가 바뀌면 질문 제목으로 포커스.
16. **모델명 0 · native dialog 0 · 줄표 0 · 내부 코드명 0**(사용자 노출 문구).

## §5 화면

1. 한 줄 → (질문이면 답 카드 · 기존) → 관문 → **단계별 모달**(스위치 켠 회사는 질문 0 이어도 만들기 단계 한 장 = 금액 확인) → [만들기] → 모달 닫고 각 화면 기존 진행 표시 → 착지(DM 결과 화면 · 이메일 편집기 · 인앱 편집 화면 · 지금 그대로).
2. 몰 후보 검색은 모달 여는 순간 한 번(혜택 단계 동안 끝남) · 상품 단계는 키 하나 안에서 `대기 → 고르기 | 직접 넣기` 로 바뀐다(커서 튐 없음) · 대기 중에도 [다음]을 막지 않는다.
3. 만들기 단계 = 줄 목록(누르면 그 단계로) + 출처 배지 + 크레딧 줄(현재 → 뒤 · 부족 = 잠금) + Source caption.
4. 결과 화면 [같은 한 줄로 다시 만들기] = 단계 답을 그대로 실어 생성비만(오늘 지나면 `PRICE_CHANGED` → 새 금액 확인).
5. 한 줄 칸의 「이미지로 불러오기」 · 「이미지」 버튼 이름 = **「사진 속 글 읽기」**(사진 단계와 혼동 방지 · 입구 수 · 무게 변화 0).

## §7 하지 않는 것 (범위 밖 · 기록)

- AI 가 단계를 고르는 v2(기록 `steps_meta` 로 「규칙이 놓친 질문」 측정 뒤).
- 생성 뒤 사진 · 주소 채우기를 단계 화면으로 하는 것 — 이번에는 기존 편집 화면 · 완성도 줄이 맡는다(상한에 걸린 것만 해당 · 이유 = 세 결과 화면 배선이 따로라 범위가 커진다).
- 입구 정리(「질문 몇 개로」 원스텝 과금 5 + 50 · 「재료로 만들기」) = 다음 안건.
- BUGS 등재: 「이미지로 불러오기」 즉시 조립이 사진 속 가격을 검증 없이 카드로 · DM 생성비 주석 3 vs 실제 5 · 발행 주석 30 vs 100 · 인앱 게시 주석 15 vs 100 · 원스텝 카드 「오토설계」 내부 용어 · 이메일만 쓰는 요금제의 편집기 사진 업로드 권한.

## §9 테스트 계약

- 걸음 테스트: 채널 3 × 몰 있음 · 없음 × 표본 한 줄 → 기대 단계 키 표(상한 · 순서 · later).
- 기간 감지: 기간 낱말이 하나라도 있으면 묻지 않는다(고정 사례) · 없으면 묻는다.
- 멱등키: 길이 ≤ 150 · 답 칸 하나만 바꿔도 키가 바뀐다 · `steps_meta` 는 키에 안 들어간다.
- 재료 놓기: 직접 상품 카드(사진 + 가격만) · 히어로 · CTA 주소(빈칸일 때만) · 인앱(사진 = image_url + media · 버튼 주소 · 사진 없으면 full_image 금지).
- 라우트 소스 계약: `PRICE_CHANGED` · 재조회 409 가 AI · 차감 앞 · 차감 = 결과 뒤 · 스위치 밖 400 · 인앱 생성기 묶음 호출.
