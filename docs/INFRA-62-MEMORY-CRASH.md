## §0 지금 (1102 저녁)

- 메모리 고장 = **확정**(1026 memtester 실패 4 · §3). 불량 메모리 4장이 그대로 꽂힌 채 운영 중.
- 어느 장이 불량인지 = **미확정**. 빼 보지 않고 짚을 방법은 확인된 것이 없다(§4).
- 하나로호스팅이 메모리 전체 검사(1102 23:00 점검)를 거절 → 로그인 점검 안내 창 취소(0a780fa3 → 되돌림 daab49e1).
- 순서(Harold 1102): .57 이전을 최대한 빨리(「57번 최대한 빨리 처리할때까지 62번은 버티겠지」) → 이전 뒤 하나로호스팅에 메모리 시험 요청(「8~12시간 소요되어도 반씩만 빼서 … 2일에 나눠서」) → 넥스서버 부품 보증 청구. **시험 방식은 그때 정한다**(「아직 멀었으니 닥치면 얘기하자」 · 안 = §5).

## §4 빼 보지 않고 불량 칸을 짚을 수 있나 = 확인된 길 없음 (1102)

- **서버가 오류를 모른다**: 비 ECC 라 메모리 컨트롤러가 오류를 감지하지 못한다 → iLO · IPMI 에 칸 번호가 남지 않는다. 1026 SEL 메모리 이벤트 0 이 실례.
- **memtester** 는 자기가 잡은 메모리 안 위치(오프셋)만 준다(1026 = 「두 군데 몰림」까지).
- **오류 주소를 칸 번호로 바꿔 주는 도구** = MemTest86(PassMark) 유료판(Pro 이상)의 DIMM 해독. 제조사 지원 목록 = 일반 PC 메인보드(B660 · Z690 · B760 · Z790 · Z890 · AM4 · AM5 등) · CPU 는 Core · Ryzen(EPYC 9005 는 예비 지원) · **HPE 서버 보드와 Xeon 은 없음** → 결과가 나와도 근거로 쓸 수 없다. 출처 = <https://www.memtest86.com/tech_DIMM_Decoding.html>(1102 확인).
- **memtest86+**(.62 에 깔림)는 틀린 물리 주소를 보여 준다. 이 서버에서 칸 번호까지 내는지는 미검증.

## §5 불량 칸 찾는 시험 (이전 뒤 · 방식은 그때 정함)

- 언제 = .57 이전이 끝나 .62 가 서비스에서 빠진 뒤(시험하는 동안 .62 는 꺼진 것과 같다).
- 누가 = 하나로호스팅(메모리를 빼고 꽂는 일) · 부팅 = GRUB 메뉴에서 memtest86+ 선택(콘솔 = iLO).

| 안 | 하는 일 | 나오는 것 | 한계 |
|---|---|---|---|
| Harold 안 = 반씩 | 2장씩 꽂고 검사 · 이틀 | 「두 장 중 하나」 | 한 장을 짚으려면 시험을 한 번 더 · 두 장이 불량이면(1026 오류가 두 군데) 양쪽 다 실패로 나와 못 가린다 |
| AI 제안 = 한 장씩 | 한 장만 같은 칸에 꽂고 1회전 · 4번(하루 2장) | 장마다 통과 · 실패 | 넷 다 혼자서 통과하면 결과 = 「4장을 같이 꽂을 때만 난다」(지금 = 4장 · 4000 MT/s · 장 수가 바뀌면 동작 속도가 달라질 수 있음 · 미검증) |

- 한 장씩의 한 번 검사는 꽂힌 용량이 4분의 1 이라 전체 검사보다 짧다(몇 시간인지는 미실측).
- 같은 칸에서 그 장만 오류가 나면 칸이 아니라 메모리 탓이라는 근거가 된다.
- 보증 근거로 남길 것 = 오류가 난 장의 검사 화면 사진 + 그 장 일련번호 + 나머지 장의 통과 화면.
