# 한줄로 SDK 설치 가이드 — 장바구니 리커버리 (v0.3.5)

> 대상: 쇼핑몰 개발 담당자. 목표 = 방문/장바구니 행동 수집 → 미구매 고객에게 한줄로 자동 메시지(장바구니 리커버리).
> 플랫폼별로 ① 스크립트 설치 ② 회원 식별 주입 ③ 장바구니 담기 이벤트 전송 ④ 수신 확인 순서로 진행합니다.

---

## 0. 공통 — 준비물

1. **공개 키(public key)**: 한줄로 관리자 → CDP 설정에서 발급된 `hjl_`로 시작하는 키. 브라우저에 노출돼도 안전한 키입니다. (비밀 키 `sk_`는 서버 연동 전용 — 브라우저에 절대 넣지 않습니다.)
2. **수집 허용 도메인 등록**: 한줄로 관리자 → CDP 설정 → 수집 허용 도메인에 쇼핑몰 주소(예: `https://www.example.com`)를 먼저 등록합니다. 등록되지 않은 도메인에서 보낸 이벤트는 거부됩니다(보안).

---

## 1. 스크립트 설치 (모든 플랫폼 공통)

쇼핑몰 모든 페이지의 `<head>`에 아래 한 줄을 넣습니다. `hjl_...` 자리에 발급받은 공개 키를 넣습니다. (한줄로 관리자 → CDP 설정에서 공개 키가 자동으로 채워진 스니펫을 복사할 수 있습니다.)

```html
<!-- 한줄로 CDP -->
<script src="https://app.hanjul.ai/sdk/v0.3.5/hanjul.min.js" data-hjl-key="hjl_여기에_공개키" async></script>
```

`data-hjl-key`에 공개 키만 넣으면 별도 init 코드 없이 수집이 시작됩니다.

설치 직후부터 페이지 방문(`page_view`)·클릭이 자동 수집됩니다. 익명 방문자도 익명 ID로 누적되며, 이후 회원으로 식별되면 그동안의 익명 행동이 자동으로 회원에게 연결됩니다(소급 연결, 최근 30일).

---

## 2. 회원 식별 주입 (플랫폼별)

장바구니 리커버리 메시지를 **실제로 보내려면** 방문자가 누구인지(회원) 식별돼야 합니다. 회원 식별이 없으면 익명 행동만 쌓이고 발송 대상이 되지 않습니다.

### 2-1. 자체몰 / 범용 (권장 방식)

로그인 회원 페이지의 `<body>` 태그에 회원 정보를 속성으로 넣습니다. 한줄로 SDK가 자동 감지합니다.

```html
<body
  data-hjl-user-id="회원의 고유 ID(평문)"
  data-hjl-phone="01012345678"
  data-hjl-name="홍길동">
```

- `data-hjl-user-id`: 회원 고유 식별자(필수). 주문/회원 DB의 회원 키와 같은 값이어야 한줄로 고객과 정확히 연결됩니다.
- `data-hjl-phone`: 휴대폰 번호(권장). 한줄로가 기존 고객과 매칭하거나 신규 고객을 만들 때 사용합니다. **메시지를 보내려면 휴대폰 번호가 필요합니다.**
- `data-hjl-email`, `data-hjl-name`: 선택.

비로그인 페이지에서는 이 속성들을 비우면 됩니다(익명 수집 유지).

### 2-2. 고도몰

고도몰 스킨은 치환 변수를 그대로 쓸 수 있습니다. 로그인 상태에서 회원 번호가 출력되도록 `<body>`에 넣습니다.

```html
<body data-hjl-user-id="{=gSess.memNo}">
```

휴대폰 번호 변수를 함께 출력할 수 있으면 `data-hjl-phone`에도 넣어주세요(발송 매칭 정확도 상승).

### 2-3. 카페24

카페24는 현재(이 가이드 시점) 가벼운 스크립트만으로 **로그인 회원의 평문 식별값을 페이지에서 읽을 수 없습니다.** 카페24가 평문 회원ID 테마 변수를 제공하지 않고, 회원 식별은 카페24 앱(서비스 키) 연동을 통해서만 가능하기 때문입니다.

따라서 카페24는 단계로 나눕니다.

- **지금 가능**: 1번 스크립트 설치로 방문/장바구니/클릭 **익명 수집**이 됩니다. 익명 ID로 쌓이며 데이터는 보존됩니다.
- **회원 식별(예정)**: 한줄로 카페24 앱 연동이 준비되면, 머천트가 앱을 1회 설치하는 것만으로 회원 식별이 자동 연결됩니다. 페이지에 별도 식별 코드를 넣을 필요가 없습니다. 그 시점에 익명으로 쌓였던 장바구니 행동도 회원에게 소급 연결됩니다.

> 카페24에서 당장 회원 식별까지 필요하면, 자체 회원 연동(서버에서 한줄로 식별 API 호출)으로 대체할 수 있습니다. 담당자에게 문의해 주세요.

## 3. 장바구니 담기 이벤트 전송

"장바구니에 담기" 동작이 일어나는 지점에서 아래 한 줄을 호출합니다. 담은 상품 정보를 함께 넘기면, 리커버리 메시지에 그 상품명·가격을 넣을 수 있습니다.

```html
<script>
  window.hjl && window.hjl.track('cart_add', {
    product_name: '린넨 원피스',
    price: 39000,
    product_url: 'https://www.example.com/product/123',
    image_url: 'https://www.example.com/img/123.jpg',
    quantity: 1
  });
</script>
```

- 이벤트명은 표준값을 사용합니다: `cart_add`(담기), `cart_remove`(빼기), `checkout_start`(결제 진입), `purchase`(구매 완료). 표준값이 아닌 이름은 SDK가 거부합니다(오타 방지). 자체 이벤트가 필요하면 `custom_` 접두사를 붙입니다(예: `custom_quiz_done`).
- `checkout_start` 또는 `purchase`가 들어오면 한줄로가 "구매로 이어졌다"고 판단해 리커버리 발송 대상에서 제외합니다. 결제 진입/구매 완료 지점에도 이벤트를 넣어주세요.

권장 상품 키(메시지 치환용): `product_name`, `price`, `product_url`, `image_url`, `quantity`.

### 메시지에서 상품 노출

한줄로 여정(장바구니 템플릿) 메시지 본문에 아래 변수를 쓰면 담은 상품이 자동으로 들어갑니다.

```
{{ cart.product_name }} 아직 장바구니에 담겨 있어요. 지금 확인해 보세요!
```

상품 정보가 없으면 해당 변수는 빈 값으로 처리되어 발송이 막히지 않습니다.

---

## 4. 수신 확인

한줄로 관리자 → CDP 설정 → 설치 상태에서 첫 이벤트 수신 여부를 확인합니다.

- 스크립트 설치 후 쇼핑몰을 열면 수 분 내 `page_view` 신호가 잡힙니다.
- 회원 페이지를 열면 `identify` 신호가 잡힙니다.
- "장바구니 담기"를 눌러보면 `cart_add` 이벤트가 누적됩니다.

신호가 잡히지 않으면 체크: ① 공개 키가 맞는지 ② 수집 허용 도메인에 현재 주소가 등록됐는지 ③ 스크립트가 `<head>`에 들어갔는지.
