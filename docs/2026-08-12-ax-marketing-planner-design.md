## §0 무엇을 만드는가

**마케팅 담당자의 한 달을 결재 두 번으로 줄이는 대행 서비스.**

1. 담당자가 월간 캘린더에 **자기 행사**를 기입하고(날짜·내용·혜택), 채널 5종(메시징·알림톡·이메일·모바일DM·인앱)을 체크박스로 고른다.
2. 채널마다 **시점 규칙**을 붙인다 — "메시징은 행사 시작일과 종료일에", "이메일 브로마이드는 D-5 사전 안내로, 참여 동의 버튼을 달아서", "DM은 제작해서 문자 문안에 삽입".
3. 시스템이 **월간 마케팅 브리핑**(스케줄러 화면)을 만들고 담당자가 **승인**한다 — 승인 = 그 달의 대행 계약(1000크레딧).
4. 이후 무인: 소재류(이메일·DM·인앱)는 **자사몰 실데이터로 대행 제작**, 문자 문안은 **행사 당일 발송 전 생성**(T스팸필터 대응), 발송·결과 브리핑까지 완주.

담당자의 업무가 **제작에서 결재로** 바뀐다 — 이것이 AX 판정의 근거다(§2).

## §2 AX 판정 · 축 정체성

**AX 성립 조건 둘** — ①브리핑이 결재 서류 수준일 것(소재류 실물 프리뷰 + 타겟 수 실쿼리 + 예상 크레딧·발송비. 문자 문안만 "당일 생성" 표시) ②승인 후 무인 완주(제작→발송→결과 브리핑). 둘 중 하나가 빠지면 AX가 아니라 예약 발송기다.

**세 번째 시계.** 여정 = "방금 했다"(사건이 시계) / 자동마케팅 = "지금 상태다"(상태가 시계) / **플래너 = "그날이 왔다"(달력이 시계)**. 기존 두 축과 겹치지 않는 새 축이므로 별도 기능이 맞고, 상단 타일(여정 자동화·자동 마케팅 옆)이 분류상 정위치다. 실행 엔진은 새로 만들지 않고 자동마케팅 것을 재사용한다(§5-4) — **축은 셋, 엔진은 하나.**

### 3-1. 크레딧의 두 축 [확정 5·6]

| 축 | 산정 기준 | 값 |
|---|---|---|
| 제작물 크레딧 | AI 호출 **원가** 연동 (기존 그대로) | 아래 단가표 |
| **대행 크레딧** | 대체하는 **인건비·리테이너** 연동 (신설) | **월간 승인 = 1000** |

### 3-4. 차감 규칙 [설계]

- **월간 승인 시점에 1000 차감** — 승인 = 그 달 대행 계약 체결. 멱등키 = `planner:{회사}:{YYYY-MM}` (더블클릭·재시도 이중 차감 차단).
- 미승인 = 제작 자체를 안 하므로 원가·차감 0 (fail-closed).
- 같은 달 안의 행사 추가·변경 = 추가 대행료 없음(대행을 이미 샀다). 단 변경분 재승인은 §5-3.
- 제작물 크레딧 = **제작이 실제로 일어나는 시점** 차감(소재류 = 승인 후 제작 시 / 문자 문안 = 당일 생성 시). 이미지 스튜디오의 "효과 확정 후 차감" 원칙과 같은 축.
- 승인 화면에 **예상 소모 합계를 채널 구성 그대로** 표시 — 체크 해제 시 합계 즉시 감소. 20크레딧+ 사전 확인 모달 원칙의 확장판.

**소진·취소 정책 [확정 0812 Harold 지시로 확정]**
- **승인 게이트** — 승인하려면 잔액 ≥ (대행 1000 + 그 달 예상 제작 합계). 승인 즉시 1000만 차감하고 제작분은 각 제작 시점 차감(예약 아님 — 행사 변경으로 합계가 달라질 수 있어 미리 잡지 않는다).
- **월 중 소진** — 제작 시점 402 → 그 터치포인트만 `보류(크레딧 부족)` + **발생 즉시 담당자 통지(알림톡+이메일)**. 행사가 조용히 증발하는 것이 최악이므로 통지는 선택이 아니라 의무다. 충전 후 [재개] 1클릭. 발송일까지 미해소면 그 터치포인트만 미실행 확정 + 결과 브리핑에 명시. **마이너스 허용·자동 충전 금지**(자동완화 금지 계열).
- **월 중 대행 취소** — 그 달 제작·실행된 터치포인트가 **0건이면 1000 전액 환불**(대행이 실제로 아무 일도 안 했다), 1건이라도 있으면 환불 없음(대행 개시). 일할 계산은 하지 않는다 — 규칙이 단순해야 분쟁이 없다. 환불은 멱등 + 감사 로그.

## §4 품질 전제 — 채널별 제작 입력 계약 (이 트랙의 본체) [확정 8]

### 4-2. 채널별 필수 입력 계약 [설계]

**계약: 필수 재료가 없으면 그 채널은 정직하게 잠근다**(기능 가능 여부는 고객사 데이터가 결정 — 하드코딩 금지, 없으면 잠금). 체크박스가 잠긴 이유를 그 자리에서 말한다.

| 채널 | 필수 실데이터 | 없을 때 |
|---|---|---|
| 이메일 브로마이드 | 상품(이미지·가격) + 이메일 보유 고객 N명 이상 + 브랜드 톤 | 잠금 + "이메일 보유 고객 없음" 등 사유 |
| 모바일 DM | 상품(이미지·가격) + 브랜드 톤 | 잠금(상품 없는 행사는 행사형 DM 템플릿으로 폴백 가능 — [미확인] 폴백 품질) |
| 인앱 | SDK 설치 몰 | 잠금 + "SDK 미설치" |
| 알림톡 | **정보성 안내 성립**(참여 신청자·예약자 등 관계 근거 — 광고 불가 [확정 11]) + APR 템플릿(**AX가 검수 대행** §5-6) | 광고 목적 체크 시 "알림톡은 정보성 안내 전용" 안내 / 리드타임 미달·재사용 템플릿 부재 시 그 터치포인트만 자동 제외 + 사유 |
| 메시징 | 발신번호·잔액/요금제 | 기존 발송 가드 그대로 |

- 혜택·수치는 **캘린더 기입 칸에서 고객사가 직접 쓴다**(AI 혜택 생성 금지 불변). 행사 기입 폼에 혜택 전용 칸을 두고, AI는 그 값을 verbatim으로만 쓴다.
- 상품 선정 층(재료 2)의 규칙 초안: 행사 기입 시 담당자가 상품을 직접 고르는 것이 기본, "AI 추천" 버튼은 판매 실데이터(기간 판매량·재구매율 실쿼리) 상위를 제안 — **추정 아닌 실쿼리, 추천이지 자동 선정 아님**(예측 타겟 금지 원칙의 상품판 유사 적용).

## §5 구조 설계

### 5-1. 데이터 모델 초안 [설계 — DDL은 구현 직전 information_schema 검증 후 확정]

- `planner_events` — 행사 원장: 회사·월·행사명·기간(시작~종료)·혜택 문구(고객사 기입)·선정 상품 목록(jsonb)·상태.
- `planner_touchpoints` — 터치포인트(행사×채널×시점): 채널·시점 규칙(D-5 사전 안내 / 시작일 / 종료일 등)·형식(브로마이드·삽입형 DM 등)·제작물 참조(제작 후 채움)·실행 참조(자동마케팅 회차/캠페인 id)·상태.
- `planner_monthly_approvals` — 월간 승인 원장: 회사·대상월·승인자·승인 시각·**차감 멱등키**·예상 크레딧 스냅샷(승인 당시 합계 — 나중에 단가가 바뀌어도 그 달 계약은 그대로)·결재 링크 토큰.
- 참여 동의는 신규 테이블 없이 **cdp_events 이벤트 유형**으로 적재하는 방향(기존 인프라 재사용) + 참여자 세그먼트는 saved_segments 자동 생성 — [미확인] cdp_events 유형 추가의 소비처 영향표는 구현 전 전수 grep.

### 5-2. 상태 기계 [설계]

행사: `draft → briefed(월간 브리핑 포함) → approved → producing(소재 제작) → scheduled(실행 예약) → done → reported`
이탈: `draft/briefed → cancelled` · `approved 이후 변경 → re_brief(그 행사만 재승인)` · **미승인 상태에서는 어떤 제작·발송도 일어나지 않는다(fail-closed).**

### 5-3. 승인 흐름 [설계]

- 월간 브리핑 = 스케줄러 화면의 결재 모드: 행사×터치포인트 타임라인 + 채널별 소재 실물 프리뷰(제작 전이면 스타일 방향) + 타겟 수 실쿼리 + 예상 크레딧·발송비 합계 + 문자 문안 "당일 생성" 표시.
- 결재 유도 = **알림톡 + 이메일 병행**(이메일 단독은 유실·스팸함으로 행사가 조용히 증발 — 미승인=미발송 구조라 치명적). 링크 = 서명 토큰(만료·1회성·회사/월 바인딩) → 로그인 → 결재 화면.
  - **★2026-08-13 실측으로 경로 확정 = 문자 + 화면 두 경로.** 알림톡은 담당자 통지 템플릿이 아직 없고(`continuous-operator.ts` `notifyOperatorAdmins` 안 TODO seam — 자동마케팅도 같은 상태), 플랫폼 이메일은 **한줄로 자체 메일 서버를 두지 않는다는 영구 룰** 때문에 `services/emailService.ts`가 의도적으로 실패를 반환하는 stub이고 `company-smtp-client.ts`는 고객사 자기 도메인 릴레이 전용이다. 그래서 지금 실행 가능한 조합은 **무과금 인증 라인 문자 + 플래너 화면 상단 결재 배너**다. "단일 경로 의존 금지"라는 이 항의 의도는 그대로 지킨다. 알림톡 병행은 통지 템플릿이 생기는 시점에 같은 함수로 붙는다.
  - **★2026-08-13 토큰 형태 = DB 저장 랜덤 토큰**(정산 컨펌 `invoice-confirm.ts`와 같은 형태). 무상태 서명 토큰(`journey-pause-handler.ts` 형태)은 **폐기·1회성을 만들 수 없어** 재제출해도 옛 링크가 계속 산다. 또한 토큰은 **딥링크 식별자일 뿐 결재 권한이 아니다** — 승인은 언제나 로그인한 고객사 사용자가 한다(링크만으로 승인되면 URL 유출이 곧 결재 위조다).
- 월 중 행사 추가·변경 = 그 행사만 `re_brief` → 개별 승인(대행료 추가 없음, 제작비 증분만 합계 갱신).
- D-1 사전 통지(정보성)는 자동마케팅 관례 유지 — 결재가 아니라 "내일 이 행사가 나갑니다" 안내.

### 5-4. 실행 배선 — 자동마케팅 엔진 재사용 [설계]

- 승인된 터치포인트 → 자동마케팅 실행 축에 등록. **문자 = 당일 발송 전 문안 생성 + 스팸필터 게이트(차단 시 재생성, CT-09) + 회차 스냅샷 + 피로도·미클릭·수신거부 게이트** 전부 기존 그대로 상속.
- ⚠ **자격 플래그 비대칭 [실측 0812]** — 자동마케팅의 자율 발송 자격은 `plans.advanced_access_enabled`인데 실값이 BUSINESS·ENTERPRISE·STAFF만 true고 **PRO는 false**다. 플래너 진입선이 PRO(§3-3)이므로 그 플래그를 그대로 요구하면 PRO가 크레딧은 되는데 엔진에서 막히는 모순이 난다. **판정: 플래너 발송은 사람이 월간 승인한 발송이라 "자율 실행 자격"과 축이 다르다 — `advanced_access_enabled`를 요구하지 않는다.** 단 구현은 자율 판정 우회가 아니라 **플래너 전용 진입 경로**로 — continuous-operator에서 그 플래그를 검사하는 지점 전수 grep + 영향표가 선행이다(6원칙 ④).
- 소재류(이메일·DM·인앱) = **승인 후 제작**(§3-4) → 제작물을 터치포인트에 연결 → 시점 규칙대로 발송/게시. DM URL은 당일 문자 문안에 삽입(URL 발급 = DM 축 그대로).
- 발송 시각: 기본값은 채널 관례, 자기 개선 루프 Phase 2(시각 환류)가 붙으면 그 추천이 여기로 들어온다 — 선반영하지 않는다.

### 5-5. 참여 동의 체인 [확정 4 + 설계]

사전 안내 이메일의 [참여하기] 버튼 → cdp_events 적재 → **참여자 세그먼트 자동 생성** → 이후 터치포인트(행사 당일 문자 등)가 그 세그먼트를 타겟으로 선택 가능. 채널들이 나열이 아니라 **행사 하나 안의 깔때기**가 된다. [미확인] 참여 의사 표시의 법적 성격(광고 수신동의와 별개임을 문구로 명확화 — 동의 버튼이 수신동의를 대체하지 않는다).

### 5-6. 알림톡 — 검수까지 AX가 대행한다 [확정 10·11로 재설계]

**역할 재정의 [확정 11]** — 알림톡은 광고 채널이 아니라 **정보성 안내 채널**이다. 플래너에서 알림톡 터치포인트의 자리는
행사 홍보가 아니라 **참여 신청 접수 확인 · 행사 시작 안내(신청자 대상) · 결과·당첨 안내** 같은 관계 기반 알림이다.
참여 동의 체인(§5-5)과 정확히 맞물린다 — 이메일에서 참여를 신청한 고객이 곧 알림톡 안내의 적법한 대상이 된다.
AX가 알림톡 문안을 만들 때는 **정보성 톤 강제 + 혜택·광고 표현 배제**(검수가 광고성을 반려하므로 이건 품질이 아니라 통과 조건이다).

**검수 대행 파이프라인 [확정 10]** — "D-X일까지 등록하러 가라"는 가드는 대행이 아니다. 흐름:
1. 행사에 알림톡 체크 + 월간 승인 → AX가 정보성 템플릿 문안 생성(변수 포함).
2. **검수 자동 제출** — [실측 §9-10 종결] 전 구간 서버 함수 실존: `createAlimtalkTemplate` → `requestInspection` → 상태 추적(`getRecentlyModifiedAlimtalkTemplates` + 30분 동기화 워커) → 반려 사유(`getAlimtalkCommentFile`). 신규 개발 = 오케스트레이션뿐.
3. 상태 추적 — 반려 시 **재생성·재제출 1회** + 담당자 통지(반려 사유 동반). 2회 반려면 그 터치포인트 보류 + 통지.
4. APR → 발송 예약에 자동 편입.

**리드타임 [확정 — 검수 실소요 보통 2~3일(Harold)]** — 가드 기준 = **5영업일**(실소요 상단 3일 + 반려·재검수 1회 여유.
검수는 우리 손 밖의 외부 절차라 하단이 아니라 상단에 여유를 얹는다). 의미가 바뀐다: 담당자를 막는 기준이 아니라
**AX가 검수를 맞출 수 있는가**의 판정선이다. 행사 첫 알림톡 발송일까지 5영업일 미만이면 — 재사용 가능한 APR 템플릿이 있으면 그걸로,
없으면 그 터치포인트만 자동 제외 + 브리핑에 사유 명시. 이미 APR 템플릿 보유 시 리드타임 무관 즉시 가능.

## §10 함정·절대 원칙 (요약)

- **[미확인]을 [확정]처럼 쓰지 마라** — 이 문서의 표기 규율이 곧 안전장치다.
- **미승인 = 미발송 = 미차감.** 어떤 경로도 이 게이트를 우회하지 않는다.
- **브리핑 수치는 전부 실쿼리** — 추정 수를 결재 서류에 올리는 순간 승인이 무의미해진다.
- **문안은 당일, 소재는 승인 후** — 사전 생성 문안을 다시 들여오지 마라(T스팸필터, [확정 1]).
- **알림톡만 리드타임이 있다** — 이 비대칭을 화면이 숨기면 행사 직전에 터진다.
- **대조 워커 없이 실행 배선을 열지 마라**(6원칙 ③) — 플래너와 실행 원장은 이중 진실이다.
- **크레딧 = 제작물(원가) + 대행(가치) 두 축** — 세 번째 축을 만들지 마라.
