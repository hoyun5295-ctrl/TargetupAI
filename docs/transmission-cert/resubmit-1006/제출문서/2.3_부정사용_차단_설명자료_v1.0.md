# 부정사용 차단 설명자료

주식회사 인비토 · 한줄로(hanjul.ai) · 전송자격인증 2.3 부정사용 차단

|---|---|---|

## 1. 원칙

이용료를 낸 사람 · 서비스를 쓰는 계정 · 발신번호 명의를 계정 기준으로 이어 두고, 명의가 맞지 않거나 정당한 결제 관계가 확인되지 않는 결제는 바로 충전하지 않는다. 자동으로 거절하지는 않고 보류한 뒤 소명을 받아 사람이 판단하며, 그 결과를 계정별로 남긴다.

## 2. 결제 수단별 계정 연결 (확인사항 ①)

| 결제 수단 | 계정과 연결되는 정보 |
|---|---|
| 카드 · 가상계좌 · 계좌이체(PG 결제) | 고객사 · 결제한 사용자 계정 · 주문번호 · 승인 키 · 결제 금액 · 결제 일시 · 결제 수단 · 처리 결과 · 구매자 정보 |
| 무통장 입금 | 고객사 · 신청 계정 · 입금자명 · 신청 금액 · 신청 일시 · 처리자 · 처리 일시 · 처리 메모 |
| 발송 에이전트 충전(비토 게이트웨이 이용 고객) | 고객사 · 충전 요청 · 실행 원장을 따로 둔다. 웹 서비스 잔액과 섞지 않는다. |

결제는 로그인한 계정 안에서만 시작되므로, PG 결제는 그 계정과 회사에 바로 귀속된다. 입금자 이름을 받지 못하는 PG 결제는 주문번호 · 승인 키 · 금액 · 일시 · 수단을 계정별로 남겨 사후 추적한다.

## 3. 명의 대조와 보류 (확인사항 ②)

1. 무통장 입금을 신청하면 입금자명을 계정에 등록된 명의(법인명 · 회사명 · 대표자명)와 시스템이 대조한다. 비교 전에 「주식회사」 · 「(주)」 같은 법인 표기와 띄어쓰기를 걷어내, 같은 이름의 다른 표기를 불일치로 잡지 않는다.
2. 명의가 맞지 않으면 **자동으로 거절하지 않고 보류**한다. 배우자 · 경리 · 법인 담당자 명의의 정상 입금이 있기 때문이다. 보류 사유와 보류 시각이 신청 건에 남는다.
3. 대조할 명의가 등록돼 있지 않거나 입금자명이 비어 있으면 「불일치」가 아니라 「확인 불가」로 따로 분류한다. 모르는 것을 불일치로 접으면 정상 충전이 대량으로 보류되기 때문이다. 확인 불가 건도 무통장 입금은 모두 관리자 승인을 거쳐야 충전된다.
4. 보류된 신청은 충전되지 않는다. 고객사는 화면에서 소명(입금자와의 관계 · 위임 관계 등)을 낼 수 있다.

## 4. 소명 확인과 처리 (확인사항 ②)

- 보류 건은 관리 화면의 승인 창에서만 승인된다. 이 창은 보류 사유와 고객사 소명을 함께 보여 주고, 여기서 승인해야 「소명 확인」이 함께 기록된다. 그 밖의 승인 요청(문자 링크 승인 등)은 시스템이 거부한다.
- 정당한 결제 관계가 확인되지 않으면 반려하고, 그 결제 건에 대한 서비스(충전)를 제공하지 않는다.
- 승인과 반려 모두 같은 처리 기록을 남긴다.
- 관리자가 금액을 직접 넣는 수동 충전은, 그 고객사에 명의 확인을 기다리는 입금 신청이 있으면 시스템이 거부한다(2026-10-05부터). 보류 건은 소명 확인 승인 또는 반려로만 닫힌다.
