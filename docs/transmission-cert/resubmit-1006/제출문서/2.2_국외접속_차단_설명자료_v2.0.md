# 국외 접속 차단 설명자료

주식회사 인비토 · 한줄로(hanjul.ai) · 비토 게이트웨이 · 전송자격인증 2.2 국외 이용자

| 문서번호 | 작성일 | 판 |
|---|---|---|
| ITU-GEO-2026-01 | 2026-08-28 최초 · 2026-10-03 개정 | 2.0 |

## 1. 목적과 적용 범위

국외에서의 계정 접속과 우회 접속을 막아, 계정 탈취를 통한 불법스팸 발송을 방지한다. 적용 범위는 이용자 웹 접속 · 운영 관리자 접속 · 연동 서버(SDK · 싱크에이전트) · 발송 에이전트와 API 연동(비토 게이트웨이)이다.

## 2. 기본 정책

기본은 차단이다. 국내 할당 대역에 드는 접속과 관리자가 승인한 예외만 통과하고, 그 밖의 국외 접속은 차단한다. **2026년 10월 1일부터 차단을 시행하고 있다.**

## 3. 국외 판정 방식

| 항목 | 내용 |
|---|---|
| 판정 기준 | 국내 할당 IP 대역 화이트리스트 |
| 대역 출처 | 아시아태평양 인터넷주소자원 관리기관(APNIC)의 국가별 할당 목록 중 한국 항목 · 2,597개 대역 |
| 갱신 방식 | 관리자 화면에서 전체 교체 등록. 부분 갱신을 허용하지 않아 빠진 대역이 남지 않는다. |
| 갱신 이력 | 갱신 시각 · 갱신 전후 대역 수 · 출처 · 처리자가 감사 기록에 남는다(최근 2026-08-30). |
| 판정 불가 | 사설 대역 · 판정 불가 접속은 막지 않고 기록한다. 판정 실패를 차단으로 접으면 정상 이용자가 함께 막히기 때문이다. |

## 4. 판정 지점

접속 세션이 만들어지는 지점에서 판정한다. 로그인 경로가 여럿이어도 세션 발급을 거치지 않는 경로가 없으므로 우회가 성립하지 않는다.

- 이용자 로그인 · 다중인증 완료 후 세션 발급
- 운영 관리자 로그인 · 인증 앱 최초 등록
- 비밀번호 확인 직후 선차단 단계: 국외 접속자가 인증 문자 발송이나 계정 잠금 같은 부수 효과를 일으키지 못하게 한다.

## 5. 접근 경로별 통제

| 시스템 | 접근 경로 | 통제 방식 | 상태 |
|---|---|---|---|
| 한줄로 | 이용자 웹(고객사 관리자 · 사용자) | 국내 대역 화이트리스트 · 예외 승인 | 차단 시행(2026-10-01) |
| 한줄로 | 운영 관리자 웹 | 같음 + 인증 앱(OTP) | 차단 시행(2026-10-01) |
| 한줄로 | SDK · 자사몰 연동(회사 API) | 회사별 등록 출발지 대조 | 미등록 출발지 기록 |
| 한줄로 | 싱크에이전트(회사 에이전트) | 회사별 등록 출발지 대조 | 미등록 출발지 기록 |
| 비토 게이트웨이 | 발송 에이전트 접속 | 계정별 허용 IP 필수 · 목록 밖 · 빈 목록이면 접속 거부 · 방화벽 접속 빈도 제한 | 차단 |
| 비토 게이트웨이 | 규격연동(TCP) | TLS 필수 · 활성 계정 허용 IP 밖은 연결 전 차단 · 접속 때 계정별 허용 IP 확인 | 차단 |
| 비토 게이트웨이 | API 연동 | 계정별 허용 IP 대조 | 미등록 출발지 기록(2026-10-03부터) |
| 서버 | 원격 관리(SSH) | 한줄로: 방화벽 허용 · 관리자(root) 직접 로그인 불가 · 로그인 실패 출발지 자동 차단 · 게이트웨이: 방화벽 출발지 지정 | 운영 중 |

연동 서버를 국가로 판정하지 않는 이유: 해외에 본사를 둔 고객사의 연동 서버가 정상 업무이기 때문이다. 대신 회사(또는 계정)별로 등록한 출발지만 통과시키며, 그 등록 행위 자체가 승인 이력이 된다.

## 6. 우회 접속 통제

- 국내 대역만 허용하는 방식이므로 국외에 출구가 있는 VPN · 프록시 · Tor · 해외 클라우드 접속은 국외 접속으로 판정돼 차단된다.
- 실제 사례: 2026-10-01 차단 16건은 모두 고객사 사내 보안 프록시의 해외 출구에서 들어온 로그인이었다(계정 2개 · 출발지 3곳). 차단 기록으로 확인했다.
- 예외로 허용하는 프록시는 고객사가 업무상 반드시 거치게 하는 사내 보안 프록시로 한정한다. 이때도 회사 전체가 아니라 그 계정에만, 사유를 적어 허용한다.
- 발송 에이전트 · 규격연동 · API 연동은 계정별 허용 IP를 지정하는 방식이라, 등록되지 않은 출발지는 국내외와 상관없이 막히거나 기록된다(5절 표).
- 같은 계정으로 다른 위치에서 동시에 접속하면 접속 인계 안내가 뜨고 기록된다.

## 7. 예외 승인

국외 접속이 불가피한 대상은 관리자 수동 승인으로만 허용한다.

- 사유를 적지 않으면 등록되지 않는다.
- 범위(계정 · 회사 API · 회사 에이전트 · 전역) · 허용 대역 · 사유 · 승인자 · 승인 일시 · 허용 만료일이 대장에 기록된다. 만료일이 지나면 자동으로 통과가 끊긴다.
- 회수는 기록 삭제가 아니라 비활성으로 한다. 이력이 사라지면 근거가 남지 않기 때문이다.
- 발송 에이전트 · API 연동의 허용 IP를 바꿀 때도 사유가 필수이며, 허용 만료일을 둘 수 있다. 바꾼 처리자 · 일시 · 바꾸기 전후 IP가 감사 기록에 남고, 만료일이 지나면 허용 IP가 자동으로 비워진다(2026-10-03부터).

|---|---|---|---|

## 8. 탐지 · 차단 기록

- 국외 접속은 차단 여부와 상관없이 전건 기록한다. 기록 항목은 일시 · 계정 · 소속 고객사 · 접속 IP · 처리 결과다.
- 열람은 대표와 지정된 운영 담당 계정만 할 수 있다.
- 차단되면 이용자에게 국내에서만 접속할 수 있다는 안내와 예외 등록 요청 방법을 보여 준다.
