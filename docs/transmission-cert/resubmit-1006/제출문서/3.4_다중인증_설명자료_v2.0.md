# 다중 인증 설명자료

주식회사 인비토 · 한줄로(hanjul.ai) · 비토 게이트웨이 · 전송자격인증 3.4 다중 인증

| 문서번호 | 작성일 | 판 |
|---|---|---|
| ITU-MFA-2026-01 | 2026-08-28 최초 · 2026-10-03 개정 | 2.0 |

## 1. 적용 대상과 인증수단

| 대상 | 1차 인증 | 2차 인증 | 이 문서 |
|---|---|---|---|
| 서비스 이용자(고객사 관리자 · 사용자) | 아이디 · 비밀번호 | 계정에 등록된 담당자 휴대폰으로 보내는 6자리 인증번호 | 2~5절 |
| 사설발송 연동(발송 에이전트 · API · 규격연동) | 해당 없음(사람이 로그인하지 않는다) | 연동 계정별 식별값 · 키 · 허용 IP · 서버 인증서 | 6절 |

서비스 이용자의 다중인증 수단은 휴대폰 인증번호 하나다. 인증 앱(OTP)은 당사 직원이 운영 관리자 화면에 들어올 때 쓰는 별도 통제이며 이용자 인증수단이 아니다(「접근권한 분류표」 1부).

## 2. 인증수단과 본인 확인 정보의 연계 (확인사항 ②)

- 계정마다 인증번호를 받을 휴대폰 번호 1개를 등록한다. 여러 사람이 함께 쓸 수 있는 인증수단을 막기 위해 한 계정에 번호를 여럿 두지 않고, 로그인 때 인증수단을 고르는 단계도 두지 않는다.
- 이 번호는 계정 발급 때 계약서로 확인한 발송 담당자의 휴대폰이다(「계정관리 설명자료」 2절). 이용자가 로그인 화면에서 번호를 입력하거나 바꿀 수 없다.

| 단계 | 번호가 정해지는 방식 | 적용 |
|---|---|---|
| 계약 확인 기반 | 계약 때 받은 담당자 번호를 당사가 등록한다. 변경도 당사가 새 담당자를 확인한 뒤 한다. | 운영 중 |
| 본인확인기관 연계 | 담당자가 본인확인기관 인증을 마치면 그 결과로 확인된 이름 · 휴대폰 번호가 계정 담당자와 인증번호 수신 번호로 등록된다. 손으로 입력하는 칸이 없다. 담당자 변경도 새 담당자의 본인확인으로만 한다. | 본인확인기관 연동 후 |

## 3. 인증 절차 (확인사항 ①)

1. 아이디 · 비밀번호를 확인한다.
2. 등록된 담당자 휴대폰으로 6자리 인증번호를 보낸다. 카카오 알림톡으로 보내고, 알림톡이 실패하면 같은 문구를 문자로 보낸다.
3. 인증번호는 5분간 유효하다. 다시 받기는 60초 간격으로만 된다.
4. 인증번호가 맞아야 접속 세션이 발급된다. 로그인할 때마다 인증한다. 기기나 접속 위치를 기억해 인증을 건너뛰는 기능은 두지 않는다.
5. 인증번호 발송분은 이용자에게 과금하지 않는다.

## 4. 실패 통제

| 상황 | 조치 | 해제 |
|---|---|---|
| 비밀번호 실패 누적 | 남은 시도 횟수를 로그인 화면에 알린다. | 해당 없음 |
| 같은 출발지 · 아이디로 10분 안에 비밀번호 5회 실패 | 30분간 자동 차단하고 차단 안내를 표시한다. | 30분 경과 또는 관리자 해제 |
| 인증번호 5회 실패 | 계정을 잠그고 접속 중인 세션을 끊고, 담당자 휴대폰으로 잠금 사실을 알린다. | 당사 관리자 확인 후 해제 |

## 5. 등록 · 변경 · 재설정 이력 (확인사항 ③)

| 행위 | 재확인 | 남는 기록 |
|---|---|---|
| 인증번호 수신 번호 등록 · 변경 | 계약 담당자 확인(본인확인기관 연동 뒤에는 새 담당자의 본인확인) | 처리자 · 대상 계정 · 변경 전후 번호(가림) · 일시 |
| 번호가 바뀐 뒤 옛 번호로 받은 인증번호 | 무효로 처리한다(발급 번호와 계정의 현재 번호를 대조) | 해당 없음 |
| 인증번호 요청 · 성공 · 실패 · 잠금 | 해당 없음 | 계정 · 일시 · 접속 IP · 결과 |

기록은 감사 기록에 남고, 대표 등급 계정만 조회한다.

## 6. 소셜 로그인 (확인사항 ⑤)

소셜 계정 로그인을 제공하지 않는다. 로그인은 당사가 발급한 아이디 · 비밀번호 + 인증번호 한 가지뿐이다.

## 7. 사설발송 연동의 발송 요청 인증수단 (확인사항 ⑥)

비토 게이트웨이로 들어오는 고객사 서버 연동은 사람이 로그인하지 않으므로, 연동 계정마다 아래 수단으로 발송 요청을 인증한다.

| 연동 유형 | 식별 | 비밀값 | 출발지 | 전송 구간 |
|---|---|---|---|---|
| 발송 에이전트 | 연동 계정 고유 식별값 | 계정별 토큰(서버에는 해시로만 저장) | 계정별 허용 IP 필수. 목록이 비었거나 목록 밖이면 접속을 거부한다. | TLS |
| API 연동 | 연동 계정 고유 식별값 | 계정별 API 키 | 계정별 허용 IP와 대조 · 기록 | TLS |
| 규격연동 | 연동 계정 고유 식별값 | 계정별 토큰 + 계정별 클라이언트 인증서(필수로 지정한 계정) | 활성 계정 허용 IP 밖은 연결 전 차단 | TLS 1.2 이상 |

- 토큰 재발급 · 설치 묶음 발급 · 클라이언트 인증서 필수 지정과 해제 · 허용 IP 변경은 처리자 · 일시 · 대상 계정과 함께 감사 기록에 남는다. 허용 IP를 바꿀 때는 사유가 필수이고 허용 만료일을 둘 수 있다.
- 발송 에이전트는 발급 때 연동 계정과 허용 IP가 함께 정해진다. 식별값 · 토큰이 새어도 허용 IP 밖에서는 접속할 수 없다.
