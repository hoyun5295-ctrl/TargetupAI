# 추가 인증(발신 인증) 설명자료

주식회사 인비토 · 한줄로(hanjul.ai) · 비토 게이트웨이 · 전송자격인증 3.5 추가 인증

| 문서번호 | 작성일 | 판 |
|---|---|---|
| ITU-SNDAUTH-2026-01 | 2026-08-28 최초 · 2026-10-03 개정 | 2.0 |

## 1. 목적

문자를 보내는 순간에 발신번호와 발송 계정의 연계를 한 번 더 확인해, 계정이 탈취되었거나 발신번호가 도용된 상태에서의 발송을 막는다.

## 2. 인증수단 (확인사항 ① · ②)

- 발송 계정에 등록된 담당자 휴대폰으로 6자리 인증번호를 보내고, 입력값이 맞아야 발송이 진행된다. 카카오 알림톡으로 보내고, 실패하면 같은 문구를 문자로 보낸다.
- 인증번호를 받는 번호는 로그인 다중인증과 같은 계정 담당자 번호다(「다중 인증 설명자료」 2절). 계약 때 확인한 담당자 번호이며, 본인확인기관 연동 뒤에는 본인확인 결과로 등록된 번호다.
- 발신번호는 등록 때 증빙 서류 확인과 승인을 거친 번호만 쓸 수 있다(「계정관리 설명자료」 6절). 발신 인증은 그 승인된 발신번호와 발송 계정의 담당자를 발송 시점에 한 번 더 묶는다.
- 인증 앱(OTP)은 이 절차에 쓰지 않는다. 인증 앱은 당사 직원의 운영 관리자 화면 접속에만 쓴다.

| 항목 | 값 |
|---|---|
| 인증번호 유효 시간 | 5분 |
| 입력 실패 한도 | 5회(넘으면 그 인증번호는 무효) |
| 다시 받기 | 60초 간격 |

## 3. 적용 대상 (확인사항 ①)

| 발송 | 발신 인증 | 근거 |
|---|---|---|
| 이용자가 화면에서 직접 실행하는 문자 발송(직접 발송 · 캠페인 발송) | 적용 | 이용자가 발송을 지시하는 순간 |
| 예약 발송 | 예약을 등록하는 순간에 적용 | 등록 행위가 이용자 개입이다 |
| 조건이 맞으면 시스템이 실행하는 자동 발송(여정 · 자동 발송) | 생략 | 이용자 개입이 없는 시스템 발송. 설정과 활성화는 로그인(다중인증)한 이용자가 한다 |
| 사설발송 연동(발송 에이전트 · API · 규격연동) | 대체 통제(7절) | 사람이 화면을 거치지 않는다 |

## 4. 유선번호 · 대표번호 (확인사항 ③)

유선번호 · 대표번호로 보낼 때도 같은 절차를 쓴다. 인증번호는 발신번호로 보내지 않고 **발송 계정의 담당자 휴대폰**으로 보낸다(계정 · 서비스 연계 인증). 그래서 휴대폰이 아닌 발신번호도 담당자 확인 없이 발송할 수 없다. ARS 인증은 두지 않는다.

## 5. 유지 시간과 재인증 (확인사항 ④)

인증은 **발송 계정과 발신번호의 짝** 단위로 기억한다. 한 발신번호로 받은 인증은 다른 발신번호에 쓰이지 않는다. 받는 사람마다 회신번호가 다른 발송처럼 발신번호를 하나로 정할 수 없으면, 그 계정의 그런 발송 전체를 하나의 단위로 따로 인증한다.

| 재인증하는 경우 | 이유 |
|---|---|
| 인증 후 8시간이 지났다 | 유지 시간 만료 |
| 처음 쓰는 발신번호다 · 발신번호가 바뀌었다 | 인증이 발신번호 단위다 |
| 접속 IP 대역 또는 접속 프로그램이 인증 때와 다르다 | 접속 환경 변경 |
| 경과 시간을 확인할 수 없다 | 모르면 다시 묻는다 |

인증이 유효한 동안에는 다시 묻지 않고 발송한다. 받는 사람 수는 인증 여부를 바꾸지 않는다. 대량 발송도 같은 발신 인증과 금칙어 차단을 거친다(「불법스팸 발송 방지계획서」 5절).

## 6. 기록

| 기록 | 남는 항목 |
|---|---|
| 인증번호 요청 | 계정 · 발신번호 · 수신 번호(가림) · 접속 IP · 일시 |
| 인증 성공 | 계정 · 발신번호 · 수신 번호(가림) · 접속 IP · 일시 |

기록은 감사 기록에 남고, 대표 등급 계정만 조회한다.

## 7. 사설발송 연동의 대체 통제 (확인사항 ⑤)

비토 게이트웨이로 들어오는 연동 발송에는 인증번호 대신 다음 통제를 적용한다.

| 통제 | 내용 |
|---|---|
| 연동 계정 인증 | 연동 계정 고유 식별값 · 토큰 또는 API 키 · 계정별 허용 IP · 서버 인증서(「다중 인증 설명자료」 7절) |
| 고객사 발신번호 사전 등록 | 고객사마다 승인된 발신번호 목록을 둔다. 발송 요청의 발신번호가 목록에 없으면 엔진이 **발송 전에** 실패 처리한다. |
| 발신번호 등록 · 정책 변경 기록 | 처리자 · 일시 · 고객사 · 번호가 감사 기록에 남는다. |
