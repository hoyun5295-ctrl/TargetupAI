# 접근권한 분류표

이 문서의 권한 구분과 권한 수준은 운영 시스템이 실제로 판정하는 값과 같다. 운영 관리자 화면의 「직원 계정 · 권한」에 같은 표가 표시된다.

## 1부. 당사 직원 계정 (운영 관리자)

### 1-1. 등급

| 등급 | 대상 | 범위 |
|---|---|---|
| 대표 | 대표이사 | 전 영역. 직원 계정 변경과 감사 기록은 이 등급만 다룬다. |
| 지원팀장 | 모바일 지원팀장 | 운영 · 보안 전 영역. 직원 계정은 조회만. 감사 기록 · 학습 데이터는 제외. |
| 지원팀원 | 모바일 지원팀 실무자 | 운영 영역 조회 · 변경. 삭제 · 시스템 설정 · 보안 화면은 제외. |

등급은 계정마다 저장되며 권한 판정은 저장된 등급 값으로만 한다. 등급 값이 비었거나 모르는 값이면 가장 낮은 등급으로 판정하고, 등급 조회가 실패해도 가장 낮은 등급으로 판정한다.

운영 기록 대장은 고치기 · 지우기가 없다. 정정은 새 기록으로 남기고, 기록한 사람과 다른 관리자가 확인해야 완료된다.

보안 · 인증 화면(직원 계정 · 권한 · 로그인 차단 · 국외 접근 통제 · 금칙어 차단 · 감사 로그 · 운영 기록 대장)은 대표와 지원팀장만 쓴다. 감사 로그는 대표만 보고, 직원 계정은 지원팀장이 조회만 한다. 관리자 화면은 등급이 열지 않는 메뉴를 보여 주지 않고, 서버도 같은 표로 요청을 막는다.

### 1-3. 등급 배정 근거

등급은 최근 90일 관리자 행위 기록으로 실제 수행 업무를 확인해 배정했다.

- 요금 단가 변경을 지원팀장이 90일간 70건 수행하고 있어 요금 영역을 대표 전용으로 두지 않았다. 통제를 이유로 실무를 막지 않는다.
- 지원팀원 2명은 90일간 고객DB 전체 삭제 기록이 없어 삭제 권한을 제외했다.
- 감사 기록과 학습 데이터는 대표 전용으로 두었다.
- 보안 · 인증 화면은 통제 장치를 운영하는 지원팀장(불법스팸 대응 책임자 · 점검 담당)과 대표로 좁혔다. 지원팀원은 고객 · 발송 · 요금 실무 화면만 쓴다(2026-10-03).

### 1-4. 부여 · 변경 · 회수 절차 (3.2 ③ · 3.3 ① ②)

| 절차 | 규칙 | 기록 |
|---|---|---|
| 계정 생성 | 대표 등급만 한다. 생성 때 등급을 지정하고 발급 사유를 남긴다(비워 두면 「신규 직원 계정 발급」으로 기록). 첫 로그인 때 인증 앱(OTP) 등록이 요구된다. | 처리자(승인자) · 대상 · 등급 · 사유 · 접속 IP · 시각 |
| 초기 비밀번호 | 본인이 비밀번호를 바꾸기 전에는 접속 세션이 발급되지 않는다. | 변경 일시 |
| 등급 변경 | 대표 등급만 한다. 사유를 적지 않으면 저장되지 않는다. | 처리자(승인자) · 대상 · 변경 전후 등급 · 사유 · 접속 IP · 시각 |
| 사용 중지 · 재개 | 대표 등급만 한다. 사유를 적지 않으면 처리되지 않는다. 계정을 지우지 않고 사용만 막는다. 지우면 그 계정이 남긴 기록의 주체를 특정할 수 없다. 중지하면 그 계정이 접속 중인 세션도 즉시 끊고, 남은 세션이 없는지 다시 확인한 뒤에 처리 완료로 표시한다. | 처리자 · 대상 · 사유 · 끊은 세션 수 · 시각 |
| 최소 인원 보호 | 활성 대표 등급이 한 명뿐이면 그 계정의 강등과 중지를 시스템이 거부한다. | 없음 |

등급 변경과 사용 중지는 대표 등급만 할 수 있으므로 처리자가 곧 승인자다. 이 기록이 「접근권한 변경 이력 및 사유 관리대장」이며, 관리자 화면에서 승인자 열과 함께 조회한다.

### 1-6. 공용 계정 처리 (3.2 ④)

여러 담당자가 함께 쓰던 관리자 계정이 있었다. 행위 기록의 주체를 특정할 수 없으므로 실제 사용자 앞으로 개인 계정을 새로 발급하고, 공용 계정은 사유를 남겨 사용 중지했다. 처리 내역은 접근권한 변경 이력 대장에 남아 있다.

### 1-8. 비토 게이트웨이 관리 콘솔

게이트웨이 관리 콘솔은 별도 계정 체계(2계정)를 쓴다. 대표 계정(대표이사 전용)과 운영 계정으로 나뉘며, 감사 기록 조회는 대표 계정만 할 수 있다. 로그인은 계정 인증 + 인증 앱(OTP)이고, 로그인 성공 · 실패 · 2차 인증이 감사 기록에 남는다.

## 2부. 고객사 계정

### 2-1. 계정 구분

| 구분 | 설명 |
|---|---|
| 고객사 관리자 | 고객사 대표 계정. 소속 회사 범위의 관리 |
| 고객사 사용자 | 고객사 발송 실무 계정 |
| 시스템 계정 | 연동 · 배치 전용. 화면 로그인 불가 |

고객사 계정의 권한은 모두 소속 회사 범위로 한정된다. 다른 회사의 자료에는 어떤 등급도 접근할 수 없다.

추가 제한 축: 기능 숨김(고객사 관리자가 소속 사용자에게 메뉴 · 기능 비노출 설정) · 매장 배정(배정된 매장 데이터만 조회 · 발송) · 계정 상태(정상 · 잠금 · 휴면, 잠금 · 휴면은 로그인 불가) · 계약 상태(종료 · 정지 시 계정 상태와 무관하게 전면 차단)

### 2-2. 권한분류표

「당사」 열은 1부 권한분류표의 해당 영역 권한을 따른다.

| 기능 | 당사 | 고객사 관리자 | 고객사 사용자 | 비고 |

### 2-3. 고객사 계정 회수

| 상황 | 조치 |
|---|---|
| 고객사 담당자 변경 | 계정 담당자 변경(새 담당자 확인 후 인증번호 수신 번호 변경 · 이력 기록) 또는 기존 계정 비활성 + 신규 발급 |
| 고객사 계약 해지 · 정지 | 회사 단위 차단 + 소속 계정 비활성 + 접속 중 세션 종료 + 회수 이력 |
| 장기 미사용 | 정기 점검에서 확인 후 비활성 |

회수는 계정마다 상태를 바꾸는 데 기대지 않는다. 로그인 때 회사 단위 차단을 판정하므로 계정 상태 반영이 늦어도 접속되지 않는다.
