설계 원칙

- 통제는 발송이 시작되는 길목 하나에 둔다. 화면마다 검사를 복사하면 반드시 빠진 경로가 생긴다.
- 막는 장치가 고장 났을 때 무엇을 잃는지 먼저 정한다. 필터 오류로 전 고객 발송이 멈추는 것이 오탐보다 큰 사고인 구간에서는 통과를 기본값으로 두고, 그 판단 근거를 남긴다.
- 모든 조치는 기록을 남긴다. 처리자 · 일시 · 사유 · 대상이 없는 조치는 조치로 보지 않는다.

## 4. 1단계: 계정 통제

### 4-1. 계약 확인 후 당사 역발급

- 공개 회원가입 경로가 없다. 계정은 계약을 체결하고 사업자등록증을 확인한 뒤 당사가 발급한다.
- 고객사는 스스로 계정을 만들 수 없다. 고객사 관리자 화면의 계정 추가 기능을 막고, 추가가 필요하면 당사에 요청하도록 안내한다(2026-10-02부터).
- 계정을 발급하면 발급자 · 발급 일시 · 대상 계정 · 고객사가 감사 기록에 남는다(2026-10-02부터. 그 전에 만든 계정은 계정 생성일로 확인한다).
- 계정은 실제 발송 담당자 단위로 발급하며, 공용 계정 사용은 통제 대상이다(4-7).

### 4-2. 발신번호 사전 등록과 회선 수 제한

- 등록 · 승인되지 않은 번호로는 발송할 수 없다. 발신번호는 증빙 서류를 확인하고 승인 절차를 거쳐 등록한다.
- 회선 수 상한은 등록 시점에 시스템이 검사한다. 상한은 신규 등록에만 적용하고 기존 보유분은 회수하지 않는다.
- 상한 값은 가입자 유형별 기준을 따른다. 개인 · 외국인 기준값은 시스템에 고정돼 회사 설정으로 올릴 수 없다. 법인 무선은 그 회사의 사용 중인 계정 수에 4를 곱한 값을 시스템이 계산하고, 회사 설정은 그보다 좁히기만 할 수 있다(2026-10-03부터). 법인 유선은 종사자 수 확인 자료를 받아 당사가 회사별 상한을 설정한다. 등록 길목 세 곳(관리자 직접 등록 · 고객사 등록 · 등록 신청 승인)에서 같은 검사를 한다.

| 가입자 유형 | 무선 | 유선 |
|---|---|---|
| 개인 | 3 | 5 |
| 외국인 | 2 | 5 |
| 법인 | 사용 중인 계정 1개당 4 | 종사자 수 기준 회사별 설정 |

### 4-3. 다중인증

- 계정마다 인증번호를 받을 휴대폰 번호 1개를 등록한다. 여러 사람이 함께 쓸 수 있는 인증수단을 막기 위해 복수 번호 등록은 허용하지 않는다.
- 로그인할 때마다 6자리 인증번호를 보낸다(카카오 알림톡, 실패하면 같은 문구로 문자 전환). 인증번호는 5분간 유효하다. 기기나 접속 위치를 기억해 인증을 건너뛰는 기능은 두지 않는다.
- 인증번호를 5회 틀리면 계정을 잠그고, 잠금 해제는 당사 관리자 조치로만 한다.
- 인증번호 수신 번호를 바꾸면 처리자 · 대상 계정 · 일시를 기록한다.
- 운영 개시: 2026-09-11. 고객 전 계정 의무 적용: 2026-10-26(모든 메시징 사업자 공통 시행일 · 로그인 화면에서 사전 고지 중).

### 4-4. 국외 접속 차단

- 국내에 할당된 IP 대역 목록(APNIC 기준 2,597개 대역)을 보유하고, 그 대역에 들지 않는 로그인을 국외 접속으로 판정해 차단한다. 2026-10-01부터 차단을 시행하고 있다.
- 차단 여부와 상관없이 국외 접속은 전건 기록한다(일시 · 계정 · 출발지 · 판정).
- 업무상 필요한 예외(고객사 사내 보안 프록시 의무 경유, 고객사 고정 접속 서버 등)는 사유 없이 등록되지 않는다. 범위 · 대역 · 사유 · 승인자 · 승인 일시 · 허용 만료일을 함께 기록하며, 회수할 때도 지우지 않고 비활성으로 이력을 보존한다.
- API · 모듈(SDK · 싱크에이전트) 경로는 국가가 아니라 회사별로 등록한 출발지 대역과 대조한다. 해외에 본사를 둔 고객사의 연동 서버가 정상 업무이기 때문이다. 등록되지 않은 출발지에서 온 호출은 기록한다.

### 4-5. 부정사용 차단: 결제 명의 대조

- 무통장 입금 신청 때 입금자명을 계정에 등록된 명의(법인명 · 회사명 · 대표자명)와 대조한다.
- 불일치는 자동 거절하지 않고 보류한다. 배우자 · 경리 · 법인 담당자 명의 입금이 정상적으로 있기 때문이다.
- 보류 건은 고객사가 소명을 낼 수 있고, 관리자가 소명을 확인했다는 표시 없이는 승인되지 않는다.
- 승인 · 반려 결과를 처리자 · 사유와 함께 계정별로 기록한다.

### 4-6. 계약 종료 · 정지 즉시 차단

- 계약이 종료되거나 정지된 고객사는 계정 상태와 상관없이 로그인이 차단된다. 계정마다 상태를 바꾸는 데 기대지 않고 회사 단위에서 판정한다.
- 해지 처리 때 소속 계정을 비활성화하고 접속 중인 세션을 즉시 끊는다.
- 회수 이력(처리자 · 일시 · 잠근 계정 수 · 끊은 세션 수)을 남긴다.

### 4-7. 공용 계정 통제

- 같은 계정으로 다른 위치에서 동시에 접속하면 기존 접속을 넘겨받을지 묻는 안내가 뜨고 그 시도가 기록된다. 이 기록을 공용 계정 탐지 지표로 쓴다.
- 입력이 없는 세션은 기본 8시간이 지나면 자동으로 끊는다.
- 접속 출발지가 지나치게 분산된 계정은 월간 점검에서 확인하고 계정 분리를 안내한다.

### 4-8. 로그인 무차별 시도 차단

같은 출발지 IP와 로그인 ID 조합으로 10분 안에 5회 실패하면 30분간 자동 차단한다. 남은 시도 횟수를 화면에 알리고, 차단을 기록한다.

## 5. 2단계: 발송 시점 통제

아래 통제는 웹 · API · 모듈 전 경로에 같게 적용된다.

### 5-1. 금칙어 조합 차단

- 차단정보 요소는 키워드 · URL · 전화번호 세 유형이며, 2개 이상 5개 이하의 조합으로만 규칙을 만든다.
- 단일 키워드 규칙은 만들 수 없다. 「대출」 한 단어로 걸면 금융 고객사의 정상 발송이 모두 걸리기 때문이다. 요소가 전부 일치할 때만 걸린다(예: 무직자 + 당일 + 단축 URL).
- 조합 개수를 부풀릴 수 없도록, 같은 값이거나 다른 요소에 포함되는 요소(예: 「대출」과 「무직자대출」)는 하나로 접은 뒤 개수를 판정한다.
- 규칙마다 「탐지」 또는 「차단」으로 운영한다. 새 규칙은 탐지로 시작하고, 실제 발송 문안에 돌려 보는 오탐 확인을 거친 뒤 관리자가 차단으로 전환한다. 규칙 등록 · 전환은 대표 · 지원팀장 등급만 할 수 있고(「접근권한 분류표」 1-2), 전환한 관리자 · 일시 · 전환 전후 값이 기록된다.
- 차단 규칙에 걸린 문자(SMS · LMS · MMS) 발송은 요금 차감과 발송 접수 전에 중지되고, 발송자에게 차단 안내가 표시된다. 웹 발송 · 예약 발송 · 자동 발송 · 여정 발송 · 대행 발송이 같은 판정을 거친다. 걸린 규칙의 내용은 발송자에게 알리지 않는다(요소를 알면 그것만 피한 문안이 나온다).
- 판정 장치에 오류가 나면 발송을 막지 않고 오류를 기록한다. 판정 오류 하나로 전 고객사의 발송이 멈추지 않게 하기 위해서다.
- 회사별 예외를 둘 수 있다. 금융사에게 「대출」은 정상 업무 용어다.
- 차단과 탐지 모두 이력(규칙 · 고객사 · 발송 경로 · 건수 · 문안 표본 · 차단 또는 탐지)으로 남는다. 문안 표본은 4자리 이상 숫자열을 가려 저장한다. 담당자는 이 이력을 월간 점검에서 확인하고, 불법스팸으로 판정되면 6절 절차로 조치한다.
- KISA 등 외부기관이 공유하는 차단정보는 출처를 표시해 규칙으로 등록한다.

### 5-2. 통신사 스팸 사전 검사

발송 전에 통신사 스팸 판정을 미리 확인하는 검사를 제공한다. 3개 통신사 시험 회선으로 실제 판정 결과를 받아, 차단될 문안을 보내기 전에 확인한다.

### 5-3. 광고성 정보 표기 자동 부착

광고성 메시지에는 본문 앞에 (광고)를, 본문 끝에 무료수신거부 번호를 시스템이 자동으로 붙인다. 사용자가 지우거나 빠뜨릴 수 없다.

| 채널 | 붙는 형태 |
|---|---|
| SMS | (광고) + 본문 + 줄바꿈 + 무료거부{080번호} |
| LMS · MMS | (광고) + 본문 + 줄바꿈 + 무료수신거부 {080-번호} |

### 5-4. 무료수신거부(080) 연동

- 회사별 080 번호를 등록해 쓰며, 수신자가 080으로 거부 의사를 밝히면 자동으로 수집돼 수신거부 명단에 반영된다.
- 080 이용료는 회사별로 정산한다.

### 5-5. 수신거부자 자동 제외

- 수신거부 명단은 계정 단위로 분리돼 있으며, 발송 대상을 뽑을 때 자동으로 빠진다.
- 시스템을 옮기거나 합칠 때도 수신거부 명단을 모두 보존한다.
- 엑셀 일괄 등록과 자동 동기화를 함께 제공한다.

### 5-6. 광고 발송 가능 시간 제한

광고성 자동 발송은 허용 시간대(한국 표준시 08:00~21:00) 밖에서 실행되지 않는다. 예약 시각이 허용 시간대를 벗어나면 등록 단계에서 거부한다.

### 5-7. 발송 대상 0건이면 발송 차단

조건에 맞는 대상이 없을 때 시스템이 조건을 임의로 넓히지 않고 발송을 막는다. 원하지 않은 수신자에게 광고가 도달하는 것을 구조적으로 막기 위한 장치다.
