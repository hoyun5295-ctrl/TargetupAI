# 방화벽 운영 정보 및 네트워크 구성도

주식회사 인비토 · 한줄로(hanjul.ai) · 비토 게이트웨이 · 전송자격인증 3.1 방화벽 설치

| 문서번호 | 작성일 | 판 |
|---|---|---|
| ITU-NET-2026-01 | 2026-08-19 최초 · 2026-10-03 개정(방화벽 운영 정보 통합) | 2.0 |

## 1. 설비 구성

자사 설비는 자체 하드웨어를 데이터센터(IDC)에 임대(콜로케이션)해 운용한다. 서비스 설비는 같은 IDC 대역 안에 있다.

| 설비 | 소유 | 역할 |
|---|---|---|
| 한줄로 서버 | 자사 | 웹 발송 화면 · API · 데이터베이스 · 발송 대기열 · 발송 에이전트 |
| 비토 게이트웨이 서버 | 자사 | 고객사 발송 에이전트 · API · 규격연동 접속을 받아 중계 구간으로 전달하고 결과를 회신 |
| 사내 서버 | 자사 | 사내 업무 시스템 · 사내 확인용 발송 에이전트(게이트웨이 허용 IP로만 접속) |
| 중계 서버 | 자사 1 · 중계사 2 | 이동통신사 · 카카오로 연결되는 구간 |
| 백업 보관 서버 | 자사 | 암호화된 백업 파일만 받는다 |

## 2. 트래픽 경로

| 구간 | 암호화 | 설명 |
|---|---|---|
| 이용자 → 한줄로 서버 | TLS | 웹 발송 화면 |
| 고객사 자사몰 · 사내 서버 → 한줄로 서버 | TLS | SDK · 싱크에이전트. 발급 키 인증 + 회사별 등록 출발지 대조 |
| 한줄로 서버 → 중계 서버 | 중계 규격 연결 | 웹 발송분 |
| 고객사 서버 → 게이트웨이 | TLS | 발송 에이전트 · API · 규격연동. 계정별 키 · 토큰 + 허용 IP |
| 게이트웨이 → 중계 구간 → 이동통신사 · 카카오 | 중계 규격 연결 | 게이트웨이 발송분 |
| 한줄로 · 게이트웨이 → 백업 보관 서버 | 파일 암호화 | 공개키로 암호화된 백업 파일만 전송 |

## 3. 방화벽 계층

| 계층 | 종류 | 역할 | 운영 주체 |
|---|---|---|---|
| 1차 | 데이터센터(하나로호스팅) 브릿지 방화벽 | 서버 IP 마다 허용할 포트 · 프로토콜 · 출발지를 등록해 통과시키고, 그 밖은 기본 정책으로 차단한다 | 당사가 호스팅 관리 화면에서 정책을 등록 · 적용 |
| 2차 | 서버별 호스트 방화벽(Linux netfilter · ufw) + 무차별 시도 · 과다 요청 자동 차단(fail2ban) | 서버마다 인바운드 기본 차단 · 허용 서비스만 개방 | 당사 |
| 3차 | 웹 리버스 프록시(nginx) | 웹 요청 종단 · TLS 종료 · 요청 빈도 제한 | 당사 |
| 4차 | 애플리케이션 접근통제 | 계정 인증 · 국외 접속 차단 · 등록 출발지 · 계정별 허용 IP · 권한 등급 | 당사 |

## 4. 서버별 정책 (2026-10-03 실측)

### 4-1. 한줄로 서버

기본 정책: 들어오는 연결 차단 · 나가는 연결 허용 · 경유 트래픽 차단 · 차단 기록 활성

| 포트 | 용도 | 허용 출발지 |
|---|---|---|
| 22/tcp | 원격 관리(SSH) | 출발지 지정(대표 · 사무실) · 관리자(root) 직접 로그인 불가 · 로그인 실패가 쌓인 출발지 자동 차단 |
| 80 · 443/tcp | 웹 서비스 | 전체 |
| 3000 · 9001~9011 | 애플리케이션 · 발송 에이전트 내부 포트 | 명시 차단(외부 접근 불가) |
| 결제 통계 수집 포트 | 데이터 수신 전용 | 컨테이너 전용 방화벽 체인에서 송신 서버 5곳만 허용 · 그 밖은 차단 |
| 데이터베이스(PostgreSQL · MySQL · Redis) | 내부 전용 | 서버 내부 주소에만 열려 있어 외부 접근 불가 |

데이터센터 브릿지 방화벽(1차)에도 외부 허용분만 등록했다: 22/tcp(대표 · 사무실) · 80 · 443/tcp(전체) · 결제 통계 수집 포트(송신 서버 5곳) · ICMP. 그 밖은 기본 정책으로 차단한다(2026-10-03 적용).

### 4-2. 비토 게이트웨이 서버

게이트웨이는 방화벽과 애플리케이션 허용 목록 두 층으로 접속을 거른다.

| 포트 | 용도 | 1층: 방화벽 | 2층: 애플리케이션 |
|---|---|---|---|
| 9443/tcp | 발송 에이전트(TLS) | 지정 서버 3곳 허용 + 그 밖은 접속 빈도 제한 | 계정별 허용 IP가 없거나 목록 밖이면 접속 거부 |
| 9444/tcp | 규격연동(TLS) | 접속 빈도 제한 | 활성 계정 허용 IP 밖은 연결 전 차단 · 접속 때 계정별 허용 IP 확인 |
| 443/tcp | API 연동 · 관리 콘솔 | 허용 | 계정 키 인증 · 계정별 허용 IP 대조 · 관리 콘솔은 계정 인증 + 인증 앱(OTP) |
| 80/tcp | 인증서 자동 갱신 | 허용 | 해당 없음 |
| 4404/tcp | RCS 결과 수신(웹훅) | 지정 출발지 1곳(대표) | 해당 없음 |
| 22/tcp | 원격 관리(SSH) | 출발지 지정(대표 · 사무실) | 무차별 시도 자동 차단 |
| 데이터베이스 | 내부 전용 | 서버 내부 주소에만 열려 있음 | 발송 엔진 · 관리 API만 접속 |

데이터센터 브릿지 방화벽(1차) 허용 줄: 22/tcp(대표 · 사무실) · 4404/tcp(대표) · 80 · 443 · 9443 · 9444/tcp(전체) · ICMP. 그 밖은 기본 정책으로 차단한다(2026-10-03 기준).

## 5. 허용 · 차단 정책의 기준 (확인사항 ②)

- 인바운드는 기본 차단이고, 서비스에 필요한 포트만 연다.
- 애플리케이션 내부 포트와 데이터베이스는 외부에 열지 않는다.
- 고객사 연동은 국가가 아니라 계정 · 회사별 등록 출발지로 통과시킨다(「국외 접속 차단 설명자료」).
- 컨테이너가 직접 게시하는 포트는 호스트 방화벽을 거치지 않으므로, 컨테이너 전용 체인에 출발지 제한을 따로 걸고 재부팅 뒤에도 유지되게 해 두었다.

## 6. 우회 · 비가시 경로 통제 (확인사항 ③)

- 서버 관리 접속은 SSH 하나다. 관리 편의를 위한 별도 원격 접속 경로를 두지 않는다. 게이트웨이 서버에 남아 있던 사설 원격 접속망은 2026-10-03에 해제했다.
- 해외 출장 등으로 지정 출발지 밖에서 관리해야 할 때만 사설 원격 접속망을 기간을 정해 켜고, 켠 날과 끈 날을 운영 기록 대장에 방화벽 정책 변경으로 남긴다.
- 월 1회 실제로 열려 있는 포트와 방화벽 정책을 대조해, 정책에 없는 개방과 쓰지 않는 규칙이 없는지 확인한다(운영 기록 대장 · 로그 점검).
- 컨테이너 게시 포트가 방화벽을 우회하는지와 출발지 제한 적용 여부를 같은 점검에서 확인한다.

## 7. 정책 변경과 관리자 접근 이력 (확인사항 ④)

방화벽 정책은 다음 절차로만 바꾼다.

1. 요청: 변경 사유 · 대상 포트 · 허용 출발지를 적는다.
2. 승인: 대표이사가 승인한다.
3. 적용: 인프라 담당이 적용하고 적용 전후 정책을 확인한다.
4. 기록: 관리자 화면 「운영 기록 대장」에 변경 일시 · 대상 시스템 · 변경 내용 · 사유 · 근거를 남기고, 기록자와 다른 관리자가 확인한다(2026-10-03부터). 남긴 기록은 고칠 수 없고 정정은 새 기록으로 남는다.

| 이력 | 남는 곳 |
|---|---|
