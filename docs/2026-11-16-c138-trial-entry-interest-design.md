## 3. 처방

### D1 — 입구 판정 한 함수
- `frontend utils/ai-operator-access.ts` 에 `fetchFeatureEntry(featureId, access?)`(`:71`) 와 `STUDIO_TRIAL_FEATURE_ID`(`:62`)를 둔다. 답 = true(들어간다) · false(잠김) · null(모름 = 잠그지 않는다 · 종전 규약). access = 요금제 답을 이미 받은 호출부(허브)가 넘긴다(다시 묻지 않는다).
  - 요금제 답이 「잠김」이 아니면 그 답 그대로(무료체험을 묻지 않는다).
  - 잠김 + 이미지 스튜디오 = 무료체험 자격이 있고 신청했을 때만 true · 무료체험 답을 모르면 false(종전 PlanGate 와 같은 규약).
- `PlanGate.tsx:22` = 그 함수의 답이 false 일 때만 잠근다(안에 있던 무료체험 갈래 삭제).
- `AiOperatorPage.tsx` = 요금제로 잠긴 회사면 들어올 때 그 함수로 묻고(`:52` · 받은 요금제 답을 넘긴다), 카드마다 `cardLocked`(`:101`)가 자물쇠 표시와 누름을 같이 정한다. 상태 `trialOpen` 은 「열림」이라는 답을 받았을 때만 true 가 되고, 그 밖(답 전 · 못 받음 · 잠김)에는 무료체험 카드를 누를 때 다시 묻는다(`:115`) — 한 번 못 받은 답이 잠금으로 굳지 않는다. 열린 카드에는 「무료체험」 표시.
- 카드 누름은 순번을 쥔다(`:109` `clickSeq`) — 답을 기다리는 동안 화면을 떠났거나 다른 카드를 눌렀으면 그 누름은 안내도 이동도 하지 않는다.
- 같은 화면의 `?intro=기능id`(화면 입구가 돌려보낸 안내)도 그 함수로 묻는다 — 그 기능의 입구가 열린다고 답하면 요금제 안내를 열지 않는다(입구가 무료체험 답을 한 번 못 받아 돌려보낸 뒤 허브에서 다시 물어 열린 경우 · 모름이면 종전대로 안내).
- 서버 무수정(판정 = 서버 /api/ai/operator/access · /api/image-studio/trial 그대로).

### 요청 2 — 장면 창의 숨김 단추
- 서버 보관 글 `backend content/gated/v3-popup.ts` V3_SCENES_HTML 에서 `data-act="dismiss"` 단추 삭제. 창의 글은 서버가 주므로 백엔드 재시작 즉시 모든 브라우저에서 사라진다.
- `components/v3/V3ScenesPromo.tsx` 의 dismiss 처리 · 알림 · 잠금 삭제.
- 그대로 두는 것(내가 정한 것 · §7): 계정당 최대 3번 · 이미 누른 계정의 숨김 기록 · 서버의 숨김 주소. 무료체험 안내 창의 「이 안내 다시 보지 않기」는 처음에는 그대로 뒀다가 Harold 「같이 없앰」으로 같이 뺐다(§13).

### 요청 3 — 기능 관심 업체
- 서버 `utils/v3-intro.ts` INTRO_DISMISSED_SQL · loadIntroDismissals = 「다시 보지 않기」를 누른 계정 전부(회사가 있는 계정 · 최근에 누른 순 · 기간 거르기 없음 · 표 없음 = null).
- 서버 `utils/feature-interest.ts` loadFeatureInterest = 업체 줄에 `seen`(이 기간에 본 기록) · `trial`(무료체험 신청 · 사용) · `dismissed`(어느 창 · 누가 · 언제)를 싣는다. 본 기록이 없어도 무료체험 신청 · 숨김이 있는 회사는 줄이 된다. 줄 순서 = 가장 최근에 일어난 일. 응답 = `companies` · `trialsKnown` · `dismissalsKnown`(못 읽었으면 false) 셋뿐.
  - 삭제(「기능별 관심」 칸과 함께 쓸 곳이 없어진 것): 응답의 `summary`(요약 수) · `features`(기능별 회사 · 요금제 보기 · 바로가기 · 열람 수) · `trials`(C135 의 따로 있던 표용) · 조회 조건 `featureId`. 화면이 받아 둔 업체 줄에서 세므로 서버가 따로 세면 같은 수가 두 벌이 된다(R1).
- 화면 `components/admin/FeatureInterestTab.tsx`:
  - 표 하나(회사 · 요금제 · 본 안내 창과 기능 · 열람 · 요금제 보기 · 바로가기 · 무료체험 · 다시 보지 않기 · 마지막 본 시각 · 본 사람). 옛 「기능별 관심」 칸 · 따로 있던 무료체험 표 · 말줄임 · 말풍선 삭제.
  - 걸러 보기 = 보기(본 회사 · 무료체험 신청 · 다시 보지 않기 · 수 표시) + 기능 단추(회사 수) + 기간 + 회사. 보기 · 기능 · 요약 네 칸 · 기능 단추의 수는 받아 둔 줄에서 계산한다(`utils/feature-interest-view.ts` 순수 함수 visibleInterestRows · featureCounts · groupDismissed · 누를 때마다 다시 읽지 않는다). 기간 · 회사만 서버 조건.
  - 이 탭만 화면 가로를 다 쓴다 = CSS 계산 하나(`xl:w-[calc(100vw - 48px)] xl:ml-[calc(50% - 50vw + 24px)]` · 가운데 정렬된 부모 틀 기준 · 부모 틀 `AdminDashboard.tsx` 무수정 · 1280px 미만은 부모 폭 그대로). 처음에는 화면 폭을 재서 고치는 훅으로 만들었으나 폭 훑기에서 창 크기가 바뀐 뒤 처음 값에 머물러 가로로 넘치는 것을 잡아 CSS 로 바꿨다(§9).
  - 표 칸은 자르지 않는다. 회사명(노트북 180px · 넓은 화면 280px) · 본 기능은 길면 그 칸 안에서 줄을 바꾸고 남는 폭은 본 기능 칸이 받는다. 무료체험 = 두 줄(쓴 수 · 상태 / 신청 시각 · 신청한 사람) · 다시 보지 않기 = 창마다 「이름 · 사람 수」 + 가장 최근에 누른 시각(낱낱의 기록은 상세 창).
  - 못 읽은 것은 「없음 · 0」이라 쓰지 않는다: 서버 답은 받는 자리 한 곳(`normalizeInterest`)에서 꼴을 맞추고(없는 칸 = 모름 · 빈 값 · 배포 중 옛 서버 답도 그려진다), 칸은 「알 수 없음」 · 보기 단추의 수는 「?」 · 그 보기를 고르면 수 · 기능 단추 · 표 대신 「이 목록을 읽지 못했습니다」 하나만 그린다.
- 등록부 `constants/login-popups.ts` 에 창마다 판 열쇠(introKeys)를 적어 숨김 기록을 창 이름으로 보여 준다(서버 판 열쇠 전부가 등록부에 있는지 시험이 본다).

6. 무료체험 신청 · 「다시 보지 않기」는 기간과 무관하게 전부 보인다(지금 상태). 그 줄의 「본 기능 · 열람」은 고른 기간의 값이다.
