## 4 처방 — 뿌리 R87 「방어값이 손 등재(선택 칸)라 등재 안 된 자리에서 빈다」

판정 기준(R87) = 재진입 대기 최솟값은 **모든 시작 사건이 반드시 선언**한다(형 필수 칸 · 0 은 「사건 키로 한 번만 들어오는 시작」만) · 최솟값은 저장 검증뿐 아니라 **실행을 넣는 자리**에서도 걸린다(저장값과 무관) · 실행을 넣는 새 자리는 분류 없이 들어오면 시험이 깨진다.

### 4-1 계약(CT = `journey-trigger-capability.ts`)

1. `cooldownMinDays` = **필수 칸**(선택 표시 `?` 삭제 · 선언 없으면 컴파일 실패).
2. 값 규칙(계약 시험이 기계로 본다):
   - 0 = 한 번만 들어오는 시작만 = 사건 커서 시작(`resolveCdpCursorEventName` 이 이름을 주는 주문 완료 · 첫 구매 · 휴면 복귀 · 상품 구매 · 예약 확인 · 배송 시작) + 앞 여정을 마치면(사건 키) + **고른 고객에게**(대상 뽑기가 재진입 설정과 무관하게 「실행이 하나라도 있으면 뺀다」 · 날짜 기준 · 한 번 보내기도 이 시작 사건).
     ★ 1110 C123-P1 실측 정정 — 처음에는 고른 고객에게를 1 로 뒀다. 템플릿 기본이 재진입 켬 · 0일이라 기존 초안 · 멈춘 여정(운영 실측 4건 · 인비토)의 켜기 · 다시 켜기가 거절됐을 것이다(반복은 원래 없던 시작 사건에 쓸모없는 거절). 반복되는 유일한 길(자동으로 다시 받기)은 자동 최솟값 1일이 건다.
   - 그 밖 = 1 이상. 휴면 전환 = 휴면 창 길이(7일 · 새 상수 `DORMANT_ENTRY_WINDOW_DAYS` · 대상 뽑기의 `기준일 + 7` 이 같은 상수를 쓴다) = 한 번의 휴면 전환에 한 번.
   - 생일 · 포인트 소멸 · 신규 가입 · 방문 전후(미구현 둘) = 1 · 구매 주기 이탈 · 등급 상승 · 장바구니 · 조회 후 미구매 = 1(지금 그대로).
3. 읽는 함수 둘(다른 파일은 이 둘만 부른다):
   - `reentryFloorDays(시작 사건)` = 계약 최솟값(모르는 시작 사건 = 1 · 덜 보내는 쪽).
   - `autoReentryFloorDays(시작 사건)` = `max(1, reentryFloorDays)` — 자동으로 다시 받기는 시각만으로 다시 넣으므로 사건형이어도 0일 = 반복(D3).

### 4-2 실행을 넣는 자리(저장값과 무관한 실행 시점 관문)

4. 새 조각 `reentryHoldSql(실행 별칭, floorDays)`(`journey-safety-filter.ts` · 재진입 허용 여정에서 「이 실행이 있으면 다시 넣지 않는다」):
   - floor 0 = `e.status = 'active'`(지금 그대로).
   - floor ≥ 1 = `(e.status = 'active' OR COALESCE(e.completed_at, e.entered_at) > NOW() − floor일)` = **끝난 뒤** 계약 최솟값 동안은 다시 넣지 않는다(화면 문구 「마친 뒤 N일」과 같은 기준 · 끝난 시각이 없는 실행 = 들어온 시각).
5. `buildReentryAntiJoin` 에 floorDays = **필수 인자**(기본값 없음 · 빠뜨리면 컴파일 실패 · Codex 설계 1R #4 — 기본 0 이면 새 뽑기 갈래가 빠뜨려도 시험이 통과하고 뽑기 수 ≠ 넣기 수로 대량 차단이 잘못 걸린다) — 재진입 허용 두 갈래(대기 0 · 대기 > 0)가 `reentryHoldSql` 을 쓴다(대기 > 0 갈래 = `… OR entered_at > NOW() − 대기일` 그대로 덧붙임). 재진입 불가 갈래 = 그대로.
6. `journeyEntryInputs`(진입 입력 CT) = 여정 행에서 시작 사건을 같이 읽어 `reentry.floorDays = reentryFloorDays(시작 사건)` 을 싣는다 → 대상 뽑기 8 자리 · 세기 · 미리보기 · 켜기 노출 수가 같은 값(R58 같은 입력). 재진입 입력 형의 `floorDays` = 필수 칸(뽑기 함수들이 받는 재진입 인자 형 한 곳 · 손으로 만든 재진입 인자도 빠뜨리면 컴파일 실패).
7. 감시 묶음 넣기 가드(`reentryGuard`) = 따로 쓴 `je.status = 'active'` 를 지우고 `reentryHoldSql('je', floor)` 로(뽑기와 넣기가 같은 집합 · C105 H3 와 같은 규칙).
8. 자동 재진입 워커(후보 문장 = 계보 잠금 안 · LIMIT 앞 그대로):
   - 여정 고르기에 `allow_reentry = true`(「다시 들어오게 하기」가 꺼진 여정은 돌지 않는다).
   - 최솟값 = 아래 공용 조각 한 곳이 건다(후보 실행 자신도 계보 실행이라 끝난 지 최솟값 안이면 빠진다 → 실제 대기 = `max(저장값, autoReentryFloorDays)`) · 0 · 미달 저장값이어도 끝난 뒤 최솟값 전에는 넣지 않는다.
   - **저장값 바인드는 옛 그대로**(시간 비교 `completed_at <= NOW() − 저장값` · 목표 달성 자격 `저장 대기일 > 0`) — 저장 0일 여정에서 구매로 빠진 고객은 지금처럼 자동 재진입 대상이 아니다(보정값을 그 바인드에 넣으면 기존에 빼던 고객을 새로 받는다 = 더 보내는 쪽 · Codex 설계 1R #2). ★ 구현 중 정정 — 설계 2R 의 「시간 비교 새 바인드」는 공용 조각과 같은 일을 두 번 해서 뺐다(변이 확인에서 그 바인드를 저장값으로 되돌려도 시험이 초록 = 중복 · 장치 하나).
   - 「진행 중 실행 없음」 조건 = `reentryHoldSql('je2', autoReentryFloorDays)` 로(계보 전체 실행 · 상태 무관) — 오래된 완료 이력이 있어도 **가장 최근 실행이 끝난(ended · paused · failed 포함) 지 최솟값 안**이면 넣지 않는다(옛: 완료 · 목표 달성 이력과 진행 중만 봐서 방금 「이 발송 정지」로 끝낸 고객을 다시 넣었다 · Codex 설계 1R #1).
9. 사건 커서 넣기 · 앞 여정을 마치면 · 날짜 기준 · 한 번 보내기 = 그대로(floor 0 또는 표식 표 멱등 · §2 F8 · F10 · F11 의 근거).

### 4-3 저장 · 켜기 · 만들기

10. `validateJourneyEntryConfig`:
    - 재진입 허용 + 대기 < `reentryFloorDays` = 거절(지금 문장 그대로 「이 발송 조건은 같은 분께 다시 보내기까지 최소 N일이 필요합니다. 재진입 간격을 지정해 주세요.」) — 계약이 필수라 **모든** 시작 사건에 걸린다.
    - 자동으로 다시 받기 켬 + 재진입 허용 + 대기 < `autoReentryFloorDays` = 거절(「자동으로 다시 받기는 마친 뒤 최소 N일이 지나야 해요. 대기 일수를 N일 이상으로 정해 주세요.」).
    - 입력 행에 `auto_reentry_enabled` 를 더한다(켜기 = 여정 행 · 옵션 저장 = 병합값).
    - **옵션 저장에서 이 두 검사는 「이번 요청이 재진입 값을 정할 때」만 건다** = 요청에 `allowReentry: true` · `reentryCooldownDays` · `autoReentryEnabled: true` 중 하나가 있을 때(입력 행 `reentry_touched`). 끄기만 하는 요청(`autoReentryEnabled: false` · `allowReentry: false`)과 재진입과 무관한 옵션 저장은 저장된 미달 값 때문에 거절되지 않는다(옛 설계안 = 병합값으로 늘 검사 → 미달 여정에서 자동 재진입 끄기 · 요금제 만료 뒤 끄기 전용 길 `journeyOptionsOffOnly` 까지 막혔다 · Codex 설계 1R #3). 실행 시점 관문(4 ~ 8)은 저장값과 무관하게 걸리므로 미달 값이 남아 있어도 반복은 없다. 켜기(F5)는 늘 검사한다(켜는 쪽).
11. 옵션 저장: 요청이 `allowReentry = false` 면 `auto_reentry_enabled = false` 도 같이 쓴다(화면은 재진입을 끄면 자동 스위치를 숨긴다 · 숨은 스위치가 켜진 채 남지 않게 · 워커 조건 8과 두 겹).
12. 만들기(`createJourneyFromTemplate`): 재진입 허용이면 대기일 = `max(준 값, reentryFloorDays)` — AI · 템플릿이 만든 초안이 켜기에서 막히지 않게(계약이 정한다 · AI 출력에 맡기지 않는다 · 사람이 화면에서 넣은 값은 올리지 않고 거절 = 10).
13. 여정 상세 응답에 `reentryMinDays` · `autoReentryMinDays` 를 싣는다(화면이 최솟값을 그린다 · 계약 표를 화면에 복사하지 않는다).

### 4-4 화면(`JourneyStartCard.tsx`)

14. 「마친 뒤 [N]일 지나면」 min = 상세가 준 최솟값(자동 켬 = 자동 최솟값) · 비우면 최솟값 · 최솟값 ≥ 1 이면 칸 옆에 「최소 N일」.
15. 「다시 들어오게 하기」 · 「자동으로 다시 받기」를 켤 때 대기일이 최솟값보다 작으면 최솟값으로 올려 보인다(저장 전 화면 값 · 저장은 사람이 누른다).
16. 「자동으로 다시 받기」 설명 「6시간마다」 → 「1시간마다」(워커 주기 사실 = `journey-reentry-worker.ts:47` · 같은 줄이라 같이).

### 4-5 이미 저장된 미달 여정

- 켜진 여정 = 실행 관문(4 ~ 8)이 저장값과 무관하게 최솟값을 건다(덜 보내는 쪽 · 배포 즉시).
- 그 여정의 재진입 값을 다시 정하는 저장(대기일 · 재진입 켜기 · 자동 켜기) · 멈춘 뒤 다시 켜기 = 10이 거절하며 최솟값을 알린다(값을 조용히 바꾸지 않는다) · 끄기 · 재진입과 무관한 옵션 저장 = 그대로 저장.
- 배포 전 실측(§8)으로 미달 여정 목록을 본다(1110 = 시연 회사 1건).
