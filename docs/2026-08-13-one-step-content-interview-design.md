## §1 정체성 — 무엇을 만드는가

**마케터는 질문에 답하고, 마스터프롬프트는 시스템이 조립한다.**
마스터프롬프트의 실체는 자연어 한 덩어리가 아니라 세 갈래다:

| 갈래 | 담는 것 | 생성기 결합 지점 |
|---|---|---|
| **사실 원문(eventText)** | 사용자가 **직접 타이핑·확인한** 사실만 — 행사명·기간·혜택(verbatim)·상품명·유의사항 | `oneShotGenerate({eventText})` → EventBrief → 출구 가드 |
| **결정 파라미터(decisions)** | 후킹 방식·긴급성·증거 블록·큐레이션 수·이미지 소스·매장 노출 — **AI 산출을 덮는 결정값** | 신설 `structure` 1급 파라미터(§4-2) — 섹션 체인을 결정적으로 고정 |
| **톤(주입)** | 브랜드 보이스·성과 문안 few-shot·업종 공식 | `composeCopyBrain` 기존 축 그대로 — **인터뷰는 묻지 않는다** |

1클릭 UX 원칙과의 관계: 전 문항에 프리필·파생 기본값이 있어 **[이대로 만들기] 한 번으로 완주 가능**하다.
질문은 "원하는 사람만 더 정확하게"의 경로다. 기존 자연어·빠른 시작 진입은 손대지 않는다.

### 2-2. 직원 시안이 준 것 (2026-08-13 dm_pages 18건 149섹션 실측)

구성 공식 4종과 "사람이 내린 결정 7축"이 질문표의 근거다. 시안 자체는 **참조 자산**:

### 2-3. 구성 공식 — 새 표를 만들지 않는다

## §3 화면 설계 (프론트·디자이너 수렴)

- **셸**: 아코디언 스텝. `CdpIntegrationStepper`는 props·완료판정 전제가 CDP 전용이라 **재사용이 아니라 사본**이 맞다(회의론자 판정) — 시각 규약(펼친 단계 하나·done/active 뱃지·`aria-current`)만 가져오고 라벨·안내 문구는 사용자 노출 검수를 다시 통과시킨다. **미래 문항은 잠그지 않는다** — 접힌 채 답 요약 한 줄 노출(프리필 6개가 "이미 채워짐"으로 읽히게).
- **진행 표시**: 도트·"3/7" 금지. **"확인할 것 N개"**(실입력 필요 축만) + 비율 바(`JourneyDataScopeNote` 2칩 형식).
- **프리필 표시**: 실값 + 출처 칩("연동몰에서 가져왔어요") + [수정]. 못 채운 것은 amber 문장으로 실토(항목별 정직 — `AiPromptModal`의 brief/missing 2블록 형식). 수정 후 재계산 금지.
- **[이대로 만들기] 상시** + 하단 스텝별 [지금 생성] 버튼 금지(스텝마다 차감 — 백엔드 판정). 생성은 최종 1회.
- **결과 화면**: 실제 미리보기(합성 값 금지) + 반영 검산 칩(coverage) + **안 채운 결정축 인라인 채움**(칩을 누르면 그 자리에서 라벨+desc 2줄 선택지가 펼쳐진다 — 화면 전환 없음) + Source caption("귀사 브랜드 톤 + 최근 발송 성과 기준") + 1-click 3카드([발송 준비]/[문안만 다듬기]/[질문 2개만 다시]).
- **감성**: 상단 헤더에 "받아적은 답 요약"(상담 노트) · eyebrow 타이포 · 흰 버튼은 최종 확정 1곳.
- **금지·의무**: 백드롭 클릭 닫힘 금지(모달이면 닫힘 차단 축) · z 티어(내부 픽커·크레딧 모달 z-[2000]와 충돌하지 않게 셸은 아래 티어) · 조기 return 뒤 훅 금지 · 모바일 반응형 · 모델명 0 · native dialog 0.
- **중도 이탈**: DB 초안 + 재개 바. 저장 축은 §6-1에서 확정(회의론자 E — `event_campaign_drafts` 재사용 시 기존 재개 바가 인터뷰 행을 3채널 모달로 열어버리는 결함 → 재사용하려면 조회 제외 조건을 같은 커밋에, 아니면 별도 축).

### 4-2. 생성기 결합 — §0 판정 A·B를 닫는 유일 경로

`oneShotGenerate`에 `structure?: { sectionTypes: SectionType[]; scenarioKey?: string; decisions: InterviewDecisions }`를 신설한다.
- `structure`가 오면: `parsePrompt` 미호출(spec은 결정적 기본값 조립) · `designSectionLayout` 미호출 · 섹션 체인 = `normalizeSectionChain(structure.sectionTypes)`.
- 계약 테스트의 단정 대상은 **정규화 이후** 최종 체인이다(§0 판정 D).
- 프리필 상품은 eventText가 아니라 `structure.decisions.products`로 — 몰 매칭이 이미 검증한 실데이터라 원문 자격이 필요 없다(§0-6).
- eventText에는 **사용자가 타이핑·명시 확인한 값만** 직렬화한다(라벨 집합은 EventBrief 필드와 1:1 — 매장·유의사항·링크 포함).

### 4-3. 파생 기본값 (1클릭 완주의 실체)

긴급성 = `period_end` 실존 시에만 / 큐레이션 = 선택 상품 수 / 매장 = brandKit 주소 실존 / 이미지 = 몰 정확 매칭 성공 / 증거 = **기본 OFF**(파생 불가 — 안 물었으면 안 넣는다).
전부 축소 방향 파생이라 "예측 타겟 선정 금지"·"0건 자동완화 금지"와 부딪히지 않는다(회의론자 판정 2).

### 4-4. 요금 (§0-7)

- 차감 = 채널 생성 키(`one-step-gen:{sessionId}:dm` — dm-ai-generate 5) + **오토설계 대행 델타 `one-step-interview` = 50**(멱등키 `one-step:{sessionId}` · 세션당 1회 · ★2026-08-13 Harold 확정).
  - **50의 근거는 임의 숫자가 아니다** — `email-campaign-complete: 50`(설계·완성 대행)과 같은 부류·같은 값이다. 고객 설명도 "완성 대행급"으로 선다.
  - 총액 = 생성 5 + 델타 50 = **55**(발행 100은 발행 시점 별도) → 직접 생성 세트 105 대비 **약 1.5배**. 2배(정액 210)는 §0-7로 기각됐다.
  - **원가는 오르지 않는다.** 인터뷰·프리필·견적은 AI 호출 0이고, 생성 단계에서도 결정 파라미터가 `parsePrompt`·`designSectionLayout` 두 호출을 대체해 **기존 경로보다 호출이 준다**(§4-2). 델타의 근거는 원가가 아니라 **대행 가치**다(플래너 요금 철학의 대행 축 — 제작물=원가 연동 / 대행=가치 연동).
  - **재생성은 델타를 다시 걷지 않는다** — 세션 멱등 1회라 재생성 시 생성비 5만 나간다("대행비를 냈는데 또 낸다"가 원천적으로 없다).
  - **인상은 계측 뒤에** — §4-5 대조군으로 "인터뷰 결과물이 측정 가능하게 낫다"가 나온 뒤 100 검토(그 전에 올리면 증거 없이 가격이 앞선다).
- 발행은 기존 `dm-publish:{dmId}` 그대로(이중과금 0 — 플래너 §3-10 규약).
- **견적 = 서버 순수 함수 하나**가 표시·실차감을 같이 소유(정적 상수 맵으로는 "표시 ≠ 차감" 재현 — 회의론자 판정 3). 20크레딧+ 모달은 그 견적을 표시. 재생성 시 채널 생성비 재차감을 화면에 사전 고지.
- 인터뷰·프리필·견적은 AI 호출 0 = 무과금.

### 4-5. 계측 (프리미엄의 사후 증명)

## §9 적대 검토 정정 (★2026-08-14 · 배포 전)

**뿌리 하나** — 세션은 "돈을 낸 단위"인데, 그 단위를 만드는 화면과 지키는 서버가 서로 다른 가정을 하고 있었다.
서버는 세션이 오래 살며 재사용된다고 보고 멱등키·표식·회차·이어하기를 전부 만들었고, **화면은 세션을 1회용으로 썼다.**
그래서 서버의 과금 안전장치 전체가 실효 0이었다. 증상 셋을 개별로 때우지 않고 그 가정 불일치를 닫았다.

| # | 결함 | 정정 |
|---|---|---|
| 1 | **못 걷은 대행비가 결제로 굳었다** — `deductCreditSafe`는 잔액 부족·영구 실패에 **예외를 던지지 않고 `false`를 돌려주는데**, 반환값을 버리고 `interview_paid_at`을 무조건 새겼다. 표식이 곧 "냈다" 판정이라 그 세션은 영구 무과금이 되고 흔적은 stdout 한 줄뿐 | 걷지 못한 source를 모아 **순수 함수 `shouldMarkInterviewPaid`(요금 CT 소유)** 로 판정 — 실제로 걷혔을 때만 표식. 못 걷으면 표식을 안 남겨 다음 생성이 **같은 멱등키로 재시도**한다(중복은 키가 막는다) |
| 2 | **이어하기가 배선돼 있지 않았다** — 모달이 열릴 때마다 `POST /sessions`로 새 세션을 만들고 `GET /sessions/:id`는 소비처 0건. 세션 고정 멱등키가 매번 새로 생겨 **실수로 닫았다 다시 연 사람에게 대행비 50이 또 나갔다.** 모달 주석("닫아도 이어할 수 있다")과 동작이 반대였다 | 세션 열기가 **진행 중인 본인 `draft`를 먼저 돌려준다**(창 30일 = `event_campaign_drafts` 재개 규약 복제 — 지난달 답이 이번 행사에 실리지 않게). 화면은 응답의 `answers`를 그대로 싣고 이어받았음을 알린다 |
| 3 | **소유 격리 누락** — 설계 §6-1이 "전 엔드포인트 owner-scope"를 선언했으나 실제는 회사 조건뿐이라, 같은 회사 **다른 담당자의 세션**이 조회·수정·생성(회사 크레딧 소모)됐다. 형제 기능 DM은 `dm_pages ... AND created_by`로 이미 격리 중 | 5경로(조회·답 저장·회차 선점·표식·계측) 전부에 소유 조건. 판정은 `owner-scope` CT — 라우트에 재정의 0 |
| 4 | **생성 후 답 수정 차단** — PATCH가 `status='draft'`만 허용해, 응답이 유실돼 모달이 열린 채 남은 경우 한 항목만 고치려 해도 404. 새 세션으로 밀려 **대행비를 또 낸다** | `draft`·`generated` 둘 다 허용하고, 고치면 결과가 낡으므로 `draft`로 되돌린다 |
| 5 | 응답 `charged`가 견적을 그대로 반환해 **못 걷은 항목도 "청구됨"**으로 보였다 | 실제로 걷힌 항목만으로 재구성 |

**요금 해석 확정** — "재생성은 델타를 다시 걷지 않는다"(§4-4)는 **한 인터뷰 안에서**의 규약이다.
생성이 끝난 뒤 **인터뷰를 다시 여는 것은 새 대행 건**이라 50이 정상 과금이고, 만든 DM의 문안을 다시 뽑는 것은 편집기의 생성 경로(5)가 받는다.

### 9-1. Codex 적대 검토 1R 뒤 재정리 (★2026-08-14 · high 4 → 뿌리 둘)

1R 판정 = `needs-attention` · critical 0 · **high 4**. 넷을 항목별로 때우지 않고 뿌리 둘로 묶어 다시 고쳤다.

**뿌리 A — 과금 진실의 사본을 만들었다.** 위 표 1번의 정정은 표식을 *더 정확히 찍는* 쪽이었지 사본을 없애지는 않았다.
그래서 1R이 남은 대가를 짚었다: 차감은 성공했는데 **표식 UPDATE만 실패하면**, 다음 요청이 이미 쓴 멱등키인데도 50을 견적에 넣고
`checkCredit`이 55를 요구한다 — 중복 차감은 원장이 막지만 **사용자는 부당하게 402로 막힌다.**
⇒ **표식을 쓰지 않는다.** 이미 냈는지는 매번 원장에 묻는다(`isChargedByKey` — `ai_credit_transactions.idempotency_key` 조회, 크레딧 CT 소유).
그 결과 표식 UPDATE·`shouldMarkInterviewPaid`·표식 실패 분기가 **함께 삭제**됐다(구조를 고치면 덧댄 장치가 사라져야 정상).
조회 실패는 **미차감으로 답한다**(fail-closed — 다시 걷으러 가도 같은 키라 원장이 막지만, 냈다고 답하면 못 걷은 채 넘어간다).

**뿌리 B — 생성이 상태를 선점하지 않았다.** 회차만 올려서 동시 요청 둘이 각자 AI를 부르고 각자 과금했고,
생성 중 답이 바뀌면 옛 답으로 만든 결과가 새 답 세션을 `generated`로 덮었다.
⇒ 선점이 `status`를 **`generating`으로 원자 전이**하고 `status IN ('draft','generated')`일 때만 성공한다.
**이 전이 하나가 셋을 닫는다** — 동시 생성(둘째는 0행 → 409) · 생성 중 답 수정(PATCH 허용 상태에 `generating`이 없다) · 완료 덮어쓰기.
끊긴 선점은 **10분 lease**로 회수하고(플래너 승인 선점과 같은 값), 실패 경로에서 `draft`로 되돌린다. 이어받기도 lease 지난 `generating`을 집어 준다.

**1R high 3(30일 재개가 캠페인 정체성을 구분하지 않는다)** ⇒ **명시적 새 세션 경로**로 닫았다(`fresh` 플래그 + 화면 [새로 시작]).
지문 대조는 호출부가 `event`를 보내지 않아 죽은 코드가 되므로 넣지 않았다 — **시간 창은 같은 행사임을 증명하지 못하니 사용자가 고른다.**

**1R high 1의 처방(차감 실패 시 결과 제공 보류)은 불수용.** 이 저장소의 전사 정책이 반대다 —
`deductCreditSafe` 영구 실패는 `[CREDIT][MISS]` + 수동 재차감이고 **효과물 회수는 금지**다(이미지 스튜디오가 같은 형태로 운영 중).
한 라우트만 다르게 굴면 그게 결함이다. 다만 1R이 짚은 사실은 맞으므로(생성비 키는 회차 고정이라 자동 재시도가 없다)
**걷지 못한 항목을 키·세션·회차와 함께 남긴다** — 수동 재차감이 정책이면 대상을 특정할 수 있어야 그 정책이 집행된다.

### 9-2. 자체 2R — 선점 토큰 (★2026-08-14 · Codex 2R를 못 얻어 내가 대신 본 것)

Codex 2R은 도구가 판정 전에 죽어 결과를 못 얻었다(런북 §3 3조건으로 확정, 4회 시도 중 1회만 완료).
그래서 2R에 물으려던 네 축을 내가 직접 봤고 **구멍 둘**을 찾았다 — 둘 다 뿌리 하나다: **선점이 돌려준 회차를 이후 쓰기에 안 걸었다.**

lease(10분)가 있는 한 "내가 잡은 그 선점인가"를 확인하지 않는 쓰기는 남의 것을 건드린다.
- **완료 UPDATE** — 우리 생성이 늦어 다른 요청이 정당하게 재선점하면, 우리 완료가 그 위에 `generated`를 덮어 **살아 있는 선점이 풀린다**(셋째가 또 잡아 동시 실행 = 이중 과금). 덤으로 옛 답 기준 `decisions`·`section_types`가 저장된다.
- **catch의 선점 해제** — 같은 이유로 **남의 선점을 푼다.**

⇒ 두 쓰기 모두 `AND attempt = <선점이 돌려준 회차>`. 재선점이 있었으면 0행이 되어 아무것도 건드리지 않는다.
이것이 Codex 1R H2 권고의 나머지 절반("완료 UPDATE는 같은 선점 토큰일 때만 성공하게 하라")인데, 내가 선점에만 적용하고 완료·해제에 빠뜨렸던 것이다.

### 9-3. Codex 적대 검토 13라운드 — 종결 (★2026-08-14 · `approve` SHIP)

**수용 20 · 불수용 2 · 명시적 위험 수용 1.** 라운드가 길어진 이유는 **정정이 새 결함을 만든 경우가 셋** 있었기 때문이고, 그 셋을 전부 Codex가 잡았다.

**명시적 위험 수용 1건** — 차감 **한 건**이 10분(lease)을 넘는 경우. 그건 회사 크레딧 행이 10분간 잠긴 계통 장애이고, 완전 차단은 커넥션 점유 잠금이 필요해 **백엔드 전체 정지**와 맞바꾸게 된다(R5 실증). 근거는 라우트 주석이 소유한다.

**내 테스트의 구멍 3건**(주입 검증이 없었으면 몰랐을 것) — ①잠금 경합 검사가 획득만 보고 차단을 안 봄 ②원장 확인 검사가 변수명만 봄 ③**순서 단정 3건이 `-1 < 양수`로 공허 통과**(`await oneShotGenerate(`가 실제 코드에 없는 문자열이었다). 이후 이 파일의 순서·구조 단정은 정규식으로 쓴다.

**검증** — BE tsc 0 · FE tsc 0 · vitest **159파일 2,456건**(계약 21건 신설). 정정마다 옛 결함을 주입해 **테스트가 실제로 깨지는 것을 확인한 뒤 원복**했다. `deductCreditSafe` 리팩터는 본문을 옮기고 불리언을 래퍼로 남겨 **다른 소비처 동작 무변경**(전량 통과가 그 근거). **DDL 0.**
