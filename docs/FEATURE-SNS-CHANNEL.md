## §0 30초 요약

## §1 정체성

- **발송이 아니라 게시다.** 문자·알림톡은 받는 사람 목록이 있고 건당 과금이 있지만, SNS 는 대상이 없고 채널 계정 하나에 글이 올라간다. 그래서 수신자·스팸·발신번호 축이 통째로 없다.
- **한 번 쓰면 갈라진다.** `sns_posts` 1행 : `sns_post_targets` N행. **상태 머신의 주인은 target 이고** post 상태는 자식 집계 파생이다. "인스타는 올라갔는데 Threads 는 실패"가 정상 결과다.
- **우리 원장과 플랫폼, 진실이 두 곳이다.** 그래서 대조 워커가 처음부터 함께 있다(6원칙 ③).

## §2 불변 원칙 (어길 수 없는 것)

전량은 설계서 §2(20개)가 소유한다. **코드를 고치기 전 반드시 보는 8개**만 여기 둔다.

1. **저장 ≠ 연결.** 토큰을 저장하면 `pending` 이다. 플랫폼에 계정을 **다시 물어** 자격이 확인된 뒤에만 `active` 다. `pending`·`ineligible` 에 초록 0.
2. **전 조회에 `company_id` 조건을 직접 부여한다.** `(platform, external_account_id)` 만으로 회사를 정하는 함수를 만들지 않는다. 공개 콜백(deauthorize)은 회사별 후보를 전부 꺼내 각각 처리한다.
3. **성공은 플랫폼 재조회로만.** API 200 은 `submitted` 까지다. `published` ⇔ `verified_at` 있음. 화면 초록도 그 뒤에만.
4. **target 상태값 7개 고정**(`draft` `scheduled` `claimed` `submitted` `published` `failed` `cancelled`). `stage` 는 **기록 전용**이며 어떤 분기도 읽지 않는다. **`failed → scheduled` 전이 없다**(재시도 = 새 행).
5. **이중 게시 0 = 3겹.** `UNIQUE(company_id, idempotency_key)` + `FOR UPDATE SKIP LOCKED`·`lock_token` + **게시 호출 직전 소유권 재확인**. 메모리 잠금 금지.
6. ⛔ **원본을 멋대로 자르지 않는다**(Harold 확정 2026-09-21) — §5 가 전문을 소유한다.
7. ⛔ **고객 문안을 말없이 바꾸지 않는다.** 채널 상한을 넘어도 **자르지 않고** 넘었다는 사실만 돌려준다. 게시를 막는 것은 호출부다.
8. **AI 는 태그 생성기가 아니라 선택기다.** 회사 고정 세트의 부분집합만 서버가 통과시킨다. 캡션은 다듬기만 하며 URL·금액은 토큰 치환 후 복원하고(**토큰을 잃은 후보는 폐기**) 출구에서 `stripUnauthorizedBenefits` 를 지난다.

## §5 ⛔ 규격 맞춤 — 원본을 멋대로 자르지 않는다 (Harold 확정 2026-09-21)

`utils/sns-media-fit.ts` 가 값으로 소유하고 **계약 테스트 6건이 잠근다.**

1. **허용 비율 안이면 아무것도 하지 않는다.** 손대는 것이 예외다. 폭 상한도 안 넘으면 픽셀 그대로 나간다.
2. **경계에 0.5% 오차를 둔다.** `1200x628` 은 1.9108 로 인스타 상한(1.91)을 0.04% 넘는데, 그걸로 여백을 붙이는 것이야말로 "멋대로"다.
3. **범위 밖이어도 자르지 않는다.** **가장 가까운 경계**로 pad 한다 — 3:4(0.75) 포스터는 1:1 이 아니라 4:5(0.8) 로 가서 여백이 최소다.
4. **`crop` 은 기본이 될 수 없다.** 사용자가 그 채널에 대해 명시적으로 고를 때만. 워커는 `mode:'pad'` 고정이다.
5. **여백을 무엇으로 채우는지는 `image-serve.ts fitToCanvas` 가 사진을 보고 고른다**(단색 배경이면 가장자리 색 · 복잡하면 블러 · 0908 비교 캡처로 확정). ⛔ SNS 에서 다시 짜지 않는다 — 같은 사진이 화면마다 달라진다.
6. **화면 문구에 "잘린다"가 나오지 않는다.** 잘리지 않으므로. 소스 스캔 테스트가 강제한다.
7. 게시본은 **별도 파일**이다(원본 불변 · `.opt` 캐시 미사용). **구운 파일을 다시 읽어** JPEG 가 아니면 게시를 시작하지 않는다.

사진을 올리는 즉시 화면이 채널마다 결과를 말한다 — "고른 채널 모두 사진을 그대로 올립니다" 또는 "Threads 는 규격이 달라 여백을 채워 올립니다. 사진은 잘리지 않아요."

## §6 운영

**ENV**(`packages/backend/.env`)

| 키 | 값 | 비고 |
|---|---|---|
| `SNS_COMPANY_IDS` | 회사 id 목록 · `*` = 전 회사 | **비면 기능이 닫힌다**(워커도 안 뜬다). 되돌리기 = 비우고 재시작 |
| `INSTAGRAM_CLIENT_ID/SECRET/REDIRECT_URI` | Meta 앱 Instagram 유스케이스 | 콜백 = `/api/sns/auth/callback/instagram` |
| `THREADS_CLIENT_ID/SECRET/REDIRECT_URI` | **인스타와 별개 값** | 콜백 = `/api/sns/auth/callback/threads` |
| `SNS_MEDIA_PATH` · `SNS_RENDER_PATH` | 원본·게시본 보관 | 생략 시 `./uploads/sns-media`·`./uploads/sns-render` |

**게이트 순서** = 인증 → `requirePlanFeature('sns_publish')`(FREE 만 차단) → ENV. ⛔ 뒤집으면 ENV 에 든 FREE 회사가 뚫린다.

**Meta 콘솔 설정** — Threads 는 콜백 **3칸이 전부 필수**이고, 리디렉션 칸은 **입력 후 제안을 클릭해 칩으로** 만들어야 저장된다(설계서 §1-5). 테스터 역할 + **초대 수락**이 OAuth 선행 조건이다(인스타·Threads 각각).
