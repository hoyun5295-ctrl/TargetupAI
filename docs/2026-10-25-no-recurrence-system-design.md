# 결함이 다시 안 나오게 하는 장치 · 설계안 (2026-10-25)

> **원래 안건(Harold 1025):** 「불과 이틀전에 구조체크해서 결함을 전부 수정했는데 할때마다 나오면 어쩌라는거야?」 → 「완벽하게 해결 할 수 있는 방법을 찾아와 다신 결함이 안나오게」
> 상태 = 설계안 제시 · Harold 동의 대기 · 코드 0.
> 관련 = [뿌리 대장](ROOT-LEDGER.md) · [여정 구조체크 2차](2026-10-25-journey-structure-check-2-design.md)

## §1 근거 = 무엇이 재발을 막았고 무엇이 못 막았나

1024 에 뿌리 대장을 만들면서 일부 뿌리만 **전 기능 기계 시험**이 됐고, 나머지는 점검표(사람이 기억해서 보는 것)로 남았다.

| 뿌리 | 1024 이후 지키는 방식 | 1025 여정 2차에서 나온 수 |
|---|---|---|
| R2 요금제 문 · R4 차감 순서 · R7 스팸 판정 · R9 한 줄 길 · R10 오류 원문 · R13 효능 거름 | 전 기능 기계 시험(소스에서 대상을 뽑음) | **0** |
| R1 같은 사실 두 벌 | 점검표 | 3 |
| R5 본 것 ≠ 나가는 것 | 기계 시험 = 자동 마케팅 · 플래너만 | 2 |
| R6 닫히지 않는 상태 · R8 상한 없는 재시도 | 기계 시험 = 플래너만 | 2 |
| R12 잠금 · LIMIT 뒤 거름 | 점검표만 | 1 |
| R3 사용자 범위 | 기계 시험 = 주소 · 목록만 | 1 |
| R11 화면 하한 | 기계 시험 = 출처 · native dialog · 모델명만(내부 표 이름 없음) | 1 |
| (대장에 없음) 죽은 주소 · DB 날짜를 시각으로 읽음 | 없음 | 2 |

→ **12건 전부 기계 시험이 덮지 않은 칸에서 나왔다. 덮은 칸에서는 0건.** 같은 부류의 반복 = 죽은 주소 4번(1023 여정 · 1024 자동 마케팅 · 1024 세 채널 · 1025 여정) · 사용자 범위 4번 · 같은 사실 두 벌 매번 · DB 날짜 3번(0726 발송통계 · 1020 마지막 날 · 1025 날짜축).

두 번째 원인 = 점검의 범위가 기록되지 않았다. 1차 「결함 0」은 「찾은 17건을 닫음」이었는데 안 읽은 파일이 표에 없어 「여정 전체 0」처럼 보였다. 2차 12건 중 10건이 1차 때 손대지 않은 5~7월 코드다.

## §2 약속하는 것 · 못 하는 것 (정직 표기)

- **약속 1** = 한 번 찾은 부류는 어느 기능에서도 다시 나가지 못한다(시험이 push 를 막는다).
- **약속 2** = 점검이 안 본 자리는 숨지 않는다(덮음표에 빈칸으로 보인다 · 빈칸이 있으면 「결함 0」이라고 쓰지 않는다).
- **약속 3** = 코드를 읽어서 못 잡은 것도 실데이터에 나타나면 하루 안에 경보가 온다.
- **기준** = 결함 0(유료 서비스 · Harold 1025). 「결함 0」은 덮음표 빈칸 0 + 기계 시험 통과일 때만 쓴다. 새 부류가 나오면 그날 전 기능에서 닫고 새 뿌리 + 기계 시험으로 막는다.

## §3 장치 네 층

### 층 1 · 뿌리마다 전 기능 기계 시험 (점검표 → 시험)

| 뿌리 | 시험(대상은 소스에서 기계로 뽑는다 · 손 등재 표 금지) | 첫 실행 예상 |
|---|---|---|
| R1 쓰기 주인 | 표 · 상태 칸마다 INSERT · UPDATE 하는 파일을 구문 트리로 뽑아 「주인 CT」 표와 대조 · 주인 밖 쓰기 = 실패(예: `journey_executions` 넣기 3곳 · 끝내기 ≠ 멈추기) | 측정 후 보고 |
| R5 지문 | 검사 · 미리보기 · 승인 · 재검사에 넘기는 글이 발송과 같은 CT(렌더 · 판 목록 · 지문)를 지나는가(R13 과 같은 구문 트리 방식) · 전 발송 기능 | 측정 후 보고 |
| R6 상태 등록부 | 코드가 쓰는 상태 값을 표마다 기계로 뽑아 「끝 / 진행 + 닫는 자리」 분류표와 대조 · 새 값 · 닫는 자리 없는 진행 값 = 실패 | 측정 후 보고 |
| R8 워커 등록부 | 주기 작업(setInterval · cron) 전수 · 실패를 다음 회차로 남기는 갈래마다 상한 상수 참조 · 없으면 실패(면제 = 이유) | 측정 후 보고 |
| R12 LIMIT 뒤 거름 | 같은 함수 안에서 LIMIT 있는 조회 결과를 JS 로 거르면 실패(면제 = 이유) · 잠금은 점검표 유지 | 측정 후 보고 |
| R3 범위 | 주인을 선언한 기능의 주소 · 추천 · 요청 키 · 집계 함수가 보는 사람 인자를 받는가 | 측정 후 보고 |
| R11 화면 하한 | + 화면 글에 내부 표 이름(DB 스냅샷의 표 이름) 0 | 측정 후 보고 |
| **R15 죽은 주소(새)** | 라우터 주소마다 화면 · SDK · 문자/메일 링크 소비처가 있거나 면제(외부 콜백 등 · 이유) | **측정 = 968 주소 중 소비처 확실 740 · 애매 185 · 안 보임 43**(경로 조각 대조 · 분류 전 · 외부 콜백 포함) |
| **R16 DB 날짜(새)** | DB 스냅샷의 date 칸을 `::text` 없이 읽어 날짜 계산에 넣는 자리 0 · 날짜 함수 입력 타입 = 글자 | 측정 후 보고 |
| **DB 스냅샷(새 기반)** | information_schema 를 저장소에 JSON 으로(Harold 조회 1회 · DDL 마다 갱신) → SQL 문자열의 표 · 칸이 실제로 있는가(「tsc 통과 ≠ SQL 유효」 운영 다운 뿌리) · R11 · R16 의 근거 | 측정 후 보고 |

- 시험마다 **변이 검사**(일부러 결함을 되살려 시험이 실패하는지) · 안 불리는 검사 = 없는 것보다 나쁘다.
- 첫 실행이 다른 기능의 기존 위반을 잡는다 → 그것이 이 장치가 일하는 증거다. 기능별 묶음으로 닫는다(면제를 늘려 통과시키는 것은 수정이 아니다 · CLAUDE.md root_ledger 2).

### 층 2 · 운영 불변식 감시 (실데이터 · 매일)

- 기능마다 「절대 생기면 안 되는 상태」를 읽기 전용 SQL 로 매일 센다 → 0 이 아니면 공용 경보 입구(`scripts/ops-alert.sh` · R14)로 문자 + 메일. 숫자만 보낸다(고객 정보 0).
- 여정 예 = 끝난 여정의 진행 중 실행 · 오류 3회 넘게 도는 실행 · 날짜축 발송일 ≠ 기준일 − N · 2시간 넘게 재검사 못 받은 판 · 상한을 넘은 하루 진입. 공통 예 = 차감했는데 발송 0 · 1시간 넘게 남은 「적재 중」 표식 · 끝난 캠페인의 대기 큐.
- 코드 읽기가 못 본 결함도 실데이터에 나타나는 순간 잡힌다(고객이 먼저 알기 전에).

### 층 3 · 구조체크 = 기계가 만드는 덮음표

- 스크립트가 기능의 파일 목록(주소 · 워커에서 따라간 import 그래프)을 뽑고 × 뿌리 목록(R1~R16) 표를 만든다.
- 칸마다 증거 = 시험 이름 또는 읽은 줄(파일:줄). 빈칸이 하나라도 있으면 보고 = 「덮음 N% · 미검증 M칸」 · 「결함 0」 금지.
- 기능마다 한 번 = 안 건드린 옛 파일까지 전부 읽는다(바뀐 줄만 보는 검토가 남긴 빚 · 여정 = 2차 §5 부터).

### 층 4 · 쓰는 순간 막기

- 층 1 시험은 pre-push 전체 시험에 들어가므로 새 위반은 push 전에 막힌다(지금 장치 그대로).
- Codex 요청문 ④ = 그 기능 덮음표 · 빈칸을 같이 보낸다.

## §4 순서

1. **여정**: 2차 §5 남은 범위를 덮음표로 다 읽기 → 12건 + 새로 나온 것 닫기 → 층 1 시험을 여정부터 켜기(R1 · R5 · R6 · R8 · R12 · R15 · R16).
2. **층 1 전 기능**: DB 스냅샷 조회 1회(Harold) → 시험 켜기 → 첫 실행이 잡은 기존 위반을 기능별 묶음으로 닫기(죽은 주소 분류부터).
3. **층 2 감시**: 여정 · 발송 · 돈 불변식부터 · 경보 = R14 공용 입구.
4. **규칙**: CLAUDE.md `root_ledger` · `skill_workflow_default` 에 「구조체크 = 덮음표 · 결함 0 금지 · 뿌리 = 전 기능 기계 시험」 반영(행동 룰이라 CLAUDE.md 안 · Harold 승인 뒤).
