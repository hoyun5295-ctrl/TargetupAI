## §2 브레인스토밍 (COLLAB §1 · 주재자 단독)

harold-guard 가 「발동」으로 시작한 턴에만 에이전트를 허용해 5역할 에이전트 소환이 막혔다(가드 안내 = 「직접 순차로 진행」). 주재자가 5역할 관점(기획 · 백엔드 · 프론트엔드 · 디자이너 · 회의론자)으로 같은 코드를 직접 읽고 4항목(제안 · 위험 · 근거 · 토론)을 차례로 적어 수렴했다. 관점마다 수렴 결과만 남긴다.

- **기획** — 세 기능을 한 엔진 원칙 위에 둔다(§3). 「검사 통과」를 날마다 알리는 것은 담당자에게 정보가 아니라 소음이다 → 손이 필요한 일만 즉시 · 나머지는 주 1회 요약 + 상황판. 상황판은 읽기 전용(돈 · 발송을 바꾸는 일은 기존 링크 화면의 되묻기를 지난다).
- **백엔드** — 병목은 셋이다: ① 플랫폼 스팸 검사 큐가 한 줄 · 전 회사 FIFO · 건당 60~90초(`spam-test-queue.ts:782-826` · `config/defaults.ts:212-214`) ② 진입 감시 · 실행기 · 자동마케팅이 회사를 가리지 않고 차례로 돈다 ③ 매일 칸마다 검사가 발송 관문이다(`journey-executor.ts:776-800`). ①③이 겹치면 수백 회사 × 칸의 매일 검사를 큐가 감당 못 해 발송이 하루 종일 묶인다. 처방 = 검사 수요를 줄이고(주 1회) · 줄을 공정하게(회사 돌아가며) · 엔진은 회사끼리 동시(회사 안은 차례 = 예산 · 잔액 경합 0).
- **프론트엔드** — 여정 점검 판(`components/journey/workspace/JourneyCheckPanel.tsx`)을 공용 점검 판으로 빼서 자동마케팅에 같은 모양으로. 링크 화면 6종 중 충전 승인만 되묻기 없음(`pages/ChargeApprovePage.tsx:195` `onClick={approve}`).
- **디자이너** — 상황판 = 휴대폰 우선 · 첫 화면 「한눈에」(판정 문장 한 줄 + 숫자 넷 + 할 일 목록) · 메뉴 = 여정 · 자동마케팅 · 플래너. 숫자는 콤마 · 단위 · 1,000만도 줄바꿈 없이.
- **회의론자(깨지는 곳 → 막은 형태)** — ① 상한 0 → 첫 동기화 대량 발화: 상한은 고객사 선택 브레이크로 남고(C92) 켜기 창 · 일괄 켜기가 위험을 한 줄로 보인다 · 이 문서는 버림만 없앤다. ② 주 1회로 줄이면 문안이 바뀐 날을 놓친다 → 문안이 바뀌면 그 자리에서 다시 검사(기존 스냅숏 표식 유지) + 실발송 결과의 스팸 차단 코드를 날마다 본다(E3-4 = 실험실 검사보다 진짜 신호). ③ 「판정 못 함 = 보냄」은 진짜 차단 · 검사 안 한 글을 보낼 수 있다 → 확인 문자 기준 「막힘」(1101 B1-4 4값)만 칸을 막고, 장애 · 확인 못 함은 **이미 통과한 글만** 보내되 기록 · 경보 · 실발송 감시가 받는다(새 글은 검사 없이 안 보냄). ④ 회사끼리 동시 → 같은 회사 두 실행이 예산을 동시에 통과 → 회사 안은 차례(설계 불변식 §7-I1). ⑤ 다른 세션과 같은 작업 트리 · 섞인 push(1101 경보 100통) → 배포 단계에서 파일 단위로 가른다(§10).

## §4 설계 항목

### E1 대상 전원 (H1 · H3-c)

**E1-1 날짜 기준 칸 · 한 번 보내기 = 넣기 한 문장이 한 시점 전원** — 작업 트리 C92 그대로(`journey-anchor-scheduler.ts` `audienceSource` · `journey-target-extractor.ts` `anchorAudienceSql` · 실 PG 시험 `journey-anchor-paging-1101.pg.test.ts` · 뿌리 R40). 한 번 보내기 멱등 = 계보 잠금 안에서 다시 확인(C92 Codex 2R).

**E1-2 한 번 보내기 적재 = 정산 뒤에만 · 실패해도 저절로 회복 · 되돌리기는 이번 시도만(Codex C92 4R · 설계 1R~4R)**
- 지금: 켜기 순서 = 켜기 커밋(`journey-builder.ts:1106-1148` · `approved_at = NOW()` RETURNING) → 첫 켜기 차감(`journey-activation.ts:117-135` · 실패 = `revertFirstActivation` `:162-168` = `status = 'active'` 만 보고 초안으로) → 적재(`:143`). 적재가 던지면(C92) 이 여정만 멈춤 + 실패 응답 → 멈춤 UPDATE 까지 실패하거나 커밋 뒤 프로세스가 죽으면 「켜짐 · 실행 0」이 남고 다시 켜도 activateJourney 가 켜진 여정을 받지 않아(`:1114`) 넣을 길이 없다. 되돌리기는 「이번 시도」를 모른다(설계 4R D4-1 = 늦게 온 되돌리기가 그 뒤 다른 요청이 정상으로 켠 상태를 덮는다 · 3R D3-3 과 같은 부류 두 번째 → 구조로).
- **뿌리 처방 = 시도 토큰 + 영속 표식 + 원장이 정산의 진실**(되돌리기 경합 · 옛 · 새 코드 판 가르기 · 정산 전 적재를 한 번에):
  - **시도 토큰 = 그 켜기가 찍은 `approved_at`**(켜기 커밋 RETURNING · 켤 때마다 새 값 · `::text` 로 마이크로초 보존) — activateJourney 가 결과로 돌려준다. 이 켜기의 되돌리기(첫 켜기 차감 실패 = 초안으로 · 재개 정산 실패 = 멈춤으로)는 **`WHERE status = 'active' AND approved_at = 토큰`** 일 때만(그 뒤 다른 요청이 다시 켰으면 토큰이 달라 안 건드린다). **토큰 · 잠금은 한 번 보내기에만** 쓴다(설계 6R) — 한 번 보내기가 아닌 여정은 지금의 `revertFirstActivation`(`status = 'active'` 면 초안으로)을 그대로 둔다: 그 여정에는 회복 고리 · 정산 표식이 없어 토큰으로 「뒤 켜기 보존」을 하면 정산 안 된 켜짐이 남는다(지금 규칙 = 「차감을 못 걷으면 켜짐이 아니다」를 지키는 쪽 · 뒤 재개를 덮는 기존 경합은 [범위 밖] 기록).
  - **영속 표식 둘**(§5 DDL-1): `one_shot_dispatch_pending_at` = 새 코드의 켜기 커밋이 같은 UPDATE 에서 찍는다(한 번 보내기 · 아직 안 넣은 판만) · `one_shot_dispatched_at` = 적재 트랜잭션이 실행을 넣고 같은 트랜잭션에서 찍고 pending 을 지운다(대상 0 도 찍는다 = 「켤 때 대상 1회」 뜻 그대로). 되돌리기는 pending 도 지운다. 옛 코드는 pending 을 모른다 → 옛 코드 판과 새 코드 판이 데이터로 갈린다(설계 3R D3-1 · 2R 「옛 0 건 · 옛 실패 판 자동 재적재 금지」).

- **직렬화(설계 5R D5-1 · 되돌리기 경합 부류 세 번째 → 잠금 규약 하나)**: 한 번 보내기의 [정산 → 되돌리기 또는 적재](켜기 경로)와 [정산 → 적재](회복)는 **여정마다 하나인 잠금**(PG 세션 advisory lock `('one-shot-settle', 여정 id)` · 전용 연결 · finally 에서 풂) 안에서만 한다. 켜기 경로 = 잠금을 기다려 잡음 · 회복 = 잡기 시도(못 잡으면 그 판 이번 회차 넘김). **잠금 안에서 다시 판정**: 되돌리기 = `status='active' AND approved_at = 토큰 AND one_shot_dispatched_at IS NULL` 이고 원장에 그 키 줄이 없을 때만(그사이 회복이 정산 · 적재했으면 되돌리지 않는다) · 회복 = 잠금 안에서 다시 읽어 `status='active' AND pending NOT NULL AND dispatched NULL` 일 때만 정산 · 적재(그사이 되돌려졌으면 차감 0). 원장 조회 · 차감 · 적재 · 되돌리기가 모두 잠금 안이라 「잠금 밖 조회」 경합이 없다.

DDL-1 의 UPDATE = 초안이 아닌 한 번 보내기(켜짐 · 멈춤 · 끝남)는 「넣음」으로 찍는다(옛 판의 뜻 그대로 · 대상 0 이던 켜진 판을 배포 뒤 다시 뽑지 않는다 · SC-4) · **초안은 NULL 그대로**(첫 켜기에 넣는다 · 설계 1R D1-2). **배포 뒤 다시 찍기(DDL-1b)는 없다**(설계 3R D3-1). DDL-1 은 코드 배포 **앞**에 돈다. DDL-1 과 코드 배포 사이(수 분)에 옛 코드로 켜진 한 번 보내기는 pending NULL(옛 코드는 칸을 모른다) → 자동 적재 대상이 아니다(옛 대상 0 판 · 옛 실패 판 자동 재적재 0) · 실행이 있으면 정상 · 실행 0 이면 운영 경보 + 사람 길(E1-2). 켜진 채 실행 0 인 한 번 보내기 수를 DDL 앞에 확인 SQL 로 본다.

## §7 정합성 불변식 (구현 · 시험이 지킨다)
