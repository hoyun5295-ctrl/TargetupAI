## 2. 1단계 · 이미지 품질(백엔드)

### R1 템플릿 판단 선택 — `pickTemplateJudged`(produce.ts)
- 후보 = 업종 풀(TEMPLATE_POOLS product + event) 중 이번 달 맞는 것(templateFitsMonth). 세부 카테고리(SUB_BY_ID)는 후보 줄에 함께 싣는다.
  - 회의 수렴은 "12~20개로 좁힌 뒤 1회"였으나 업종 풀 전체(뷰티 ≈90)를 한 줄 30토큰짜리 목록으로 넣어도 텍스트 1회라 비용·정확도에 문제가 없다(이미지 0). 좁히는 단계를 따로 두지 않는다.
- 입력 = 업체명 · 업종 · 확정 행사 제목(면허 통과분은 인용 · 수치는 숫자 가림) · 상품명 상위 6 · 강조 포인트 일치 구간(R9) · 후보 `id | 세부 | 이름 | useCase`.
- 출력 = `{"product":[id×3], "event":[id×3], "reason":"한 줄"}` JSON. 후보 밖 id 는 버린다. 한쪽이 비면 그 쪽은 해시(pickTemplate)로 채운다.
- 실패(모델 장애·형식 불명) = 전부 해시. 호출 위치 = jobs.ts producing_image 의 포스터 직전(대기열 imageSlot **밖**).
- 저장 = `stage_results.template_pick = { product[], event[], reason, source:'ai'|'hash', at }`. 있으면 다시 부르지 않는다(같은 잡 = 같은 순위). 지우는 곳 = 재크롤(RESETTABLE_KEYS) · 사람 확정(confirm SQL `- 'template_pick'`).
- 고르기 = 순위 목록[regenSeq % 길이] — 처음 = 1위, [다시 만들기] = 2위 → 3위 → 1위(접수 5 "다시 해도 안 변함").

### R2 템플릿은 한 번 고른 것만
- 숫자 유출 재시도 = 같은 템플릿으로 배경만 다시(옛 `seedSuffix` 경로 제거 · 기록 templateId 와 실물 불일치 해소).
- 재시도도 숫자가 남으면 포스터를 버린다(throw) → 기존 폴백(히어로 = 홈 배너).
- 16:9 배너도 같은 템플릿.

### R3 누끼 원천 규칙
- 이미지 종류 판정 대상에 상품 사본 상위 3장을 **앞에** 더한다(상한 14 → 17 · 기존 14장 판정 그대로).
- 누끼 후보 = (엑셀 대표 상품 이미지) → 사람이 고른 이미지 → 상품 사본. 판정이 banner·photo·document 인 것은 **제외**(옛 = 뒤로 미루기). 판정 없음은 통과(모델 부재 폴백).
- 해상도 하한 300 → **600**(짧은 변 · `OUTREACH_CUTOUT_MIN_SIDE`). 포스터에 폭 0.62배로 얹으므로 3:4 기준 ≈670px 필요. 600 은 시작값 · C12 측정으로 조정.
- 인물 판정 · strictPerson(자동 확정) 그대로.

### R4 누끼 원천이 없을 때
- 기존 그대로: 행사(event) 템플릿 배경 포스터(제품 0) · 실패 = 홈 배너 히어로. 업종 일괄 규칙 없음(원천 규칙만).
- "행사 배경 안에 홈 원본 사진 합성"(디자이너 안)은 합성 경로가 없어 이번 범위 밖(추가 과제).
- 글자 있는 홈 배너 히어로: 기존 `heroBannerCopyOf` 판정(배너·상품 · 글자 있는 것 우선) 유지. 회의론자 지적(글자 판정은 날짜·가격을 구분 못 함)은 추가 과제로 기록.

### R5 템플릿 장면의 소품 문장 제거
- `buildPosterPrompt` 에 선택 인자 `scaffold`(덮어쓸 장면 문장)를 더한다(공용 CT · 미지정 = 종전 그대로 · 스튜디오 무영향).
- 아웃리치는 `stripScaffoldProps(scaffold)` 결과를 넘긴다 — "props"·"product stands/sits/rests" 가 든 문장만 지운다(덮어쓰는 지시 추가 0 · LESSONS_BACKEND 0809 교훈). 문자열 테스트로 고정.

## 3. 2단계 · 받는 메일 첫 화면

### R7 메일 첫 화면 재구성(`buildProposalEmailSections`)
옛: 한줄로 머리 → 헤드라인·서두 → [DM 열어보기] → 시안 머리말 카드 → 그 브랜드 DM 블록 전부 → 꼬리.
새:
1. 한줄로 머리(작게)
2. 글자 카드: 호칭 + **"○○님 브랜드로 만든 문자 DM 시안입니다"** 한 줄(헤드라인) — 이미지 차단 메일에서도 남는 글자
3. 그 브랜드 머리(로고 · 브랜드 색) + 히어로(포스터/배너) — 시안의 header·첫 gallery 만
4. **휴대폰 틀 안 DM 첫 화면**(dm asset `captureUrl` 을 서버가 sharp 로 틀에 끼운 JPEG · `dmFrameUrl`) — 없으면 생략
5. [DM 열어보기] 버튼
6. 서두 문단 → 그 아래 기존 꼬리(확정 행사 요약 · 문안 · 기능 · 버튼 · 서비스 · footer)
- 시안의 나머지 블록(상품·행사·슬라이스)은 메일에서 빼고 DM 안에서 본다(디자이너 "메일 ≠ DM"). 확정 행사 요약 카드는 시안 행사 블록이 빠지므로 다시 나온다.
- 이미지 alt: 히어로 = "{업체} 브랜드 이미지" · 틀 캡처 = "{업체} 문자 DM 첫 화면".
- 평문 대체본은 같은 순서로.
- 파기: email_html payload `dmFrameUrl` 파일도 지운다(purge).
- 확정 전 실측 = 검수 메일로 Gmail · 네이버 · 아웃룩(Harold 실행).

### R8 재료가 적을 때 — `composeOutreachStandard`

- 행사 0 = 행사 블록 없음(기존) · 대표 버튼은 상품 뒤(기존).
- 새 멈춤 없음 — 재료 잠금은 기존 불변 29(MATERIAL_THIN)만.

### R9 엑셀 선택 칸 2개 — `sales-outreach-bulk.ts`
