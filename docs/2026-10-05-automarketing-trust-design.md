## §0 30초 요약

- **대상은 계약만.** 등록(미리보기) 때 목표를 한 번 번역해 **축** 또는 **고정 칸 조건**으로 고정한다. 회차는 그 계약만 컴파일하고 대상 AI를 부르지 않는다. 목표가 요구하는 데이터(칸)가 없으면 **넓히지 않고 멈춘다**(「필요한 고객 데이터가 없어 시작할 수 없어요」).
- **빈 조건 = 전체는 없다.** 전체 발송은 「전체 고객」 축으로만. 축도 칸 조건도 없는 등록(옛 자유 해석)은 회차가 멈추고 1회 알린 뒤, 담당자가 조건을 확인해야 다시 나간다.
- **생일 = 이번 회차 기간에 생일인 고객**(매일 = 오늘 · 매주 = 이번 주 · 매월 = 이번 달) · 월일 칸 또는 생년월일 · 2월 29일생은 평년 2월 28일.
- **매일 · 매주 주기 + 상태 조건 = 같은 사람 반복**이라 등록을 막고 「새로 해당된 사람」 축(발길이 끊긴 고객 등)이나 매월 주기로 안내한다.
- **0명인 날은 정상** — 조용히 넘긴다(발송 0 · 차감 0 · AI 0 · 회차 기록 「대상 없음」). 판정 불가(데이터 없음 · 조건 없음)만 멈추고 알린다.
- **주간 승인** — 승인 1회 = 다음 회차부터 7일(매일이면 7회) 자동 발송. 매주 · 매월은 다음 회차 1회분. 상한(회사 자율 발송 상한 · 자동 마케팅 예산)을 넘는 회차만 보류. 끝나기 하루 전 지난 기간 요약 + 다음 승인 요청 문자 1통. 슈퍼관리자 자율 옵션은 그대로(승인 없이 계속 자동).
- **문안 분기** — 「AI가 회차마다 새로 써요」(허브 문안 엔진 · 핵심 혜택 = 사용자 글자만 근거 · 조건 · 계절 느낌) / 「직접 쓴 문안 그대로」(AI 문안 0 · 미리보기 0크레딧 · 스팸 검사는 같은 문안 1회 · 값 없는 %칸% 차단).
- DDL 1문(continuous_operators nullable 6칸 · 배포 뒤) · 신규 크레딧 키 0.

## §2 계약

### 2-1. 대상 = 계약만 (§2 불변 원칙 1의 구조적 강제)

- 계약 = **축**(`segment_key` · `segment_params`) **또는 칸 조건**(`audience_filters`). 옛 축 힌트(`target_hint`)는 같은 이름의 축으로 결정적으로 바뀐다(AI 지시 갈래 삭제).
- 회차는 계약을 컴파일해 **먼저 센다**(AI 0). 계약이 없으면 멈춘다 — 담당자 1회 알림(기존 0건 알림 쿨다운) + 회차 기록 「조건 확인 필요」.
- 오케스트레이터의 대상 AI는 자동 마케팅 회차에서 대상을 정하지 않는다. 채널 · 개인화 같은 부가 판단에만 쓰고, 조건은 계약(축 또는 고정 칸 조건)이 정한다.

### 2-2. 대상 번역 module (`utils/audience-translate.ts` · 등록 · 미리보기 · 승인 창 공용)

입력 = 회사 · 사람 · 목표 · 주기 · (명시 값: 고른 축 · 옛 힌트 · 고른 칸 조건). 결과는 넷 중 하나:

| 결과 | 언제 | 화면 |
|---|---|---|
| 축 | 매핑 AI가 축을 고르고 그 축이 열려 있고 짝 검사 통과 | 「조건에 쓰는 칸」에 축 · 기준 |
| 칸 조건 | 축이 아니고 칸 번역 AI가 모든 조건을 칸으로 옮김 · 짝 검사 통과 | 조건마다 칸 · 기준(고침 가능) · 값 있는 고객 수 · 값 예시 |
| 고르기 필요 | 칸으로 못 옮긴 말이 있음 | 그 말마다 칸 고르기(값 있는 칸만) · 「맞는 칸이 없어요」 |
| 막힘 | 가리킨 축이 잠김(데이터 없음) · 조건 없음 · 짝 불가 | 사유 · 시작 버튼 없음 · 차감 0 |

- 매핑 AI는 **잠긴 축도** 사유와 함께 받는다(옛: 열린 축만 → 잠긴 목표가 자유 해석으로 샜다). 잠긴 축을 가리키면 그 축의 잠금 사유로 막는다.
- 칸 번역 AI는 `detectActiveFields`(값 있는 칸 · 회사 전용 칸 라벨 · 값 목록)를 받고, **표현 못 한 말을 빼지 않고 따로 돌려준다.**
- 근거 숫자(값 있는 고객 수 · 값 예시 · 대상 수)는 **DB만** 센다. AI가 낸 칸 · 연산자 · 값은 칸 목록(화이트리스트)으로 검증한다.
- 번역 AI 호출은 무과금(옛 등록 매핑과 같은 `creditCost: 0`).

### 2-3. 컴파일 (`compileOperatorAudience`)

- 축 없음 + 조건 비어 있음 → **던진다**(`AUDIENCE_EMPTY`). 소비처 4곳(회차 수 · 명단 · 실발송 · 축 미리보기)이 같은 판정.
- 생일 축은 `period`(주기에서 결정)로 기간을 받는다. 주지 않으면 「이번 달」(옛 동작).

### 2-4. 생일

- 판정 = `birth_month_day`('MM-DD') 또는 `birth_date`의 월일이 기간 안. 2/29생은 평년 기간에 2/28이 있으면 그날로.
- 근거 판정(`hasBirthday`) = 월일 칸 또는 생년월일이 있는 고객 1명 이상(옛: 생년월일만).

### 2-5. 회차 (`generateProposalForOperator`)

1. 계약으로 먼저 센다 → 던짐 = 멈춤 + 알림(판정 불가) · 0 = 조용히 기록(「대상 없음」 · AI 0 · 차감 0) · 그 밖 = 다음.
2. 문안: 직접 쓴 문안 = AI 없이 그 문안 · AI = 미리보기 결과(precomputed · 대상 수 · 비용은 방금 센 값으로 덮는다) 또는 오케스트레이터(핵심 혜택 = 사용자 글자만 근거).
3. 자율 자격 = (회사 자율 옵션 **또는** 승인 기간 안의 회차) **그리고** 기존 상한 · 위험도 · 검수 · 발신번호 · 080.
4. 스팸: AI 문안 = 지금 그대로 · 직접 쓴 문안 = 지문이 같은 통과 기록이 있으면 검사 생략, 없으면 그 문안 1안만 검사(재생성 0)하고 결과를 지문으로 저장.
5. 회차 기록(`round_log` · 최근 60건) = 예약 · 승인 대기 · 보류 · 대상 없음 · 멈춤.

### 2-6. 승인 기간

- 시작 = 다음 회차의 발송일 · 끝 = 시작 + 6일 그날 밤 12시(KST). 매일 = 7회 · 매주 · 매월 = 1회.
- 승인 = 그 기간의 회차를 자율 자격으로 만든다. 상한을 넘는 회차는 지금처럼 발송 직전 재검사에서 보류된다(한 곳).
- 끝나기 24시간 안 = 담당자 문자 1통(지난 회차 요약 + 다음 승인 요청) · 기간마다 1회(`approval_meta.renewalNoticeFor`).
- 기간이 끝나면 회차마다 승인 대기(옛 동작)로 돌아간다.

### 2-7. 문안

- AI: 허브와 같은 `generateMessages`. 오케스트레이터에 `lineFacts = { benefit: 핵심 혜택 }`을 넘겨 혜택 근거 = 목표 + 핵심 혜택뿐(회사 메모리 · 계절 블록은 근거가 아니다). 조건 느낌 = 계약 설명 블록(축 설명 · 칸 조건 문장) · 계절 = 기존 계절 힌트.
- 직접: `fixed_copy { subject, body }` · 저장 때 %칸% 검사(값 없는 칸 = 400) · 발송 때 (광고) · 080은 지금처럼 자동으로 붙는다.

## §3 데이터 (DDL 1문 · 배포 뒤 · 모두 nullable)

```sql
SET lock_timeout = '3s';
ALTER TABLE continuous_operators
  ADD COLUMN IF NOT EXISTS audience_filters jsonb,
  ADD COLUMN IF NOT EXISTS copy_mode varchar(10),
  ADD COLUMN IF NOT EXISTS fixed_copy jsonb,
  ADD COLUMN IF NOT EXISTS approved_until timestamptz,
  ADD COLUMN IF NOT EXISTS approval_meta jsonb,
  ADD COLUMN IF NOT EXISTS round_log jsonb;
```

| 칸 | 모양 |
|---|---|
| `audience_filters` | `{ conditions: [{ term, field, label, operator, value }], confirmedAt }` |
| `copy_mode` | `'ai'` · `'fixed'` (NULL = ai) |
| `fixed_copy` | `{ subject, body, spam: { hash, status, checkedAt } }` |
| `approved_until` | 승인 기간 끝(KST 그날 밤 12시) |
| `approval_meta` | `{ approvedAt, approvedBy, windowStart, renewalNoticeFor }` |
| `round_log` | `[{ at, outcome, count, reason }]` 최근 60 |

**DDL 전 폴백**: 칸 준비 여부를 실제로 본다(`hasOperatorV2Columns` · 옛 `hasSegmentColumns`와 같은 형태). 준비 전 = 칸 조건 저장 · 직접 쓴 문안 · 승인 기간 요청만 503 `DB_MIGRATION_PENDING`, 축 계약 등록 · 회차 · 발송은 그대로. 회차 기록 쓰기는 건너뛴다.

### 9-2. 구현하며 정한 것 (설계 밖 · 같은 접수를 닫는 데 필요)

- **한 줄에서 주기를 읽는다**(`parseScheduleFromText` · AI 0) — 한 줄의 기본값이 매일이라 「매월 초에 포인트 독려」 같은 상태 조건이 Q9 짝 검사에 전부 막혔다. 문장의 매일 · 매주 ○요일 · 매월 ○일 · 매월 초/말 · 「생일인 날」(= 매일)을 읽고, 없으면 **매월 · 오늘 날짜**. 정해진 주기는 창 첫 줄에 날짜로 보인다.
- **상태 시나리오 7종 = 매월 1일 기본**(같은 이유) · **오늘의 추천 [시작]도 승인 창을 거친다**(옛: 매일 기본값으로 바로 등록).
- **시작 판정은 문안을 만들지 않는다**(`copyStep = existing`) — 보관본에 문안이 없으면 400(AI 0 · 차감 0). 다음 승인 창은 문안 없이(`skip` · 회차가 만든다).
- **생일 월일 칸은 글자로만 비교**(`LEFT(birth_month_day, 3) = 'MM-'`) — `::int` 형변환은 PG 가 AND 평가 순서를 보장하지 않아 이상한 값 한 행이 회차 전체를 멈출 수 있다. 같은 칸을 쓰는 기존 화면(`companies.ts` `LIKE 'MM-%'`)과 같은 방식.

- **조건 → SQL 다리는 하나**(`conditionsToFilters`) — 같은 칸 겹침(이상 + 이하 한 쌍만 허용)과 SQL 로 안 나오는 조건(칸마다 혼자 컴파일해 빈 조각)을 거절한다. 실측 탐침: 옛 컴파일러는 `store_code` · 일부 날짜 칸은 모든 연산자, `age` 는 between 밖 연산자를 빈 조각으로 건너뛰었다(= 조건이 사라져 넓어짐). 사람 입력 = 400 · AI 입력 = 고르기 필요.
- **말(term)은 빠지지 않는다** — AI 응답에서 칸 · 연산자 · 값이 빠진 조건, 배열이 아닌 칸, 값이 비거나 숫자 문법이 아닌 조건(「,」 포함)은 버리지 않고 「옮기지 못한 말」로 돌린다. 창 편집은 지금 창의 번역(`carry`)을 넘겨, 이미 정한 말이 빠지면 400 · 못 정한 말이 남으면 계속 고르기. 한 번역 안의 말은 유일하다(`termUniquer` · 「금액 (2)」 · 이름 없음 = 「대상 조건」). 9개 이상은 잘라 받지 않고 400.
- **창 상태는 서버 보관본 하나 + 판 번호** — 다음 승인 창도 처음 시작처럼 서버 보관본(`PreviewEntry.operatorId · rev · shownStart`)을 쓴다. 창 열기 = `approval-preview`(보관만) · 편집 = `preview/update` · 승인 = `approve-window`(보관본 id + 판 번호만) · 시작 = `from-preview`(판 번호). 판이 다르거나 보여 준 승인 기간이 바뀌었으면(발송 시각이 지남) 409 + 지금 상태를 돌려 화면이 바꾼다. 기간이 바뀌어 나가는 모든 응답은 판을 올린다(`shown()` 한 곳). 저장은 화면이 확인한 기간 그대로(`approveOperatorWindow.window`). 화면 초안(renewalDraft · contractDraft · applyCopyDraft)은 삭제.
- **회차 결과의 대상 칸 = 저장된 계약**(`contractTarget`) — 미리보기 결과 · AI 결과 · 직접 쓴 문안 결과 모두 마지막에 계약으로 덮는다. 문안은 다시 만들지 않는다(기준 숫자만 고친 경우 5크레딧 재차감을 피함).
- **수신자 확정 = 지금 계약과 같을 때만 · 계약 저장과 직렬화**(`stageIfContractMatches`) — 발송 함수의 수신자 적재 자리에서 한 트랜잭션으로 운영자 행 `FOR SHARE` → 회차 대상 칸과 지금 계약 비교(`proposalMatchesContract` · 키 순서 무관) → 적재 → 커밋. 다르면 `admin_review` 보류 + 알림. 자동 · 수동 승인 공통 · 리마인드(1차 수신자 코호트)는 비교 밖. 계약 저장 UPDATE 는 이 잠금을 기다린다(적재 시간만큼 · 시간 상한 없음).
- **승인 기간 = 첫 승인 회차의 날(KST 0시) ~ 끝**(`isWithinApprovalWindow`) — 끝만 보면 승인 전 회차(최적 시각 모드의 오늘 회차)가 다음 기간 승인으로 나갔다. 요약은 시작 − 발송 준비 시간부터 센다(`approvalSummarySince`).
- **갱신 안내** — 안 보낸 행만 조회(LIMIT 없음 · 24시간 안 만료분) · 적재 실패면 같은 기간일 때만 선점 해제. 선점과 적재 사이 프로세스 종료는 그 기간 안내가 빠진다(알려진 한계 · 필요해지면 안내 작업 표).

### 9-4. 배포 직후 기존 운영자에게 생기는 변화 (Q12 · 의도된 동작)

- **계약 없는 옛 자유 해석 운영자**(축 · 칸 조건 · 축 힌트 모두 없음) = 회차가 멈추고 담당자에게 1회 알림 · 목록에 「조건 확인 필요」 → 창에서 조건을 확인하고 승인하면 고정되어 다시 나간다.
- **이미 만들어진 제안(예약 · 승인 대기)** = 발송 때 그 대상 칸이 운영자의 지금 계약과 다르면 보류(`admin_review` · 알림 · 발송 0). 계약 없는 운영자의 제안, 옛 축 힌트 운영자가 배포 전 AI 해석 조건으로 만든 제안, 조건 확인 · 다음 승인으로 계약이 바뀐 뒤의 옛 제안이 해당한다. 담당자가 사람 승인한 제안도 같다(조건 확인 뒤 다시 승인).
- **승인 기간이 없는 운영자** = 지금처럼 회차마다 승인(회사 자율 옵션이면 지금처럼 자동).
- **미리보기 · 승인 창 보관본 = 서버 메모리 30분** — 배포(재시작) 순간 열려 있던 창은 시작 · 승인 때 410(차감 0) → 다시 열기.
- **화면 · 서버 판 번호** — 배포 순서(백엔드 → 프론트) 사이에 옛 화면으로 시작 · 승인하면 판 번호가 없어 409(지금 상태로 바뀜) → 새로 고침 뒤 진행.
- DDL 전에는 승인 기간 · 칸 조건 · 직접 쓴 문안 등록이 503(`DB_MIGRATION_PENDING`) · 축 + AI 문안은 그대로.
