# 정산 특례 — 추가 청구(080·부가서비스·최소과금)와 발행 그룹 — 설계

> 2026-07-30. 기원 = 서수란 팀장 "정산 관련 체크 사항"(0729 접수) + KT 명세서 실측(Harold 제공).
> SoT = 이 문서. 상태·잔여·금지 조건은 STATUS §2 카드가 소유한다(doc_ownership) — 여기엔 구조와 근거만.

## §0 문제 — 특례가 시스템 밖에 있다

일괄발급·컨펌·세금계산서 체계(0728)를 세웠는데도 서 팀장은 매달 전 업체를 손으로 보정하고 있었다.
청구 규칙 상당수가 **머릿속과 종이(KT 명세서 손글씨)에만** 있기 때문이다. 사람이 바뀌면 청구가 틀어진다.

접수 항목을 성격으로 가르면 셋이다. 한 덩어리로 보면 설계가 안 나온다.

| 부류 | 성격 | 해법 축 |
|---|---|---|
| ① 반복 금액 규칙 | 매달 같은 값(최소과금·080 관리비·정액 특례) | **축 A** — 회사 규칙·월별 항목 |
| ② 발행 분할 | 누구 앞으로 몇 장을 끊는가(지점·대상ID·계정 묶음·모듈/웹) | **축 B** — 발행 그룹 |
| ③ 수기 종량 | 매달 값이 바뀌고 사람 판단이 끼는 것(통화료·URL 제작·대행 문안) | **축 A** — 월별 항목 수기 입력 |

## §2 축 A — 080 청구 (구현 완료)

### 2-1. 실체 (KT 명세서 실측)

인비토 명의로 **월 1장**이 온다. 일반전화 1대 + **080 서비스번호 18대**. 번호마다 `부가서비스이용료(고정) + 이동전화에 건 통화료(변동) + VAT`.
2026-07 청구분 실측: 총 155,930원 / 080 소계 147,462원 / 부가서비스 전 번호 4,000원 / 통화료 0~27,790원 / **VAT = floor((통화료+부가서비스) × 10%)**(18행 전수 확인).
번호↔업체는 명세서 여백의 손글씨가 유일한 근거였다. `080-566-3330`에 "7월부터 리스킨 사용" 메모가 있어 **번호는 업체 간 재배정된다**는 것도 확인된다.

이용료 9,900원(부가세 포함)은 KT 청구서에 없다 — **인비토가 붙이는 080 관리 서비스료**(Harold 확정).

### 2-2. 구조

```
번호 매핑(1회 등록) → 매달 KT PDF 업로드 → vision 판독 → 코드 검산 → 사람 확인 → [반영] → 발행이 항목으로 인쇄
```

- **매핑** `billing_080_numbers` — 번호(숫자만·전사 유일)·회사·라벨(부서/브랜드)·이용료 공급가(기본 9,000)·KT 부가서비스 공급가(기본 4,000)·통화료 청구 여부·활성. 금액은 전부 **공급가 저장**(VAT는 청구서가 파생 — 0726 원칙).
  - 기존 `users/companies.opt_out_080_number`(수신거부 콜백 축)는 **재사용 불가** — 회사당 1개뿐이고 의미가 다르다(실측 확인).
- **판독** `utils/billing-080.ts extractKtStatement` — 0728 사업자등록증 판독(`biz-registration-extract`) 미러. PDF/이미지·10MB·매직바이트 스니핑·크레딧 0.
- **검산은 AI가 아니라 코드**(`validateKtStatement`, 전부 fail-closed):
  ① 행 내부합 `call+svc+vat = subtotal` ② `VAT = floor((call+svc)×10%) ±1` ③ 부가서비스 0 행 거부 + 3행 이상일 때 최빈값 이탈 거부 ④ `Σsubtotal = total_080` **및** 행 수 = `count_080`(둘 다 필수 — 0이면 판독 실패로 본다) ⑤ 번호 중복 ⑥ **3행 미만 = 자동 반영 불가**(통계 축이 성립하지 않는 표본).
- **결속** — /parse가 정규형(번호 정렬·정수 고정)에 **HMAC 서명**(TTL 6시간)을 발급하고, /apply는 서명이 유효한 전문만 받아 **검산을 서버에서 다시 실행**한다. 판독을 거치지 않은 금액은 반영될 수 없다.
- **반영** → `billing_extra_items`(월별 항목) 회사 단위 독립 트랜잭션. 발행된 달·이미 반영된 달(UNIQUE)은 건너뛴다. 미매핑 번호는 "보류"로 표시만(시세이도가 여기 해당 — 의도).
- **발행 통합** — `channel='extra'` 신설. 발행 코어가 **미소비 항목만** FOR UPDATE로 싣고, 공통 장 커밋 트랜잭션에서 `billed_billing_id`를 마킹한다. 항목줄·금액 항등식·장 분배·절사 계약은 기존 그대로(공급가 정수라 절사 멱등).

### 2-3. 왜 이렇게 했나 (Codex 적대검증 5R에서 굳은 것)

| 결정 | 이유 |
|---|---|
| `billed_billing_id` 소비 마커 | 없으면 7/1~15 + 7/16~31처럼 **겹치지 않는 두 발행**이 같은 달 항목을 각각 실어 이중청구가 된다. AI 크레딧(`ai_credit_transactions.billed_billing_id`)이 같은 부류를 이미 푼 계약이라 그대로 미러 — FK `ON DELETE SET NULL`이라 발행을 지우면 자동으로 미소비로 돌아온다 |
| 발행·반영·취소가 **같은 회사 advisory lock** | 잠금 밖에서 "발행이 있나" 조회만 하면 경합에서 진다. 취소 DELETE는 `WHERE billed_billing_id IS NULL` 원자 조건이라 져도 근거 행을 못 지운다 |
| 검산 결과의 서버 결속(HMAC) | 검산은 "전문 안에서의 일관성"만 본다 — 일관되게 조작한 전문은 통과한다. 세션 저장 없이 결속하는 최소 수단이 만료형 서명 |
| `toStrictInt`(숫자 타입 안전 정수만·반올림 금지) | `NaN → JSON null → Number(null)=0`으로 **"판독 불가"가 "0원"으로 살아나는** 3단 경로가 있었다. 671.6을 672로 살려주는 반올림도 같은 부류(손상 전문이 서명을 유지) |
| 총계·번호수 0을 불합격으로 | "안 보이면 0" 폴백이 검산을 여는 fail-open이었다 |

## §3 축 A — 최소과금 (구현 완료)

`company_billing_settings.min_charge_supply`(공급가·기본 50,000). 등록 회사는 **일괄발급 담기에서 빠지고**(서버 `filterBillableCompanies`가 단일 진실 — 화면 뱃지·담기 필터는 편의), [최소과금] 모달에서 대상월을 골라 **기본요금 정액 청구서**를 만든다(`issueMinimumChargeBilling`). 발행 후 메일·컨펌·세금계산서는 기존 흐름 그대로.

**fail-closed 6종** — 접수 원문이 "5만 미만의 경우"라는 조건부라, 조건을 확인할 수 없거나 조건에 맞지 않으면 발행하지 않는다.

| 게이트 | 이유 |
|---|---|
| 끝나지 않은 달 거부(KST) | 사용량은 가변이라 진행 중인 달의 스냅샷으로 정액을 확정하면 이후 발송이 최소과금을 넘어도 겹침 차단 때문에 되돌릴 수 없다 |
| 실사용 공급가 > 최소과금 → 거부 | 많이 쓴 달에 정액 5만을 끊으면 회사 손해. 판정은 **잠금 이후 트랜잭션 안 단일 시점**에서 일반 발행과 같은 집계·단가로 |
| 단가 미설정 3종(회사 단가·에이전트 매핑 0·발송ID 단가 공백) | 계산이 0원으로 나와 "가짜 미달"이 된다 |
| 미청구 AI 크레딧 존재 → 거부 | 정액 청구서가 그 기간을 덮으면 크레딧이 영구 미청구가 된다 |
| 미소비 추가 항목(080·부가서비스) 존재 → 거부 | 정액과 섞이면 이중청구/누락 어느 쪽이든 난다(벨루티류 겹침 규칙은 §7 확인 후) |
| 요금제(구독) 회사·선불 회사 → 거부 | 정액 대상이 아니다 |

원장 지문 재검증 + `companies` 행 FOR UPDATE(크레딧 승인·차감 경로와 직렬화)도 일반 발행 코어와 같은 계약으로 붙였다.

## §4 축 A — 부가서비스 수기 항목 (구현 완료)

`billing_extra_items.kind='manual'`. 추가 청구 관리 모달의 "부가서비스 입력" 탭에서 회사·대상월·항목 내용·건당 공급가·수량을 넣으면 **수량만큼의 행**(행당 단가)이 생기고, 청구서 항목줄이 같은 단가를 합쳐 **"부가서비스 N건 × 단가"** 참 산식으로 인쇄한다.

시세이도 단축 URL(장당 5만)·제시뉴욕 대행 문안(건당 2만)이 이 경로다. **자동 집계하지 않는 이유** — "서비스 제외" 같은 판단이 사람 몫이라 자동으로 세면 틀린다(§7-5).

발행된 달은 추가 차단, 개별 삭제는 미소비 행만(소비된 행은 발행 삭제로만 복귀).

## §5 축 A 나머지 (미구현)

정액 특례 — 시세이도 부서당 10만(드렁큰 5만)·에이스하드웨어 5만. §2의 매핑 금액(이용료·부가서비스)으로는 담기지 않는 "번호와 무관한 회사 단위 정액"이라, **회사 반복 항목 규칙**(매달 자동 생성되는 `billing_extra_items`)이 필요하다. §4 저장 축을 그대로 쓰고 "매달 자동" 플래그만 얹으면 된다.

## §6 축 B — 발행 그룹 (미착수 · 설계 방향)

현행 발행 단위는 `combined`(회사 1장)·`by_user`(계정별)뿐이고 `by_agent`는 축만 잡힌 채 이월돼 있다(`billing-issue.ts`). 접수 3-4·3-6·3-7·3-8과 서 팀장 제안(4번)이 전부 이 공백이다.

**제안 = 발행 그룹.** 회사 밑에 그룹을 두고(이름·사업자·담당자), 구성원으로 **계정 N + 발송ID N + 대상ID N**을 묶는다. 유형 귀속 예외(에이스: 알림톡을 웹으로)도 그룹 속성으로 둔다.
- 기존 `by_user`는 "계정 1개짜리 그룹"의 특수형이라 흡수된다.
- 이월된 `by_agent`도 같은 구조로 열린다.
- 서 팀장 4번 제안("Agent 사용분도 계정별로 지정")의 일반형이 정확히 이것이다.

데이터는 이미 있다 — `billing_items`가 행마다 `user_id`·`agent_id`·`store_id`·`channel`을 적재 중이다. 없는 것은 **그룹 정의와 장 분할 규칙**뿐.

미시스템화 권장 2건: 최선어학원 27지점(분할 금액 기준 미확인 — §7-2), 이새 3장("모듈" 실체 미확인 — §7-3).

## §7 서 팀장 확인 5건 (설계 확정 전제)

1. **벨루티** — 080 관리와 최소과금 양쪽에 있다. 별개 두 규칙인가, "080 포함 합산 최소 5만원" 하나인가.
2. **최선어학원 27분할** — 금액을 무엇으로 나누는가(지점별 사용량? 균등?).
3. **이새 "모듈"** — 무엇의 요금인가.
4. **시세이도 URL "서비스 제외"** — 누가 어떻게 판정하는가(수기 입력 전제가 맞는지).
5. **시세이도 번호 수** — 접수는 3개(드렁큰 제외)인데 명세서 계열은 4개(sh·Nars·cpb·De)로 보인다. 청구 대상 3개가 어느 것인가.

## §8 수용 위험 (Codex 적대검증 — 불수용 기록)

| 위험 | 판단 |
|---|---|
| KST 자정을 걸친 미커밋 크레딧 승인 × 자정 직후 정액 발행의 가시성 창 | 실현 조건이 자정 직후 수 초 안의 수동 발행(운영은 익월 낮)이고, 처방이 범위 밖 크레딧 승인 경로 수정이다. 결과도 영구가 아니다 — 발행 삭제 → 마커 FK 복귀 → 일반 발행으로 회수된다 |

| 동시성 회귀 테스트 부재 | 이 스위트는 DB 목이 없고, 일반 발행의 같은 부류(지문 재검증·FOR UPDATE)도 소스 계약으로만 고정돼 있다. 같은 기준을 유지한다 |
