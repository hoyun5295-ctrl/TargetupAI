## 1) 대행발송이란 — 제품 정의

**사람이 하던 대행발송의 손을 전부 기계로 옮기되, 발송을 결정하는 손(승인)만 담당자에게 남긴다.**

- 경위 = Harold 2026-08-22 "직원 2명이 대행발송에 붙어 있다. 슈퍼관리자가 체크한 업체에만 열고, 담당자가 등록하면 스팸 검사·다듬기·테스트 문자·승인·예약·당일 재검사까지 기계가 돌게 하자."
- 흐름 = **접수 → 1차 스팸 검사(AI 다듬기 포함) → 담당자 테스트 문자 → 승인 → (발송일이 다르면) T-2h 재검사 → 큐 적재 → 발송.**
- **입구는 셋, 그 뒤는 하나다.** 어느 입구로 들어와도 같은 원장·같은 워커·같은 승인 게이트를 지난다.

| 입구 | 무엇 | 사람이 확인하는 자리 |
|---|---|---|
| 화면 접수 | 명단 업로드 + 문안 직접 입력(3단계 Composer) | 접수 화면 자체 |
| 요청서 원스텝 | 요청서 xlsx + 명단, 두 파일로 끝(§17) | 확인 화면(strict 스냅샷) |
| **이메일 접수** | hanjullo 메일함으로 같은 두 파일을 보내면 자동 접수(§18) | **확인 화면이 없다** → 접수 완료 회신 메일 + 담당자 테스트 문자가 그 역할 |

- 노출 = **메뉴는 모든 회사에 보인다(미끼).** 진입은 슈퍼관리자 스위치 AND 유료 요금제(`canUseAgencySend` 한 곳이 판정).
- 돈 = **전액 고객사 귀속.** 정산은 이미 "누구 ID로 나갔나"로 굴러가므로 이 축이 정산에 새로 할 일이 없다.

## 2) 불변 원칙 (어길 수 없는 것)

> 전문·경위는 설계서 §3(불변 11개)·§12-G(계약 10)가 소유한다. 여기는 **다시 손댈 때 반드시 지나는 것**만.

1. **⛔ 승인 없는 발송 0 · 발송일 당일 검사 없는 발송 0.** 워커가 죽어 검사가 안 돌았으면 그 건은 `expired`로 안내하고 나가지 않는다.
2. **⛔ 큐 적재는 당일 검사 통과 뒤 1회뿐이고, 적재는 직접발송 배관에 위임한다.** 이 축이 `campaigns` INSERT·`bulkInsertSmsQueue`를 직접 쓰면 선불 차감·수신거부 제외·부분 적재 롤백·재시도 멱등이 한꺼번에 빠진다(0823 실측).
3. **⛔ 정산 축에 새 값을 만들지 마라.** `send_type='direct'`로 그냥 탄다. 새 값은 청구·동기화 축에 없어 빠지고, 넣으려면 정산 CT를 건드리게 된다(0823에 실제로 그랬고 전량 원복).
4. **⛔ 접수 쓰기는 `createRequestCore` 하나다**(CT = `utils/agency-send-intake.ts`). 입구가 늘어도 검증·트랜잭션·적재 대조는 이 한 곳이다. 라우트에 코어를 다시 정의하지 마라(계약 테스트가 잡는다).
5. **⛔ 소유권은 두 축뿐**: `revision`(담당자 경로 CAS) · `lock_token`(워커 경로). **타임스탬프를 토큰·CAS 조건으로 쓰지 마라** — PG 마이크로초와 드라이버 밀리초가 왕복에서 어긋나 정상 소유자도 0행이 된다(0823에 배웠는데 **0826 새 파일에서 재현했다**).
6. **⛔ `final_test_at`은 통과 분기에서만 찍는다.** 시도 시각(`last_test_at`)으로 "당일 검사 통과"를 판정하면 차단된 문안이 검사 없이 예약된다.
7. **⛔ 문안 변수는 주소록 슬롯 4칸으로 번역해 넘긴다**(`agency-send-vars.ts`). 치환 CT는 값을 **DB 컬럼 이름**으로 찾으므로 변수명을 키로 넘기면 전 건이 빈칸으로 발송된다(에러도 로그도 없다).
8. **⛔ 확정 경로에서 AI를 부르지 마라.** 미리보기가 추천하고, 화면이 그 매핑을 조정값으로 되보내고, 확정은 조정값만 믿는다(`aiSuggest=false`). 이메일은 전 구간이 확정 경로다.
9. **⛔ 양식의 원본은 xlsx가 아니라 생성 스크립트다**(`packages/backend/scripts/build-agency-request-form.js`). 손으로 고치면 파서 계약(★0826(2)·(3) 통일 양식 = **업체 실물 복제** · 시트 "내용"+"고객리스트" 한 파일 · 라벨 별칭 · 구양식 시트 "요청서"도 계속 읽음)이 깨진다. 바꾼 뒤 **파서 왕복 실측**이 같은 커밋에 들어간다. **값 칸 안내문은 실물 원문만**(파서 PLACEHOLDER_VALUES와 짝) — 새 안내문을 값 칸에 만들면 목록이 늘어난다.
10. **⛔ 이 축의 모든 문구에 줄표 0**(모달·버튼·안내 문자·회신 메일 전부). 계약 테스트 = `em-dash-invariants.test.ts`.
11. **⛔ 일반 사용자(company_user)는 본인 접수만, 관리자(company_admin·super_admin)는 회사 전체**(★0826(2) 서수란 접수·Harold 확정). 고객 라우트에 행 접근 경로를 새로 만들면 소유자 술어(`created_by`)를 같은 커밋에 건다. 판정은 **JWT 어휘로만**(DB `users.user_type`과 어휘가 다르다 · SCHEMA users 절 함정).

**이메일 입구 전용 (§18)**

12. **⛔ 서버 메일을 지우지 않는다(DELE 0).** 처리 상태의 진실은 intake 원장 단독이다. POP3에는 폴더·읽음 개념이 없다. 이 메일함에 다른 POP3 클라이언트를 물리면 그쪽 삭제 설정이 메일을 지운다.
13. **⛔ 신원은 allowlist_only.** 하이웍스가 수신 인증 헤더를 안 붙이므로(0826 실측) **허용 목록 정확 일치가 전부**다. 메일 안의 `ARC-*`·`Authentication-Results`·`X-Authinfo`는 발신자가 위조 삽입 가능하니 신뢰 근거로 쓰지 마라.
14. **⛔ 신원 판정 전에 본문·첨부를 내려받지 마라**(TOP 헤더만 → 판정 → 선점 INSERT → RETR). 무인증 입구의 첨부 폭탄 방어다.
15. **⛔ 허용 주소는 귀속 사용자(`user_id`)를 반드시 갖는다.** 그 값이 접수의 `created_by`가 되고, 없으면 승인까지 다 끝난 건이 발송 직전 `dispatch_no_owner`로 죽는다.
16. **⛔ POP3 로그인 실패는 백오프 대상이 아니다.** 3연속이면 폴링을 멈추고 경보를 보낸 뒤 **사람이 재개**한다(1분마다 재시도 = 계정 잠금).
17. **⛔ 중복 차단 집합에 `queued` 미도래를 포함한다.** 종결로 읽으면 아직 나가지 않은 예약과 같은 명단이 한 벌 더 접수된다(이중 발송).
18. **⛔ 회신은 발신 주소 ∧ 활성 허용 목록 교집합에만 보낸다.** 위조 메일에 답해도 진짜 소유자에게 가고, 우리가 백스캐터 반사판이 되지 않는다. 미등록·판정 실패에는 회신 0.
19. **⛔ 청구 계정(귀속) 후보가 여럿이면 자동 선택 0**(★0827 §20). 같은 주소는 여러 귀속에 등록될 수 있고(활성 UNIQUE = `(email_norm, user_id)`), 여럿이면 요청서 "청구 계정" 지정으로만 확정한다(`matchBillingTarget` · 표시명 또는 로그인 ID **정확 일치** · 부분 일치 금지). 지정 못 하면 반려(회신에 계정 목록). "기본 계정"을 만들면 지정을 깜빡한 건이 엉뚱한 계정으로 청구된다.
20. **⛔ 예약이 잡힌 뒤의 취소는 큐를 지우되 캠페인 상태는 그대로 둔다**(★0828 `queueOnly`). 대행발송 캠페인은 생성 51밀리초 뒤 적재를 끝내고 `completed`가 된다(예약 시각은 큐 행의 `sendTime`이 든다). 상태 게이트(`scheduled`·`draft`)를 그대로 두면 **예약이 잡힌 접수를 아무도 취소할 수 없다**(B-0828-1). 반대로 상태를 `cancelled`로 바꾸면 **이미 나간 발송이 청구에서 사라진다** — 청구 선택기가 `status='completed'`를 요구하고, 수량은 큐의 성공 행 수로 세기 때문에 상태를 두고 큐만 지우면 나간 몫은 청구되고 막은 몫은 0원이 된다.
21. **⛔ 막을 것이 없었으면 「취소됨」으로 적지 않는다**(★0828 `alreadySent`). 큐에 대기도 픽업도 0이면 이미 전량 나간 것이다. 그때 취소로 확정하면 **고객은 받았는데 화면은 취소**가 된다. 원래 상태로 되돌리고 「이미 발송이 끝나 취소할 수 없습니다」를 알린다. ⛔ 그리고 `inspectAttemptCampaign`을 고쳐 발송 종결을 `stopped`로 보게 만들지 마라 — 적재가 끝나도 큐가 남아 있으면 더 나가므로 `live`가 맞고, 바꾸면 워커 D가 취소 건의 큐 회수를 놓친다.
22. **⛔ 회신 상한에 걸려도 침묵하지 않는다**(★0828 B-0828-2). 요청서를 고쳐 다시 보내는 것이 정상 흐름인데 답이 없으면 사용자는 무엇이 잘못됐는지 알 수 없다. 상한은 ENV로 조이되(`AGENCY_MAIL_REPLY_RATE_PER_HOUR` · 0 = 무제한 기본) 상한에 닿은 첫 회차에는 그 사실을 한 통 알린다.
23. **⛔ 메일 MMS 이미지는 규격이면 그대로, 벗어나면 파일별 사유 반려. 변환하지 않는다**(★0828(2) 서수란 접수 `cmtclkuhe04iujnotbi3xbuu3` · Harold 확정). 이미지는 요청서와 **별도 첨부** 최대 3장(요청서 파일 안에 넣지 않는다). 규격 = **JPG 실체(SOI 바이트 판정 · 확장자·MIME 불신) · 장당 300KB · 3장**(`LIMITS` 재사용). 변환(파이썬 서비스)을 접수 경로에 들이면 그 서비스 장애가 접수 장애가 된다 · 큰 이미지의 출구는 화면 접수 라이브러리 변환 안내다. 요청서 "이미지 파일명" 칸은 **첨부가 있으면 무시**(순서 = 첨부 순서 · 접수 완료 회신이 순서를 고지 · 최종 확인 = 담당자 테스트 MMS)하고, **칸만 있고 첨부 0장이면 반려**(`image_not_attached`). 저장은 청구 계정 확정 뒤에만 하고 반려로 빠지면 그 자리에서 지운다. 코어에는 화면 접수와 같은 형태(절대경로 문자열 배열)로 넘긴다 = 발송·테스트 문자·청구 배관 무변경. 옛 "메일 = SMS·LMS만"(설계서 §18-3 9)은 이날 폐기.
