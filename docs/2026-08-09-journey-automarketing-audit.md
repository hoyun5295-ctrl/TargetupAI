# 여정 · 자동마케팅 전수점검 (2026-08-09) — 불변 원칙 ↔ 코드 대조

> **방식**: 코드를 처음부터 다시 훑지 않는다. 두 기능 문서에 적힌 **불변 원칙이 코드에서 실제로 강제되는지**를 항목별로 대조한다.
> 리뷰를 반복해도 결함이 남는 전형적 이유가 "원칙은 적었는데 강제 장치가 없어서"이기 때문이다.
> **이상 없음도 기록한다** — 다음에 같은 의심이 들 때 중복 노동을 막는다. 재점검은 코드가 바뀐 축만.

## §2 남은 점검 항목 (다음 세션)

### 여정
- **정답표를 갖지 않는다** — 트리거 가능 판정에 하드코딩된 조건이 없는지(`journey-trigger-capability.ts` 런타임 데이터 기반 확인)
- **문은 회사마다 하나** — 자사몰·싱크 두 문 중 하나만 진실로 삼는 판정
- **게이트는 활성화 길목에** — 자연어 생성 경로가 게이트를 우회하지 않는지

### 자동마케팅
- **모르는 값은 넓히지 않는다** — 권한·범위 해석의 fail-closed
- **회차 스냅샷** — 변화 축의 유일 근거가 스냅샷인지(§4 계약)

### 교차 (LESSONS 기반 위험 패턴)
- 기본값이 OFF인 보호에 안전을 기대는 곳
- 소스 스캔 테스트가 조건 반전을 못 잡는 곳(행동 테스트로 고정됐는지)
- 컬럼 별칭이 축 grep을 은폐하는 곳(0731 브랜드 표시 축 부류)
