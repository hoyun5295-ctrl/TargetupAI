## 1. 배포 정책

**검증된 조합만 내보낸다. 고객 환경이 정해지면 그 조합을 검증하고 등재한다.**

싱크에이전트 고객은 앞으로 늘어난다. 그래서 20조합을 미리 다 검증하는 것도, 미검증을 검증된 것처럼 화면에 내보이는 것도 답이 아니다. 검증을 **싸게** 만들어 조합이 생길 때마다 붙이는 쪽으로 간다.

- 검증 상태의 단일 진실원 = `packages/backend/src/utils/agent-build-tiers.ts` 의 `VERIFIED_COMBOS`. **키 = `<osTierId>__<dbId>__<version>`(2026-08-03 버전 스코프 전환)** — 검증은 버전 세대에 귀속되고, `CURRENT_AGENT_VERSION`과 일치하는 등재만 verified다. 비어 있으면 전부 `candidate` — fail-closed다. 에이전트 버전을 올리면 여기 상수도 함께 올린다(= 전 조합 자연 폐쇄 → 조합별 재검증 개방).
- 한 번 등재되면 빠지지 않는다(이력 주석 보존). 검증 집합은 세대별로 쌓인다.
- 슈퍼관리자 "싱크에이전트 배포" 메뉴는 **없애지 않는다.** 그 화면의 값은 다운로드 버튼이 아니라 OS → 티어 → 드라이버 판정이다(2008 R2에 node20 빌드를 보내는 실수를 막는 게 그 화면이다). **다운로드는 verified만**(서버 길목 403 게이트 `isPackageKeyVerified` — 2026-08-03 구현 완료), candidate는 화면에 "확인되지 않음 — 담당자 확인 후 개별 전달"로 표시된다.

## 2. 검증 도구

### 2-1. `--test-db` (1.6.5+)

비대화형·읽기 전용 DB 진단. 설치 마법사 Step 2·3과 **같은 커넥터**를 쓴다.

```bash
sync-agent --test-db --type mysql --host 10.0.0.5 --port 3306 --db shop --user readonly --pass-env DBPW [--ssl] [--ssl-ca /path/ca.pem] [--table members]
```

- 종료 코드 0 = 접속·테이블·컬럼 조회 성공 / 1 = 실패 / 2 = 인자 오류
- 마지막 줄에 `__TEST_DB__ {json}` — 파서는 이 표식만 본다(로그가 같은 콘솔로 나온다)
- **테이블 0개는 실패로 처리한다.** 붙었는데 아무것도 안 보이는 건 대부분 읽기 권한·스키마 지정 문제다. 성공으로 답하면 담당자가 엉뚱한 곳을 뒤진다.
- 비밀번호는 출력 어디에도 싣지 않는다. `--pass-env`로 프로세스 목록 노출도 피한다.
- 설정 저장·에이전트 기동·한줄로 API 호출을 하지 않는다.

현장에서도 쓴다 — 고객사에서 접속이 안 될 때 마법사를 다 타지 않고 한 줄로 원인을 본다.

### 2-2. `scripts/smoke-combos.sh`

배포되는 zip을 그대로 풀어 실제 DB에 붙인다.

```bash
bash scripts/smoke-combos.sh              # 전체
bash scripts/smoke-combos.sh --only linux # 부분
bash scripts/smoke-combos.sh --keep       # DB 컨테이너 남김
```

DB 컨테이너 기동(**127.0.0.1 바인딩 강제**) → 테스트 데이터 5행 → zip 해제 → `--version`으로 기동·버전 확인 → `--test-db` → 판정 → 정리까지 한다. `PASS`한 조합만 `VERIFIED_COMBOS`에 넣는다.

- **1.6.5 미만 바이너리는 SKIP된다.** 옛 exe에 `--test-db`를 주면 분기에 안 걸려 에이전트 본체나 마법사가 떠버린다 — 판정이 아니라 사고다.
- `mode=launch`(win-mid·win-legacy)는 이 PC가 대상 OS가 아니라는 뜻이다. **통과해도 그 티어를 검증한 게 아니다.**
- 전체 동기화·서비스 등록·재부팅 자동시작은 보지 않는다. 대상 OS VM 몫이다.

**왜 마법사를 몰지 않고 이걸 만들었나**: 설치 마법사는 node readline이라 답이 프롬프트보다 먼저 도착하면 그 줄이 리스너 없이 버려진다. 피더가 1.2초 간격으로 정확히 내보내도 실행마다 다른 자리에서 입력이 밀려 재현이 안 됐다(2026-07-28 실측).

## 3. 조합 현황

zip은 20개지만 **실제 바이너리는 5개**다 — 같은 티어의 4개 드라이버 zip은 내용이 동일하다(크기·이름 일치 확인). 드라이버 4종이 한 exe에 다 들어 있고 지연 require로 선택된 1종만 로드된다.

| 티어 | 검증 수단 | 상태 |
|---|---|---|
| `win-modern` | 이 PC(Windows 11) + 도커 DB. Server 2016 VM은 1.6.4 설치 검증 후 삭제(2026-08-03 Harold) — 재검증 필요 시 재구축 | mysql = 1.6.4 전체 통과. pg는 접속·조회까지 확인 |
| `linux-modern` | 도커(ubuntu:24.04, glibc 2.39) | mysql·pg 접속·조회 확인 |
| `linux-legacy` | 도커(centos:7, glibc 2.17 = 티어 바닥) | mysql·pg 접속·조회 확인 |
| `win-2012`(win-mid) | **Server 2012 R2 VM 필요** | 미검증 |
| `win-2008r2`(win-legacy) | **Server 2008 R2 VM 필요** | `win-2008r2__oracle-10g`만 2026-06-24 등재(당시 버전) |

**VM은 고객 단위가 아니라 OS 티어당 1대 상설 시험대다.** 두 대를 한 번 만들어두면 이후 모든 버전에서 스크립트만 돌리면 된다.

**드라이버 축 잔여**
- MSSQL — 이미지 확보 필요(`mcr.microsoft.com/mssql/server`). `mssql-2008 × modern 티어`는 코드가 이미 `blocked`(node20 OpenSSL3 × 옛 TLS)라 검증 대상이 아니다.
- Oracle — 로컬 이미지가 `gvenzl/oracle-xe:11-slim`(11g)뿐인데 11g는 thick이라 Instant Client가 있어야 붙는다. **레포에 IC가 없다.** IC를 확보하거나 12c 이상 이미지로 thin 검증을 해야 한다.

## 7. 폐기된 계획

- **20조합 전수 검증 후 일괄 배포** — 물량 대비 낭비. §1 정책으로 대체.

## 8. 반복하지 말 것

- 검증 → 빌드 순서를 뒤집지 않는다. 2026-07-27에 빌드·업로드·매뉴얼을 먼저 하고 나중에 VM 검증을 해서 전부 무의미해졌다.
- **"그 OS를 지원한다" ≠ "그 OS에서 우리 제품을 끝까지 쓸 수 있다".** 런타임 지원표는 exe가 뜨는지만 말해준다. 정적 리뷰로도 안 잡힌다 — "Server 2016 기본 브라우저가 IE11"은 코드에 없는 사실이다.
- **0건을 안전의 근거로 쓰지 않는다.** 조회 0건은 "문제 없음"이 아니라 "표본이 없음"일 수 있다. `--test-db`가 테이블 0개를 실패로 처리하는 이유가 이것이다.
- ⛔ **테스트 전화번호를 `010`+랜덤 8자리로 만들지 않는다.** 실가입 번호와 겹친다. 2026-07-27에 그렇게 만든 2만 건이 운영 PG에 유입됐다(삭제·잔존 0 확인). 형식만 지키고 값은 도달 불가한 대역으로, 건수는 최소로. `smoke-combos.sh`가 이 규칙을 코드로 강제한다(5행 고정·미할당 대역·`.invalid` 도메인).
