# 템플릿 등록 연동(구성안 1안) 진행 제안 — 검토 요청

> 발신: 인비토 (Harold)
> 수신: 강문희 이사님
> 일자: 2026-07-14
> 관련: 보내주신 "템플릿코드관리연동-구성안"(1안/2안) · QTmsg 사용설명서 4.0

이사님, 보내주신 구성안 1안·2안 잘 검토했습니다. 서수란 팀장 통해 매핑 목록과 절차 설명도 잘 받았습니다. 저희 내부 정리 결과를 공유드리고, 진행 방향에 대한 이사님 의견을 여쭙니다.

## 1. 진행 방향 (안)

**1안(API 연동)을 기본으로 진행하고자 합니다.** 이유는 두 가지입니다.

1. 기존 업체들의 발송 프로그램을 건드리지 않는 것이 가장 안전하다고 판단했습니다. 저희 쪽에서 확인해 보니 대부분의 업체가 "별도 작업 없이 사용" 전제로 연동되어 있어서, 2안(발송 시 senderkey 동봉)을 일괄 요구하기 어렵습니다.
2. QTmsg 매뉴얼(p.8~9)을 정독해 보니 알림톡의 공식 경로가 "중계서버 템플릿코드 매핑관리(우선순위 최상위)"로 안내되어 있어서, 이 정공법을 따르는 것이 맞다고 봤습니다.

2안(senderkey 동봉)은 폐기하는 것이 아니라, 발송 프로그램 수정이 가능한 신규 업체부터 점진 적용할 예정입니다. 두 방식이 병행되는 그림입니다.

기존에 엔진에 등록된 매핑들은 전부 그대로 유지합니다. 보내주신 매핑 목록 엑셀은 이관 후 대조 검증 기준으로 소중히 쓰겠습니다.

## 2. 저희가 준비하는 것

구성안 1안의 "템플릿연동요청 API프로그램" 역할을 저희 시스템이 맡습니다.
- 템플릿 등록·검수 승인 확인까지 저희 쪽에서 자동 처리하고, 승인 확정 건만 이사님 쪽 API로 매핑 등록을 요청합니다.
- 등록 후에는 조회 API로 실제 반영 여부를 재확인하고, 주기적으로 전체 매핑을 대조해서 어긋남이 없는지 점검하겠습니다. (사고 예방 차원의 저희 쪽 안전장치입니다)
- 삭제는 자동으로 호출하지 않습니다. 필요 시 사람이 확인 후에만 요청하겠습니다.

## 3. 이사님께 요청드리는 것

구성안 1안의 **API수신프로그램(입력/삭제/조회)** 개발입니다. 말씀하셨던 1.5일 범위 그대로이고, 아래 세부만 함께 확정하고 싶습니다.

1. **등록 = upsert(멱등)** — 동일 건이 이미 있으면 값 갱신 후 성공 응답으로 처리 가능할지요. 저희가 통신 장애 시 재시도를 하게 되는데, 중복 호출이 문제되지 않아야 해서요.
2. **조회 = BILL_ID 단위 전체 목록 반환** — 대조 검증용입니다.
3. **등록 항목 확정** — 저희는 BILL_ID, senderkey, 인비토코드(승인 템플릿코드), 외부템플릿코드, 외부모듈 5가지로 이해하고 있습니다. 54/58 서버 구분을 저희가 지정해서 보내는 게 맞을지, 수신측에서 판정하시는 게 맞을지 알려주시면 맞추겠습니다.
4. **반영 시점** — 등록 후 즉시 발송에 반영되는지, 엔진 재기동이 필요한지요.
5. **인증 방식** — API 키 + 저희 서버 IP 화이트리스트 정도로 생각하고 있습니다. 편하신 방식 알려주시면 따르겠습니다.

## 4. 확인 문의 2가지

1. **필드 명칭** — QTmsg 매뉴얼 기준으로 `k_template_code`, `k_etc_json`의 json 키 `senderkey`로 이해하고 있습니다. 구성안 자료의 `k_templ_code` / `senerkey` 표기와 달라서, 실제 엔진이 읽는 정확한 명칭을 확인 부탁드립니다. (오타 하나로 발송이 실패할 수 있는 부분이라 확실히 하고 싶습니다)
2. **알림톡 senderkey 동봉 통과 여부** — 매핑이 등록돼 있지 않은 상태에서 발송 데이터에 `k_etc_json` senderkey만 넣은 알림톡(K)도 출중계로 통과되는지요. 구성안 2안에 "54와 58 전부 DPK_HM은 이미 지원"이라 해주셨는데, 매뉴얼에는 친구톡 기준으로 기재되어 있어서 알림톡도 동일한지 확인차 여쭙니다. (신규 업체 온보딩에 쓸 예정입니다)

## 5. 검증 절차 제안 (돌다리 두들기기)

바로 전체 적용하지 않고 아래 순서로 확인하며 가겠습니다.

1. 테스트용 BILL_ID 1건으로: API 등록 → 조회 확인 → 알림톡 실발송 1건 → 결과코드 확인
2. 통과 확인 후, 신규 승인 템플릿부터 API 자동 등록 개시
3. 기존 등록분(4,159건)은 손대지 않고 그대로 운영
4. 저희 쪽 주기 대조 결과에서 어긋남이 보이면 바로 공유드리고 함께 확인

## 6. 여쭙는 것

- API수신프로그램 개발 착수 가능 시기와, 스펙 협의 방식(메일/통화) 편하신 쪽 알려주시면 감사하겠습니다.

항상 협조해 주셔서 감사합니다. 이 건만 마무리되면 143 서버 정리가 가능해져서, 이사님 쪽 유지 부담도 줄어들 것으로 기대합니다.
