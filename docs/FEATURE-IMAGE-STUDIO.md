## §2 불변 원칙 (어길 수 없는 것)

### 2-1. 템플릿 = 서버 은닉 프롬프트 스캐폴드다
`scaffold`(장면 지시)·`textStyle`(타이포 지시)은 **공개 API에 절대 포함하지 않는다**. `listTemplatesPublic()`이 내보내는 것은 `id·name·category·kind·desc·accent·exampleUrl·defaultTexts·sample`뿐이다. 고객은 "예시 스타일"을 고를 뿐 프롬프트를 보지 못한다 — 이것이 자유 프롬프트 도구와 우리를 가르는 축이다.

### 2-2. 문구는 사용자 지정 verbatim만 렌더한다
프롬프트 마지막 줄이 항상 "지정 문구 외 텍스트·가격·로고·QR·워터마크 일체 금지"다(인젝션 방어 겸용). 세일·혜택류 템플릿의 기본 문구는 `[혜택은 직접 입력해주세요]` placeholder이고, 카탈로그에 **브랜드 실명·혜택 수치(%·원·쿠폰·무료)를 쓰지 않는다.** 장면 힌트 칸에 혜택 패턴이 들어오면 힌트를 통째로 버린다(`hasBenefitPattern`).

### 2-3. 완성물의 색·형태가 바뀌면 안 되는 변환에 생성 모델을 쓰지 않는다
2026-07-21 실측 — 채널 비율 변환을 image-to-image로 했더니 검정 스커트가 흰색으로 다시 그려졌다. 생성 모델은 "비슷하게 다시 그리는" 것이라 원본 픽셀 보존이 원리적으로 불가능하다. **비율·크기 조정은 순수 이미지 처리(PIL 크롭·패딩)로만.** AI는 배경 생성·아웃페인팅처럼 새로 그려도 되는 곳에만.

### 2-4. 크레딧은 효과·저장이 성공한 뒤 마지막에 차감한다
`checkCredit`(사전 402) → `tryAcquireGenerateLock`(회사당 동시 1건·두 번째 409) → 생성 → 저장 성공 → **그 후에야** `deductCreditSafe`(멱등키 `image-studio:{uuid}`) → `finally` 잠금 해제. 실패 경로는 차감 도달 전이라 미차감(사용자 이득 방향)이다.

### 2-5. 화면 워터마크는 표시본에만 있고 원본은 무손이다
2026-07-21 신설 — 스크린샷 유출 억제용 CSS 오버레이(회사명·사용자명 대각선 반복)이며 DOM 레이어다. **저장물·발송물 원본에는 들어가지 않는다.** 같은 날 파일 다운로드는 폐기됐다(전 직원 요청 — 소재는 한줄로 채널로만 활용). 배치로 만든 예시 이미지도 원본이라 워터마크가 없다.

### 2-6. 생성 축은 `poster` 하나다
2026-07-30 확정 — 채널별 재생성(+크레딧) 축을 폐기했다. 생성은 3:4·2K 포스터 한 장이고, 인앱·DM·이메일·MMS는 저장된 그 한 장을 통짜로 쓴다(MMS만 서버가 1080px·300KB 이하로 변환). 옛 프리셋 4종은 호환용으로만 남아 있고 `resolvePreset` 폴백이 poster다.

### 2-7. 손익 지렛대는 "크레딧당 호출 수" 하나뿐이다
후보 장수를 줄여도 크레딧당 원가는 안 변한다(2장=2크레딧=2호출). 2026-07-30에 1장 생성·2크레딧으로 바꿔 크레딧당 호출 0.5회가 됐고, 그때 원가가 절반이 됐다. 수치·재검토 트리거 = `reference_image_studio_unit_economics`.

### 3-2. 문구 위치 축 (2026-08-09 신설)

`/generate` 요청의 `textPosition`(`top`·`center`·`bottom`)을 라우트가 화이트리스트로 검증하고, `buildPosterPrompt`가 지정 시 **세 신호를 한 목소리로** 낸다(0809(2) 실측 보강 — 최후미 규칙 한 줄만으로는 textStyle 상단 문구·장면 구도에 밀려 미준수였다. 같은 부류 2회 = 모순 제거가 뿌리 수정):
1. 스캐폴드 직후 — 그 위치에 문구용 조용한 구역을 비워 **구도부터** 잡게 한다.
2. textStyle은 "서체·무드 참고용, 위치 문구 무효"로 발언권을 박탈한다.
3. 최후미 FINAL LAYOUT RULE(부정형 포함)이 위치의 유일한 권한자다. 누끼가 있으면 제품 회피 지시 동반.

- 화면은 **행사 포스터에만** 칩 3개를 노출하고 **기본값 위**가 미리 선택돼 있다(0809 Harold 재확정 — 갤러리 예시가 상단 기준이라 첫 결과가 예시와 같은 구도로 나온다. 중앙·아래는 선택. 추가 입력 없이 그대로 생성 — 1클릭 규약).
- **위치를 바꾸면 구도도 함께 바뀐다** — 1번 신호가 그 자리를 비우게 하므로 예시와 다른 장면이 나오는 것이 정상 동작이다.
- 제품 포스터·예시 배치는 미전달이라 템플릿 기본 배치·프롬프트가 그대로다(회귀 0). 값 미지정·화이트리스트 밖이면 무시.
- 생성 모델 특성상 100% 보장은 아니다 — 실측: 중앙 미준수 2회(모순 제거 전) → 제거 후 중앙 통과. 재발 시 다음 층 = 생성 직후 위치 판독·1회 재생성 루프(미착수).

`kind` 생략 = `product`. 행사 트랙은 **제품 없이 성립**하고 누끼 첨부는 선택이다.

**0811 확장(+64)** = 뷰티 +10 · 패션 +10 · 세일·이벤트 +8 · 팝업·페스티벌 +8 · 데이·기념일 +8 · 시즌·명절 +6 · 멤버십 +6 · 오픈 +5 · 클래스 +3.

채울 축이 없는 곳에 숫자를 맞추면 유사 변형이 되고, 그건 고르는 사람의 시간만 쓴다.

### 4-1-A. 추천 용도(`useCase`) — 2026-08-11 신설 (Harold 지시)

`desc`가 **어떤 그림인지**를 말한다면 `useCase`는 **언제 고르면 되는지**를 말한다("고가 안티에이징·시그니처 스킨케어",
"11월 11일 빼빼로데이 기획전"). 249종을 하나씩 열어 보지 않고 고르게 하는 축이라 **전 항목 필수**이며, 갤러리 카드와
제작 화면 양쪽에 뜬다. 공개 필드(`listTemplatesPublic`)지만 **생성 프롬프트에는 안 들어간다** — `buildPosterPrompt`가
읽는 것은 `scaffold`·`textStyle`·`useSeason` 셋뿐이다(실측 확인).

### 4-2. 추가 규칙

- **데이터만 추가한다 — 코드 무수정.** 카테고리를 신설할 때만 `TemplateCategory` 유니온에 값을 더한다. 화면은 템플릿 데이터에서 카테고리 탭을 동적으로 만들기 때문에 **프론트 수정이 필요 없다.**
- **숫자 채우기 금지.** 항목마다 장면·소품·조명·타이포가 실제로 다른 아트 디렉션이어야 한다(Harold 확정). 추가 전 기존 카탈로그의 같은 카테고리를 전부 대조해 **빈 축**을 찾는다 — 겹치면 유사 변형이 된다.
- `sample`은 갤러리 카드에 노출되는 실카피다. **브랜드 실명·혜택 수치 0**(§2-2).
- **`useCase`는 전 항목 필수**(§4-1-A). 빈 값이면 그 템플릿만 고를 근거 없이 놓인다.
- `id` 중복 검사 의무: `grep -o "id: '[^']*'" <파일> | sort | uniq -d` 가 0줄.
- **★2026-08-11 계약 테스트로 자동화** = `backend/src/utils/image-studio-catalog.test.ts`. id 중복 · `useCase` 누락 ·
  은닉 필드(`scaffold`·`textStyle`) 공개 유출 · 금액/비율 표기 · 예시 문구의 혜택 약속 · 행사 카테고리 `kind` 정합 6건을 막는다.
  **금지 표기는 두 층으로 갈린다** — 수치(`%`·`원`)는 어디에도 못 쓰고, 혜택 단어(쿠폰·무료)는 **포스터에 새겨질 문구**
  (`sample`·`defaultTexts`)에서만 막는다. `name`·`desc`·`useCase`는 메뉴 라벨이라 "티켓 모양 디자인"을 그렇게 부를 수밖에 없다.
  그림의 모티프를 가리키는 말과 포스터에 새겨질 약속은 다르다.
- 카탈로그 일괄 치환 시 `{productName}` 토큰이 정규식 `[^}]*`를 깨서 오삽입된다 — 부분 치환 대신 해당 항목 전체를 다시 쓴다.
- 추가 후 예시 이미지는 §5 배치를 **다시 실행**하면 새로 추가된 것만 만들어진다.

## §5 예시 실샘플 배치 (슈퍼관리자 전용)

`POST /template-samples/generate` — **예시 파일이 없는 템플릿만** 골라 제품 없이 `sample` 카피로 1장씩 생성해 영구 저장한다. 크레딧 미차감(내부 원가만), 호출당 `limit` 1~5장(기본 2), 모듈 잠금으로 동시 실행 1건.

- **재실행이 안전하다** — 이미 만든 것은 대상에서 빠지므로 중복 비용이 없다. 중간에 끊겨도 같은 명령으로 이어진다.
- 응답의 `remaining`이 0이 될 때까지 반복 호출한다. 진행 중 재기동되면 그때 처리 중이던 1건만 실패한다.
- 실측 속도·원가 = 장당 약 20초·약 230원(2026-07-31 기준).
- 토큰은 슈퍼관리자 로그인으로 받는다. **super는 단일 세션**이라 이 로그인이 열어둔 관리자 화면을 로그아웃시킨다.
- **발급 절차·계정·호출 주소 = [OPS.md §8-B](../status/OPS.md)가 소유한다.** ★2026-08-11 — 여기에 그 링크가 없어
  매번 명령을 새로 조립하다 틀렸다(도메인으로 호출, 필드명 오기). 아래 스크립트의 `$TOKEN`은 §8-B로 받은 값이다.

```bash
TOKEN="[슈퍼관리자 토큰]"
while :; do
  R=$(curl -s -X POST https://hanjul.ai/api/image-studio/template-samples/generate -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"limit":2}')
  echo "$R"
  case "$R" in
    *'"remaining":0'*) echo "완료"; break;;
    *'"generated":[]'*) echo "생성 실패 반복 — 중단"; break;;
    *'"success":true'*) sleep 2;;
    *) echo "오류 응답 — 중단"; break;;
  esac
done
```

## §8 남은 것 (착수 원장)

- **인앱 웹 디자인 탭 단순화** — 컨트롤 13개 세로 나열을 3덩어리 + [세부조정] 모달로(Harold 지적, 0719부터 이월).
- **원샷 이식** — 구조화 판독→완성 흐름이 지금 DM에만 있다. 인앱·이메일로 확장.
- **판독 3축 확장** — 현재 내용·구조만 읽는다. 디자인 신호(색·무드)·이미지 역할까지 읽어 생성물에 자동 반영.
- **DM 상품 링크 입력 시 멈춤** — 미해결. 재현 정보 대기.
- **생성 멱등키가 서버 생성** — 응답 유실 후 클라이언트 재시도 시 이중 차감 가능(0719부터·0730 Codex 범위 밖 지적). 착수 판단 = Harold.
- **빈 기본틀 + 코드 렌더링 전환(검토안)** — 배경을 1회만 생성해 저장하고 문구는 `composeImage`로 그리는 방식. 위치 100% 통제·장당 원가 0·한글 무결이 장점. **0809 파일럿 판정 = 보류** — 위치·한글은 통과했으나 조판이 포스터 급 미달(서체 맑은고딕 1종·자간 제어 없음·배경 대비·소품 겹침, Harold 불합격). 재개 조건 = 무드별 무료 폰트 확충 + 조판 엔진 보강(자간·행간·그림자·배경 밝기 대비·텍스트 존) 후 재파일럿. 누끼형은 장면 통합(그림자·광원) 때문에 어차피 생성 유지가 맞다.

## §9 뒤집힌 판단 (다시 꺼내지 않기)

- **후보 2장 생성** — 같은 프롬프트·인자로 2회 호출한 것이라 레시피 차이가 없었다(좌우 선호는 우연). 0730에 1장으로 확정.
- **착용컷 배경 교체 분기** — 인물·장면 광원 불일치로 합성 티가 나는 구조 한계. 분기·감지 호출을 전부 폐기하고 "의류는 단독컷 권장" 안내 1줄로 대체(0719 실측). 옷만 추출(고스트마네킹)은 상품 왜곡 위험으로 영구 미도입.
