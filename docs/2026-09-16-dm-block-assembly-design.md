## §1 불변 원칙 (어길 수 없는 것)

1. **블록은 기존 섹션 타입이다.** 새 타입을 만들지 않는다. 조립 산출물은 지금 편집기가 저장하는 구조 그대로다.
2. **블록 창은 기존 섹션 편집기(27종)를 재사용한다.** 새 폼을 따로 만들면 편집기와 두 벌이 되어 한쪽만 고쳐진다(공용 편집기 원칙 = LESSONS_FRONTEND 2026-08-26).
3. **가격·할인율·링크는 코드가 싣는다.** AI 프롬프트를 지나지 않고, 쪽 이미지에도 새기지 않는다. 값이 바뀌면 이미지가 거짓말을 한다.
4. **자사몰 상품은 상품번호로 다시 읽는다.** 못 찾으면 "가격 확인 못함", 품절이면 제외하고 사유를 남긴다(AI 자동제작 불변 3 그대로).
5. **이미지 스튜디오 삽입은 기존 생성·저장 경로를 그대로 지난다.** 새 생성 엔진을 만들지 않는다. 크레딧도 기존 키(`image-studio-generate` 2)다.
6. **신규 크레딧 키 0.** 조립 자체는 AI 호출이 없어 무료다. 생성이 붙는 자리(이미지 스튜디오 2 · 카탈로그 쪽 합성 10)만 기존 키로 차감한다.
7. **DDL 0.** 넘김 효과는 `dm_pages.settings` jsonb에 키 하나(`effect`)를 더한다. 그 컬럼은 이미 `catalog` 키를 쓰고 있다.
8. **native dialog 0 · 모델명 0 · 1클릭.** 블록 추가 = 클릭 1회 + 창 1개. 중간 선택 단계를 만들지 않는다.
9. **효과를 켠 DM만 새 넘김 경로를 탄다.** 안 켠 DM은 지금 코드(브라우저 기본 스크롤)를 글자 그대로 지난다.
10. **기존 입구 제거는 이 축에 넣지 않는다.** 빠른 시작 12 시나리오의 폐기·축소는 사용량 SQL 결과를 본 뒤 별도 단계다.

## §3 상품 페이지 창 (자사몰 불러오기 · 직접 입력)

- 탭 2개. **자사몰에서 불러오기** = 기존 `ProductPickList`(AI 자동제작이 쓰는 부품)를 그대로 띄운다. 고른 상품은 상품번호로 재조회해 이름·가격·이미지·주소를 코드가 채운다.
- **직접 입력** = 이름·가격·주소·사진. 사진은 업로드 경로(`/api/dm/v/images/...`) 그대로.
- 몰 장애는 조립을 막지 않는다. 피커 값으로 카드를 만들고 "가격 확인 못함"을 표시한다.
- 상품 카드의 **보러가기**는 상품 주소를 그대로 쓴다. 상품이 없으면 그 버튼을 그리지 않는다.
- 카탈로그 쪽에서는 상품 정보가 이미지 밖 **칩**으로 붙는다(§5-3).

## §4 이미지 스튜디오 겹쳐 띄우기

- 헤드라인·설명·쪽 템플릿의 사진 자리마다 **"이미지 스튜디오에서 제작 후 삽입"** 버튼을 둔다.
- 누르면 블록 창 **위에** 스튜디오 창이 뜬다(z 규약 = 확인·차단 모달 z-[2000]보다 위, 새 티어 하나).
- 창 안 흐름은 기존 스튜디오와 같다. 템플릿 고르기 → 문구(블록에 이미 쓴 제목·부제 자동 채움) → 상품 사진(선택) → 만들기.
- 서버 경로도 기존 그대로다: `POST /api/image-studio/generate` → `compose` → `save`. 크레딧 `image-studio-generate` 2.
- 만들어진 이미지는 **라이브러리에 저장되고** 그 URL이 블록 props(`image_url`)에 들어간다. 즉 나중에 라이브러리에서 다시 쓸 수 있다.
- 실패하면 블록은 사진 없는 상태로 남는다. 조립이 막히지 않는다.

## §5 카탈로그 쪽 템플릿과 넘김 효과

### 5-1 쪽 템플릿 4종 (1단계 완료분)
- `utils/dm/dm-catalog-templates.ts` 신설 완료. 표지 · 상품 한 점 · 두 점 비교 · 마무리 안내.
- 자리 좌표, 줄 나눔, 말줄임, 합성기 글자 항목까지 순수 함수. 테스트 16건 통과.
- 합성 실행(사진 얹기 → 저장 → 공개 URL)은 2단계에서 `utils/dm-catalog-render.ts`로 낸다. 기존 `sales-outreach-catalog.ts`의 sharp·`composeImage` 사용법을 따른다.

### 5-2 쪽이 장이 되는 방식
- 합성 결과 이미지 1장 → `catalogPagesOf`(기존 공용 부품)로 장을 만든다. 장 자격(`isSwipeImagePage`)은 갤러리 1섹션·`list_1xN`·이미지 1장이므로 **그대로 통과**한다. 뷰어·책 펼침 무수정.

### 5-3 상품 칩
- 쪽 이미지에는 숫자를 새기지 않는다. 상품 정보는 갤러리 섹션 props에 **칩 배열**로 싣고 뷰어가 이미지 아래에 그린다.
- 칩 = 상품명 + 가격 + 주소. 값은 몰 재조회 결과.
- 장 자격 판정은 `images`와 `layout`만 보므로 props에 칩이 더해져도 책 펼침이 유지된다.
- 지금 PC 책 펼침에는 링크가 없다(아웃리치 기록의 알려진 한계). 칩이 그 자리를 함께 닫는다.
- 계약: `dm-property-contract`에 gallery 칩 등재 + 편집기↔발행 파리티 테스트.

### 5-4 넘김 효과 3종
- 저장: `dm_pages.settings.effect` = `'slide'`(기본) | `'flip'` | `'fade'`. 미지정 = `slide` = 지금 동작.
- 뷰어: `slide`면 현행 코드를 그대로 지난다(바이트 동일). `flip`·`fade`면 장 넘김을 자체 페이저가 맡는다.
- 자체 페이저가 지켜야 할 것: 손가락 끌기, 장 위치 복원(`--dm-vh` 재계산), 도달 장 기록(`updateCurrent`·`bumpSection`), 점 인디케이터.
- `flip`은 PC 카탈로그의 3D 장 뒤집기(`dm-cat-sheet`)를 한 쪽 모드로 재사용한다.

## §6 화면 구조 (조립 화면)

- 3열. 왼쪽 = 블록 팔레트(분류별), 가운데 = 폰 캔버스(실제 모습), 오른쪽 = 진행 상태와 완성 버튼.
- 블록을 누르면 캔버스에 얹히고 **창이 자동으로 열린다.** 창을 닫아도 블록은 남고 "내용 필요" 표시가 붙는다.
- 캔버스 블록은 마우스를 올리면 순서 변경·수정·삭제.
- **시작 세트** 4종(세일 한 판 · 신상 소개 · 이벤트 응모 · 매장 오픈)은 블록 3~4개를 한 번에 얹는다. 첫 블록 창이 바로 열린다.
- 오른쪽 상태 = 블록 수 · 내용 필요 수 · 상품 연결 여부. 카탈로그 모드면 넘김 효과 선택이 함께 뜬다.
- 저장은 기존 스토어 `save({silent:true})`. 발행 DM 자동저장 차단 가드는 그대로 지킨다.

### 6-2 시작 화면 최종 구성 (★0916 실물)
- 맨 위 카드띠 = **[AI 자동제작] [블록으로 만들기]**(기능 개방 회사만 · 옛 [직접 제작] 자리).
- 아래 패널("어떻게 만들까요") 두 열 = 좌: 한 줄 입력 → 더 정확하게(접힘 줄) → **자동 생성** / 우: **이미지로 불러오기 → AI 자동제작으로 만들기 → 완성 이미지로 만들기**(저장 소재 보조 줄) 스택. 마지막 카드가 남는 높이를 먹어 빈칸이 없다.
- 기능 미개방 회사는 오른쪽 스택 맨 위에 블록 카드가 한 줄로 붙는다(입구 소멸 방지).
- **사라진 것**: 빠른 시작 12 시나리오(카드·모달·표·일러스트) · 완성 슬라이드/카탈로그 DM 분리 타일 · 라이브러리 타일 · 옛 폰목업 썸네일. 기능이 사라진 것은 시나리오 생성 경로 하나뿐이고 그 API 는 남아 있다([B-0916-2](../status/BUGS.md)).
