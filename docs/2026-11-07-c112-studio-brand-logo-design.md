## §1 결정

- **D1 층 구조 = 바탕은 하나 · 합성은 두 자리에서만.** 생성 결과 = **바탕**(지금 그대로 kind `poster` 임시 그림 · `routes/image-studio.ts:196-207` · 시도 키 · 기억 계약 그대로 `:130` · `:228-233`). 로고를 얹은 그림은 ① **미리보기** `POST /layers` = 서버가 실제로 합성한 그림을 응답에 담아 돌려준다(임시 파일 쓰기 0 · 기억 0 · 0크레딧 · 표시용으로 줄인 JPEG) ② **저장** `POST /save` = 같은 합성 함수로 원본 크기 합성본을 만들어 그것을 저장한다 · 두 자리에서만 만든다. 합성 함수는 하나(결정적: 같은 바탕 · 같은 설정 · 같은 로고 파일 = 같은 그림). 임시 폴더에 합성본이 오래 남지 않으므로 짝 정리 · 바탕 잠금 · 합성본 가리키기가 필요 없다(Codex 설계 1R ① ② ④ 의 뿌리 = 합성본 임시 수명 · 그 수명을 없앴다).
- **D2 미리보기와 저장의 일치.** 미리보기 응답이 **확정 설정**(켜짐 · 모서리 · 크기 · 로고 키 = 캐시 파일 이름의 주소 해시)을 돌려주고 화면은 저장 때 그 값을 그대로 보낸다. 서버는 저장 때 모서리를 다시 재지 않는다(보낸 모서리 · 크기를 허용 목록으로만 검사). 로고 키가 지금 키와 다르면 409 `LOGO_CHANGED`(「브랜드 키트 로고가 바뀌었어요 · 다시 확인해 주세요」) → 화면이 미리보기를 다시 받는다.
- **D3 로고 저장 = 영구 이름은 바탕 id(지금 저장의 이름 규칙 그대로).** `/save` 요청에 `layers`(선택). 저장 전체 = 지금 저장 잠금(같은 임시 id 줄 세움 `routes/image-studio.ts:537`) 안 · 새 잠금 0. 지금 갈래 · 옛 MMS 갈래 본문(`:538-683`)은 그대로 두고 그 앞에 두 단계를 더한다.
  - **이름 규칙** = 지금 저장은 영구 파일 이름 = 저장한 임시 id(`moveTempToPermanent` `utils/image-studio.ts:874-886`)이고 모든 복구가 이 이름으로 찾는다(서버 `findPermanentByTempId` `:892-902` · 화면 `findSavedStudioAsset` `lib/studio-api.ts:52-57`). 로고 합성본도 **`{바탕 id}.jpeg`** 로 영구 자리에 바로 쓴다(그 폴더 안 임시 이름에 쓰고 이름 바꾸기 · 임시 폴더를 거치지 않는다 · 바탕 그림과 폴더가 달라 부딪히지 않는다). → 7일 스윕 뒤 · 응답 유실 뒤 · 바탕을 지운 뒤의 재요청도 지금 「임시 파일 없음」 판정(`routes/image-studio.ts:563-579`)과 화면의 409 뒤 찾기가 손대지 않은 채 그 소재를 찾는다(Codex 설계 4R). 표식 칸 · 해시 고정 id · savedAs 쓰기 = 없음(`TempMeta` 무변경).
  - **1단계 = 남은 바탕의 영구 파일 확인(켜짐 · 꺼짐 갈래 나누기 전 · 모든 저장 요청)**: 바탕 그림이 아직 있고 그 바탕 id 의 영구 파일도 있으면(= 앞선 로고 저장이 등재 판정 「모름」 · 바탕 지우기 실패로 멈춘 자리) 그 주소의 소재를 조회한다 → 있음 = 남은 바탕을 지우고 그 소재를 돌려준다(바탕 하나 = 소재 하나 · 다른 설정 · 끔 재요청도 같은 소재 · Codex 설계 3R ① ② ) / 없음(조회 성공 · 0행) = 켜짐 요청이면 2단계가 그 이름에 덮어쓰고 · 끔 요청이면 그 파일을 지운 뒤 지금 갈래로 / 조회 실패 = 503(파일 · 바탕 그대로).
  - **2단계 = 로고 켜짐 갈래**(바탕 그림이 있고 확정 설정이 있을 때 · 바탕이 없으면 지금 갈래 그대로 = pendingAsset · savedAs · 영구 파일 단건 판정 · 끔 · 확정 설정 없음 = 지금 갈래 그대로 바탕 저장): 지금 로고 상태 · 키(쓸 수 없음 = 409 `LOGO_UNAVAILABLE` · 키 다름 = 409 `LOGO_CHANGED`) → 합성(원본 크기 · JPEG 92 · 메모리) → 저장 용량 검사(초과 = 409 STORAGE_FULL · 아무것도 안 남김 · 바탕 그대로) → `{바탕 id}.jpeg` 영구 쓰기 → **등재 판정 = 지금 저장 갈래의 판정(등재 → null 이면 주소로 다시 확인 → 있음 · 없음 · 모름 `:636-654`)을 CT 함수 하나로 잘라 옮겨 두 갈래가 같이 쓴다**(지금 갈래 동작 불변) → 있음 = 바탕 그림 · 사이드카를 지우고 그 소재(지우기 실패 = 경고 로그 · 다음 요청이 1단계에서 마무리) / 없음 = 영구 파일을 지우고 바탕을 남긴다(503) / 모름 = 파일 · 바탕 그대로 503(다음 요청 = 1단계).
  - 불변: 한 바탕의 저장본은 늘 `{바탕 id}.*` 한 자리 → 같은 설정 · 다른 설정 · 끔 · 응답 유실 · 스윕 뒤 어떤 재요청도 두 번째 소재를 만들지 못하고 기존 판정으로 그 소재를 찾는다. 등재되지 않은 채 스윕까지 남은 영구 파일 1장은 지금 pendingAsset 갈래와 같은 성질(§10).
  - 옛 MMS 꼴(채널 사양 mms)에서는 로고를 합성하지 않는다(지금 화면은 채널 사양을 보내지 않고 생성 사양 = poster `:582` · `image-studio.ts:158`) · 옛 MMS 갈래의 「바탕을 먼저 지우고 savedAs」 순서는 지금부터 있던 길이라 범위 밖(§10).
  - **화면 = 저장값**: 저장이 성공하면 두 결과 화면이 카드 그림을 저장된 소재 주소(실물)로 바꾼다(미리보기 · 저장본이 갈렸으면 그 자리에서 보인다).
- **D4 로고 원본 = 브랜드 키트 `logo_url` 하나**(진실 한 곳 · `dm-brand-kit.ts:83-95` `getCompanyBrandKitRaw`). 처음 쓸 때 한 번 안전하게 바꿔 회사별 캐시(`uploads/studio-logos/{회사}/{주소 해시}.png`)에 둔다. 주소가 바뀌면 새로 만들고 그 회사의 옛 캐시를 지운다.
  - 읽는 길: 우리 저장본(`dmImageLocalPath` · `inappImageLocalPath`)은 **그 파일이 이 회사 폴더 바로 안일 때만** 디스크에서 읽는다 · 그 밖의 `https` 주소 = `fetchImageGuarded`(사설 주소 차단 · DNS 고정 · 리다이렉트 거부 · 10MB · `sales-outreach-produce.ts:224`) · 그 밖(http · data · 상대 주소 · 다른 회사 저장본) = 쓸 수 없음.
  - **안전 변환(한 함수 · D11 도 같은 함수)** = sharp metadata 로 형식 판정(png · jpeg · webp 만 · svg · ico · gif 등 = 쓸 수 없음) · 입력 픽셀 상한 2,500만(제품 묶기와 같은 상한 `image-studio.ts:334`) · 1024px 안으로 줄인 PNG(알파 유지 · 줄이기만) · 원본 폭 60px 미만 = 쓸 수 없음(「너무 작아요」 · 홈페이지 로고 거르기와 같은 하한 `brand-page-reader.ts:232`).
- **D5 크기.** 작게 · 보통 · 크게 = 포스터 폭의 12% · 18% · 24%(디자인 값 · `studio-zones.ts`) · 높이 상한 = 포스터 높이의 6% · 9% · 12% · **원본보다 크게 키우지 않는다** = 목표 폭이 캐시 로고 폭보다 큰 크기는 고를 수 없다(칩 꺼짐 + 이유 「원본 로고가 작아 이 크기는 흐려져요」) · 작게는 늘 고를 수 있고 로고가 더 작으면 원본 크기로 · 기본 = 보통(못 고르면 작게).
- **D6 자리.** 모서리 4(왼쪽 위 · 오른쪽 위 · 왼쪽 아래 · 오른쪽 아래) · 여백 = 포스터 폭의 4% · 글 없는 판(인앱 글 얹기 장 · `StudioMake.tsx:184` 아래 비움)은 아래 두 모서리 금지(아래 1/3 = 인앱 글 자리) · **기본 모서리 = 허용 모서리 가운데 그 포스터의 로고 자리가 가장 조용한 곳**(회색 밝기 표준편차가 가장 작은 곳 · 미리보기 때 서버가 그림마다 잰다 · 같으면 왼쪽 위 · 오른쪽 위 · 오른쪽 아래 · 왼쪽 아래 순) · 사람이 고르면 그 값.
- **D7 판.** 로고와 그 자리의 대비가 WCAG 비텍스트 대비 3:1(SC 1.4.11)에 못 미치면 로고 뒤에 둥근 판을 깐다. 자리 밝기 = 그 자리 회색 밝기의 하위 10% · 상위 10% 두 값 · 둘 중 하나라도 3:1 미만이면 판(어수선한 자리 = 밝은 곳 · 어두운 곳이 섞여 걸린다). 로고 밝기 = 불투명 화소(알파 128 이상) 평균. 판 색 = 흰색 · 짙은 남색 가운데 로고와 대비가 큰 쪽 · 사용자 선택 0. 판 여백 · 둥글기 · 불투명도 = 디자인 값.
- **D8 기본값 켜짐(Harold 1107).** 생성이 끝나면 공용 훅이 곧바로 미리보기(켜짐 · 모서리 자동 · 크기 기본)를 부른다(0크레딧). 키트에 쓸 수 있는 로고가 없으면 서버가 로고 상태(없음 · 쓸 수 없음)만 돌려주고 화면은 바탕 그림 + 그 상태를 그린다. 미리보기 실패 = 바탕을 보여 주고 「로고를 얹지 못했어요 · 다시 얹기」 · 확정 설정이 없는 카드 = 끔으로 저장된다(화면에 보이는 그대로).
- **D9 끄고 켜기 · 모서리 · 크기 = 결과 화면의 같은 부품 하나**(`StudioLogoControls` · 스튜디오 결과 카드 · DM 삽입 창 결과 단계 · 두 화면 소스 계약). 표시값 = 서버가 돌려준 확정 설정(LESSONS_FRONTEND 「토글 표시 = 실제 동작」). 저장 전 카드만 · 저장한 카드 = 줄 대신 「저장한 포스터는 로고를 바꿀 수 없어요 · 바꾸려면 다시 만들어 주세요」. 결과 카드 아래 안내 = 「로고는 저장하기 전까지 · 만든 지 7일 안에 바꿀 수 있어요」. 미리보기 · 저장 중에는 화면 처리 막(지금 `busyMsg` 오버레이)이 저장 · 넣기 · 채널 · AI 수정 · 로고 칩을 함께 막는다.
- **D10 AI 수정.** 화면이 카드의 바탕 id 로 `/edit`(지금 그대로 · kind 판정 `:276`) → 새 바탕 → 공용 훅이 그 카드의 확정 설정(켜짐 · 모서리 · 크기) 그대로 미리보기 → 새 카드(같은 자리에 로고 · 옛 카드는 그대로 남는다 · 지금과 같음).

## §3 계약(새 · 바뀐 끝점)

**`POST /api/image-studio/layers`** 요청 `{ baseTempId: uuid, logo: { on: boolean, corner?: 'tl'|'tr'|'bl'|'br'|null, size?: 's'|'m'|'l'|null }, textless?: boolean }`
- 응답 200 `{ success, logo: LogoView, preview: string | null }` · `preview` = 합성 그림(data URL · JPEG · 폭 1080 이하로 줄임) · null = 끔 · 로고 없음 · 쓸 수 없음(화면은 바탕 그림 그대로).
- `LogoView` = `{ state: 'ready', on, corner, size, key, plate, corners: 허용 모서리[], sizes: [{ id, ok, reason? }] } | { state: 'none', homepage: string|null } | { state: 'unusable', reason: 'format'|'small'|'fetch' }`.
- 400 = 꼴 오류(id · 모서리 · 크기 화이트리스트 밖 · 글 없는 판에 아래 모서리 · 고를 수 없는 크기) · 404 = 바탕 없음(만료 · 저장됨 · 다른 회사 · kind 다름) · 502 `LAYER_FAILED`(「로고를 얹지 못했어요. 다시 눌러 주세요.」).
- 크레딧 0 · 임시 쓰기 0 · 잠금 0.

**`POST /api/image-studio/save`** 요청에 `layers?: { logo: { on, corner, size, key }, textless? }` 를 더한다(없으면 지금 그대로).
- 켜짐 = 허용 목록 검사(400) → D3 순서(1단계 남은 바탕의 영구 파일 확인 → 바탕 없음 = 지금 판정 → 로고 상태 · 키 409 `LOGO_UNAVAILABLE` · `LOGO_CHANGED` → 합성본 `{바탕 id}.jpeg` 저장).
- 응답 · 그 밖 코드 = 지금 그대로(STORAGE_FULL · ALREADY_SAVED · ASSET_REGISTER_* · DB_MIGRATION_PENDING).

**`POST /api/image-studio/logo/read`** 요청 `{ url }` · 응답 200 `{ success, logo: LogoView, saved: boolean }`(saved = 키트를 채웠는가 · 이미 차 있었으면 false + 그 상태) · 400 `field: 'url'` · 422 `LOGO_NOT_FOUND` · 422 `READ_FAILED`.

**`POST /api/image-studio/edit`** 계약 그대로.

**화면 공용** = `useStudioMake.generate()` 가 바탕을 받은 뒤 미리보기(켜짐)를 부르고 `StudioMade` 에 `logo` · 미리보기 그림을 더한다 · 새 `relayer(baseTempId, next, textless)` · `readLogo(url)` · `saveStudioTemp(tempId, title, layers)`(두 화면 · 채널 버튼 · DM 넣기가 같은 함수 · `lib/studio-api.ts:60`).

## §5 시험

**행동 시험(backend vitest · sharp 로 그림을 만들어 잰다)**
1. 구역 표 순수: 글 없는 판 = 위 두 모서리만 · 자리 상자가 포스터 안 · 원본보다 크게 안 함 · 높이 상한.
2. 합성: 흰 바탕 + 어두운 로고 = 판 없음 · 회색 반반 바탕 = 판 있음 · 결과 크기 = 바탕 크기 · 로고 화소가 고른 모서리에 있다 · 같은 입력 두 번 = 같은 바이트.
3. 기본 모서리: 세 모서리를 어수선하게 만든 바탕 = 조용한 모서리 · 글 없는 판이면 아래가 조용해도 위에서.
4. 크기 칩: 캐시 로고 폭 100 · 포스터 폭 1000 = 작게만 ok.
5. 로고 저장(라우트가 부르는 CT 함수 단위 · 소재 조회 · 등재 · 용량은 주입): 켜짐 = 영구 파일 이름 = `{바탕 id}.jpeg` · 크기 = 바탕 크기 · 로고 화소 있음 · 등재 모름 503 뒤 = 같은 설정 · 다른 설정 · 끔 재요청 모두 두 번째 등재 0(소재 있음 = 그 소재) · 0행 확정 = 켜짐은 덮어써 등재 · 끔은 그 파일을 지우고 바탕 저장 · 바탕 지우기 실패 = 다음 요청이 1단계에서 마무리 · 바탕이 지워진 뒤(스윕 · 성공 뒤) 재요청 = 지금 판정이 `{바탕 id}` 로 그 소재 · 화면 `findSavedStudioAsset(바탕 id)` 가 그 소재를 찾는다 · 미리보기 = 임시 폴더 파일 수 변화 0.
6. 로고 원본: 다른 회사 저장본 주소 · 폴더 밖 경로(`..`) = 쓸 수 없음 · svg · gif = 형식 · 2,500만 화소 넘는 그림 = 디코드 전 거절 · 폭 59 = 작음 · 주소가 바뀌면 옛 캐시 지움 · 같은 주소 = 다시 안 받음.
7. 홈페이지 읽기(가짜 HTML · 가짜 가져오기 주입): img logo 가 apple-touch-icon 보다 먼저 · gif · 큰 화소 · 흰 로고 · 작은 그림 = 사본 저장 전에 건너뜀 · 키트가 이미 차 있으면 읽기 · 쓰기 0.

**실 PG 시험**(`npm run test:pg`) = `setBrandKitLogoIfEmpty`: 빈 키트(NULL · `{}` · logo_url 빈 글) = 채움 · 이미 차 있음 = 그대로 + false · 다른 키(색 · 서체) 보존.

**화면 순수 함수**(frontend `lib/studio-layers.ts` · backend vitest 가 import) = 로고 줄 보기(저장됨 · 없음 · 쓸 수 없음 · 준비됨) · 칩 목록 · 미리보기 요청 몸 · 저장 layers(확정 설정이 있을 때만 켜짐) · 조건 뒤집기 주입 시 실패.

## §7 직원 시트(C112-S1 · 동작 · 볼 결과만)

1. 브랜드 키트에 로고가 있는 회사로 이미지 스튜디오에서 포스터를 만든다 → 결과 포스터 모서리에 회사 로고가 보인다 · 크레딧은 2만 줄었다.
2. 결과 카드의 로고를 끈다 · 다시 켠다 · 모서리를 오른쪽 아래로 · 크기를 크게로 바꾼다 → 바꿀 때마다 그림이 바로 바뀐다 · 크레딧은 그대로다.
3. 「라이브러리에 저장」 → 저장한 그림이 결과 카드에 보이던 그대로(로고 자리 · 크기)다 · 카드에 「저장한 포스터는 로고를 바꿀 수 없어요」가 보인다.
4. 로고가 있는 포스터에서 「AI 수정」(예: 더 밝게) → 새 포스터에도 같은 자리에 로고가 있다.
5. 모바일 DM 편집기 → 사진 블록 → 이미지 스튜디오로 만들기 → 결과에 로고 줄이 보이고 끄고 켤 수 있다 → 넣기 → 블록 사진에 로고가 있다.
6. 인앱 메시지 → 글 얹기 장 → 스튜디오로 만들기 → 로고 모서리에 아래 두 칸이 없다.
7. 브랜드 키트에 로고가 없는 회사 → 결과 카드에 「브랜드 키트에 로고가 없어요」 → 회사 홈페이지 주소 → 「읽어 와서 브랜드 키트에 저장」 → 로고가 얹힌다 · AI 메모리 › 브랜드 키트에 그 로고가 들어 있다.
8. 3번에서 저장한 포스터로 MMS 를 보낸다(라이브러리에서 첨부) → 받은 MMS 그림에 로고가 있다.
