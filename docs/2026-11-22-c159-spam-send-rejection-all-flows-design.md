# C159 접수 거절 사유를 스팸 검사를 쓰는 전 기능에 표시 — 설계서

> ★ 2026-11-22 · C158(BUGS B-1122-3)의 범위 밖 첫 줄을 닫는다 · Harold 「시작해」(「거절 사유를 다른 기능에도 표시하는 구현을 지금 시작할까요?」에 대한 답)
> 뿌리 = R7(판정 못 함을 반대로 읽음) 넓힘 · 카드 = STATUS-FEED C159 · 원장 = C159-H1

## 0. 접수와 지킬 것

- 접수 = C158 은 접수 거절(차단된 URL 9407 등)을 대행발송에서만 반려 + 사유로 바꿨다. 자동마케팅 · 플래너 · 자동발송 · 여정 · AI 한줄로 · 제안 체험은 같은 일이 나면 「검사를 마치지 못했어요」로만 말하고, 장애로 보아 같은 글을 다시 검사한다.
- 미가입 · 직접발송만 쓰는 회사 = 동작 변화 0. 증명: 바뀌는 자리는 ① 자동 검사 공용 입구(autoSpamTestWithRegenerate 의 runOneTest) ② 여정 사전 검사의 결과 기다림 ③ AI 한줄로 칩 보기(spamCheckView)의 덧칸 하나 ④ 반려를 말하는 문장들. 직접발송 화면의 검사(수동 검사 주소 · judgeSpamVerdict · 결과 창)와 발송 경로는 손대지 않는다. 사람 검사 결과 창은 이미 「보내기 전에 막혔어요: 차단된 URL」을 보여 준다(0929).
- 값 범위는 그대로: `spamTestOutcomeOf` · `readSpamTestOutcome` · `judgeSpamVerdict` 가 내는 값(통과 · 차단 · 확인 중 · 검사 중 · 장애)은 바꾸지 않는다. 같은 날 재사용 · 엿보기 · 늦은 보고 회복 · 보류 감시가 그 값으로 흐름을 정한다(접수 거절로 끝난 검사 = 장애 = 다시 누르면 새 검사 = 운영자가 차단을 푼 뒤 바로 통과할 수 있다 · 1122 실측의 그 길).

## 2. 설계 결정

- **D1 판정 한 곳 = `spamGatewayRejectionOf`.** 조건을 조인다(설계 Codex 1R #1): 그 검사의 결과 행 **전부**가 발송 실패이고 그 코드가 전부 문안 사유 접수 거절일 때만 사유를 낸다. 통과 · 시간 초과 · 확인 중 행이 하나라도 섞이면 null(늦게 도착할 수 있는 문자가 남은 검사는 접수 거절로 굳히지 않는다 · 종전 판정 · 종전 늦은 보고 보호 그대로). 문안은 통신사마다 같으므로 문안 사유 거절은 행 전부에서 난다. 돌려주는 값을 반려 문장의 정본 꼴로 바꾼다: `검사 문자를 보내지 못했어요: {사유}.` 글자 반려(C109)의 `문자로 보낼 수 없는 글자가 있어 검사하지 않았어요: {위치}`와 같은 뼈대(머리 + `: ` + 내용 · 접수 거절은 끝에 마침표). 날것으로 그리는 자리(자동발송 사유 · 제안 카드)가 그대로 읽히고, 제 말투가 있는 자리는 사유만 뽑아 쓴다(`spamSendRejectionReason`).
- **D2 자동 검사 공용 입구에서 반려로.** runOneTest 가 검사 완료 판정이 failed 일 때 D1 을 불러, 사유가 있으면 `spamResult: 'rejected'` + `rejection`(정본 문장)으로 돌려준다. C109 가 만든 반려 갈래(다시 검사 0 · 재생성 0 · 저장 = SpamCheckRecord)를 그대로 탄다 → 대행 · 자동발송 · 자동마케팅 · 플래너 · 제안 체험이 한 번에. 사유는 안별 결과까지 실어 보낸다(설계 Codex 1R #2): 지금 고리는 등록이 실패한 갈래에서만 반려 문장을 옮긴다 → 판정이 rejected 이면 등록 성공 갈래에서도 옮긴다(안마다 도는 고리 · 첫 통과에서 멈추는 고리 둘 다). 대행발송의 「검사 뒤 장애」 자리에 달았던 자체 사유 읽기(C158)는 지운다(공용 입구가 한다 · 보류 묶음 갈래의 읽기만 남는다).
- **D3 저장된 검사를 읽는 두 자리.** 여정 pollSpamResult = 결과가 장애이면 D1 → 사유가 있으면 판정 rejected + 사유. AI 한줄로 spamCheckView = 상태가 결과 없음(warn)이면 D1 → 사유를 덧칸(`rejection`)으로. 그 검사는 늦은 보고로 고쳐지지 않으므로 `lateOpen` 은 false 로 낸다(이어 읽기 · 같은 날 재사용에 묶이지 않는다 = 다시 누르면 새 검사).
- **D3-2 보류로 남겼다가 닫힌 검사(설계 Codex 1R #3).** 검사 줄이 길어 기다림(pending)으로 돌아간 검사는 나중에 닫힌다. 대행 = 보류 묶음 갈래의 읽기(C158). 자동마케팅 = 보류 회복(recoverHeldProposals)이 그 회차를 종결할 때 **안마다** 본다(설계 Codex 2R — 회차 결말을 합친 뒤에 보면 다른 안이 차단인 회차에서 사유가 사라진다): 다시 읽은 결과가 장애인 검사마다 D1 → 사유가 있으면 그 안의 결과를 반려 + 사유로 적는다(안별 결과 갱신 함수 refreshHeldResults 가 반려 값도 받는다 · 종결 표식과 같은 문장으로 저장). 회차 결말의 차례는 그대로다(통과 > 기다림 > 차단 > 그 밖). 안내 문장만, 결말이 「그 밖」이고 반려 안이 있으면 사유 문장으로 낸다(「결과를 받지 못해」가 아니다). 결말이 차단이면 안내는 차단 문장 그대로이고 그 안의 카드에 반려 + 사유가 보인다.
- **D4 값 범위 · 재사용 무변경.** `readSpamTestOutcome` 은 건드리지 않는다(트랜잭션 연결로 불리는 자리가 있어 그 안에서 MySQL 을 읽지 않는다). D1 은 말하는 자리 가까이에서만 부른다(다섯: runOneTest · 대행 보류 갈래 · 자동마케팅 보류 회복 · 여정 기다림 · 칩 보기).
- **D5 반려를 말하는 자리 = 글자 반려와 접수 거절을 가른다.** 판정 = `isCharsRejection`(C158) 하나. 글자 반려 문장은 한 글자도 바꾸지 않는다.
- **D6 9401 · 9402 도 접수 거절 갈래.** 위치를 모르는 반려라 글자 반려 문장(위치 포함)으로 바꾸지 않는다.
- **D7 반려는 사람 판단.** 접수 거절은 같은 글이면 같은 결과다(차단은 운영자가 풀어야 풀린다). 회차마다 새로 검사하는 흐름(자동발송 · 자동마케팅 회차 · 여정 하루 검사)은 다음 회차에 저절로 다시 본다. 잠그는 흐름(플래너 발송 당일 · 대행)은 사람이 다시 진행한다.

## 4. 시험

- 단위(순수): 정본 문장 만들기 · 사유 뽑기 왕복 · 글자 반려 판정 · 말하는 함수들(자동마케팅 · 플래너)의 두 갈래 문장 · 칩 글 · 안내 줄.
- 순수: 결과 행 전부의 코드를 받는 판정 — 실패 셋 전부 9407 = 사유 · 실패 9407 + 통과 = null · 실패 9407 + 시간 초과 = null · 행 0 = null.
- 동작: 공용 검사 고리 둘(안마다 · 첫 통과에서 멈춤)에 「등록 성공 + 반려 + 사유」를 돌려주는 가짜 검사를 넣어 안별 결과에 사유가 그대로 남는지(글자 반려 기본 문장으로 덮이지 않는지).
- 순수(자동마케팅 보류 회복): 안별 결과 갱신 — A 안 차단 + B 안 장애(접수 거절 사유 있음) = A 차단 그대로 · B = 반려 + 사유(검사 중으로 남지 않는다) · 회차 결말 = 차단(차례 그대로) / A 없이 B 만 = 결말 「그 밖」 + 안내가 사유 문장 / 사유 없는 장애 = 종전 값 그대로.
- 계약(구문 트리): runOneTest 의 failed 갈래가 D1 을 부르고 반려로 돌려준다 · 대행 runSpamRound 의 「검사 뒤 장애」 자리에 자체 읽기가 없다(보류 갈래에만) · D1 을 부르는 자리 = 다섯 · 반려 문장을 글자 문장으로 고정해 말하는 자리 0(반려 갈래 안에서 `plannerCharsReason(spamRejectionPlaces(` · `operatorCharsReason(spamRejectionPlaces(` 를 직접 부르지 않는다) · `readSpamTestOutcome` 본문에 MySQL 읽기 없음.
- 실 PG: 칩 보기 — 세 통신사 행이 failed 인 닫힌 검사에서 큐 행을 못 읽으면(시험 환경 = MySQL 없음) 덧칸 null · lateOpen 은 기존 값(종전 그대로)임을 본다.
- 화면: 미리보기에서 칩 글 폭 320 ~ 1920(가장 긴 사유 = 9407).

## 5. 배포

- DDL 0 · ENV 0 · 백엔드 + 프론트 · 원장 C159-H1(dist grep · 재시작) · S1 = 자연 발생 때(접수 거절 건의 자동발송 사유 · 제안 사유가 사유 문장으로 남는지).

## 6. 직원 지시문(배포 뒤 · 자연 발생이 없으면 생략)

1. 사내 계정의 AI 한줄로에서 차단 목록에 올려 둔 시험 주소가 든 문안으로 스팸 검사를 누른다 → 칩에 「보내지 못했어요」와 사유가 보인다(「결과 없음」이 아니다).
2. 링크가드에서 그 주소를 푼 뒤 같은 카드에서 다시 검사를 누른다 → 새 검사가 걸리고 통과한다.

## 7. 범위 밖(기록만)

- 결과 표에 거절 코드 칸을 두는 것(지금 = 큐 행이 남아 있는 동안만 읽힌다).
- 문안 탓이 아닌 접수 거절(9404 · 9405 · 9406 · 9408 · 9409)의 안내.
