## 3) 불변 원칙

1. **⛔ 코드가 강제하지 못하는 정의는 만들지 않는다.** 요금제 이름·크레딧 숫자·버튼 라벨을 정의에 **문자열로 적지 않는다.** 요금제 가부는 런타임 `canUseFeature` 판정으로만 말하고, 크레딧은 키 참조로 두고 렌더할 때 `getCreditCost`로 숫자를 만든다. 최근 3개월에만 요금제 경계가 세 번 움직였다(0720 · 0814 · 0822).
2. **⛔ 봇 컨텍스트에 들어가는 것은 이 카탈로그의 공개 필드뿐이다.** `docs/FEATURE-*.md`도, 화면 문구도, 내부 문서도 넣지 않는다(2-4).
3. **⛔ 매칭 실패면 AI를 호출하지 않는다.** 폐집합이라 지어낼 재료가 없는 것이 환각 차단의 1층이다. "모릅니다"가 틀린 답보다 낫다.
4. **⛔ 게이트는 필요조건이지 충분조건이 아니다**(2-10). 게이트가 건너뛰어진 기계에서도 제품이 거짓말하지 않게 **런타임 2층**을 함께 둔다: 응답 조립 직전에 경로 실존을 다시 확인하고, 없으면 버튼을 그리지 않는다.
5. **정의가 없는 기능도 목록에는 있다.** 미작성은 빈칸(stub)으로 **전수 등재**하고 만료일을 준다. 그래야 역방향 게이트가 첫날부터 전수로 켜지고, 봇이 "모릅니다" 대신 "이 기능은 여기서 시작합니다"까지는 답한다.
6. **정의는 한 벌이다.** 봇과 안내 화면(`/guide`)이 같은 원장을 읽는다. 화면에만 있고 봇은 모르는 설명이 생기면 그것이 결함이다.
7. **⛔ 봇이 회사 데이터를 답하지 않는다**(1단계). 수치 질문은 기존 AI 설명 화면이 소유한다. 어제 회사 격리 실사고가 난 자리에 경로를 하나 더 만들지 않는다.

## 4) 구조

### 4-1) 정의 단위 = 작업(Job)

화면 47개도 요금제 키 12개도 아니다. **"고객이 하려는 일"** 하나가 단위이고, 화면·모달·요금제는 그 일의 속성으로 매단다.

라우트 기준이 안 되는 근거: 고객이 보는 헤더 메뉴는 8개뿐인데 라우트는 47개다. 자동발송·세그먼트·모바일 DM은 메뉴에서 빠졌는데 라우트는 살아 있다(`ai-operator-modules.ts` 주석: "카드를 교체, 라우트는 유지"). 라우트에 정의를 묶으면 고객이 갈 수 없는 화면까지 목차가 된다.

### 4-2) 파일: `packages/backend/src/content/feature-catalog.ts` 한 개

12개를 도메인별 8파일에 흩으면 대부분이 항목 1~2개짜리 껍데기가 된다. **항목 30개를 넘으면 그때 쪼갠다.**
> 2026-08-22(2) 40개가 한 파일(약 1,000줄)에 있다. 쪼개기는 **하지 않았다**: 같은 세션에 본문 27개를 쓰면서 구조까지 바꾸면 검토 면이 두 배가 된다(범위 규율). 쪼개기는 "추가 과제"로 남긴다. 쪼갤 때 기준은 `JOB_GROUPS` 7묶음이고, 불변식 8번이 읽는 파일 경로(`content/feature-catalog.ts`의 `Omit<FeatureJob, 'sourceFile'`)는 그대로 둬야 한다.

```ts
export interface FeatureJob {
  id: string;               // 'send-direct'
  title: string;            // 고객 언어 명사구, 14자 이내        [사람]
  goal: string;             // 이걸 하면 무엇이 끝나는가, 40자 이내 [사람]
  keywords: string[];       // 사용자 어휘·구어·오탈자 5개 이상     [사람]
  steps: string[];          // 3~6줄                             [사람]
  blockers: { symptom: string; fix: string }[];  // 0~3개         [사람]
  entry: { path: string; via: string };          // 기계 대조
  planKey: FeatureKey | null;                    // plan-guard 타입 직접 import
  creditSource: string | null;                   // CREDIT_COST_MAP 키. 숫자 금지
  related: string[];                             // 최대 3
  status: 'ready' | 'stub';
  stubUntil: string | null;                      // 'YYYY-MM-DD'
  sourceFile: string;                            // 내부 전용. 노출 0
}

export type PublicFeatureJob = Omit<FeatureJob, 'sourceFile' | 'status' | 'stubUntil'>;
```

**사람이 쓰는 것은 넷뿐이다**: `goal` · `keywords` · `steps` · `blockers`. 나머지는 기계가 대조한다.

`blockers`가 이 체계의 핵심이다. 기능 설명이 아니라 **막히는 지점**이 봇의 실제 답변 내용이다. 옛 매뉴얼이 죽은 이유가 화면 구성표와 단계 나열만 있고 "왜 안 되는지"가 없어서다.

### 4-3) DB: 원장 1개

`help_questions(id, company_id, user_id, path, question, matched_ids text[], answered bool, created_at)`.
답한 질문과 못 답한 질문을 한 테이블이 가져야 **미답 비율**이라는 단일 지표가 나온다. 정의는 DB에 두지 않는다.

### 4-4) 봇

- **노출 대상 = 요금제 사용 중인 회사만**(★Harold 지시). 판정은 서버가 한다(`plan_code <> 'FREE'` + 구독이 만료·정지 아님, 2-5). 프론트가 요금제를 받아 판정하면 판정이 두 벌이 된다.
- **자리 = 우측 하단**(★Harold 지시). 토스트가 같은 자리를 쓰므로(2-7) 토스트가 뜨는 동안 런처가 비켜선다: ToastProvider와 인터럽트 3종이 `body`에 표시 속성을 달고 런처가 그 속성에 반응한다.
- **층 = 런처 `z-[1400]` · 패널 `z-[1500]`.** 인터럽트(2000) 아래여야 한다. 도움말이 크레딧 차감 확인창을 덮으면 사고다. 캔버스가 화면을 소유하는 `/dm-builder`·`/image-studio`는 런처를 띄우지 않는다(2-7의 2400·2500).
- **모드를 묻지 않는다.** 서버가 발송 이력 유무로 판정한다. 없으면 온보딩(시작 카드), 있으면 도움말(현재 화면 작업 + 막히는 지점).
- **화면 인지 = 라우트만**(1단계). 모달은 등록하지 않고, 대신 정의가 모달을 지칭하지 못하게 막는다. 6개만 등록해도 나머지 52개에서는 여전히 모르기 때문이다.
- 스크림·포커스 트랩·본문 스크롤 잠금 없음. 봇이 "여기를 누르세요"라고 하면 그대로 눌러야 한다.
- 껍데기에 `transform`·`filter`·`backdrop-filter` 금지.

**기존 온보딩 마법사와의 관계**: 대체하지 않는다. 진행률 원장도 새로 만들지 않고 마법사 것을 읽는다. 봇 카드가 `/onboarding?step=N`으로 딥링크하되, **그 회사가 마법사 대상이 아니면(체험권 없음, 2-6) 링크를 그리지 않고 봇이 직접 단계를 안내한다.** 봇이 체험권 게이트를 물려받으면 지금과 똑같이 "체험권 준 회사만 안내받는" 상태가 된다.

### 4-5) 답변 조립과 환각 차단 4겹 (★0824 §10-6 개정 반영)

1. **컨텍스트 = 카탈로그 전체의 공개 필드뿐**(캐시된 시스템 프롬프트). ★0824 개정: 전에는 "매칭 실패 = 모델 호출 0 + 후보 3개만 컨텍스트"였다. 지금은 매칭이 못 찾은 질문도 원장 40개를 들고 모델이 찾는다. 폐집합이라는 사실은 그대로다.
2. **응답 계약 = JSON `{jobs, answer}`.** id가 카탈로그에 실존해야만 카드다. jobs가 비면 "모른다"로 보고 문의 남기기로 보낸다.
3. **출구 코드 검사**(프롬프트 지시가 아니다): 응답 안 모든 `/경로`가 실제 라우트에 있는지 · 기존 `detectBenefits`로 혜택 토큰(%·원·쿠폰·무료) 검출 · 모델명 · 긴 줄표. 하나라도 걸리면 답변을 버리고 후보 카드로 되돌린다.
4. **요금제 문구는 모델이 쓰지 않는다.** `planKey`를 그 회사 기준으로 판정해 우리 문자열로 렌더한다.

### 4-6) 안내 화면 `/guide`

**원고 0장·스크린샷 0장.** 같은 카탈로그를 그리기만 한다. 톤은 라이트 인디고(읽고 검색하는 조회 화면). 지금 대시보드 푸터가 걸고 있는 3개월 낡은 정적 매뉴얼 링크를 여기로 돌린다.
