### 2-2. P3-4 — Agent 설정의 "이모지면 encoding 1" 안내 정정 (새 업체 위험 · 추천 1순위)

- **왜**: `bito-gateway/internal/agent/config/config.go:42-53` 주석이 이모지를 쓰려면 `encoding: 1` 이라고 안내한다. 우리 젬텍 계정은 1 을 213 으로 반려하므로(설계서 §1-1), 이 안내대로 설정한 Agent 는 **문자가 전부 실패**한다. 카카오 대체 문자도 부모 encoding 을 물려받아 검사 없이 213 이 된다(`engine/report.go` startKakaoFallback `Encoding: parent.encoding`). 발급 설정 기본값에는 이 키가 없어 지금은 아무도 안 걸렸다(0910 추적).
- **현황 파악부터**(코드 수정 전): ① 안내가 있는 곳 전수 grep(`config.go` · `status/AGENT_MANUAL.md` · 발급 템플릿 · 대시보드 발급 화면 · 온보딩 문서) ② 운영에서 `encoding <> 0` 으로 들어온 요청이 있는지 게이트웨이 DB 로 센다. **SQL 을 쓰기 전에 `information_schema` 로 `message_request` 의 `encoding`·`agent_id`·`source_type`·`created_at` 컬럼부터 확인**한다. 게이트웨이 운영 DB 는 .65 도커 `bito-bench-postgres`(DB `bito_gateway`) — 접속 명령 형식은 착수 때 Harold님께 확인한다.
- **설계 후보(착수 때 추천 1개로)**: (a) 안내 문구 정정만 (b) + 게이트웨이가 문자 유형의 `encoding=1` 을 사유 코드와 함께 즉시 반려(213 로 늦게 실패하는 대신 · "막고 계도" 원칙) (c) + Agent 설정 검증 경고. (b)는 모든 계정 동작 변경이므로 ②의 실측 결과를 보고 판단한다.

## 3. 범위 밖으로 기록만 한 것 (착수 금지 · 판단은 Harold님)

- 휴머스온 RESEND_* 칸으로 중계사가 직접 문자 재발송할 때 이모지 처리 미검증(0911 검토).
- 카카오 대체 발송 재진입 가드 없음 — 중복 REPORT 때 대체를 다시 시도(기존 결함).
- 브랜드 JSON 전문이 본문인 부모는 대체 문안이 없으면 JSON 원문이 대체 LMS 로 나간다(기존 결함 · 한줄로는 `k_next_contents` 를 싣는다).
- 카카오 본문의 깨진 글자(U+FFFD)는 이제 검증에서 막히지 않는다(카카오 제외의 부수 효과 · 낮음).
- 내부 API `msg_type` 앞 공백 → 대체 발송 판정 불일치(내부 직접 호출만 · 기존).
- `Dashboard` "캠페인 설정" 탭은 들어갈 길이 없는 죽은 화면(설계서 §9).

- Windows 에서 `agent/bootstrap` 테스트 5건은 원래 실패한다(`check.sh` 환경 제외 목록 · HEAD 에서도 동일) — 새 변경 탓으로 오인하지 않는다.
