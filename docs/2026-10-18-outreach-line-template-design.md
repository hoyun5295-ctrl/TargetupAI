## §0 원래 안건 (Harold 원문 요약)

- 1017에 만든 템플릿 제작 엔진을 AI 영업에도 이식한다. AI 영업만 · 템플릿 먼저 · 안 맞으면 지금 표준 조립 · 스위치로.
- 「AI 영업은 이벤트 페이지나 고객사 페이지를 읽고 업종에 맞춰 알아서 베스트를 추천하는 방법으로」 → 1단계 + 2단계를 끝까지 구현하고 Codex 가 닫힐 때까지 돌린 뒤 배포 명령.
- 「퀄리티는 늘 베스트 퀄리티로 뽑아야 해. 한줄제작도 마찬가지」.

## §1 구조체크 결론

- AI 영업 DM · 브랜드 이메일은 재료(상품 · 행사)가 있으면 이미 코드 표준 조립(`composeOutreachStandard`)을 공용 엔진의 preset 자리로 넘긴다. 템플릿 조립은 같은 자리에 꽂힌다(엔진 · 발행 · 캡처 · 채점 무변경).
- 섹션은 공용 닫힌 타입이라 출처는 지금처럼 **id 접두**로 싣는다(`so-std-` → `so-tpl-`).
- Codex R1~R3: 사람이 고르지 않는 경로에서 **AI 가 값이 든 문장을 자유롭게 쓰면 사후 검사로 닫히지 않는다**(공백 인접 · 율/률 · 한글 수사 · 「두 배」). → AI 는 **고르기만** 하고 값은 코드가 재료 원문으로 놓는다.

## §2 결정 (Harold 승인 1018)

| 안건 | 결정 |
|---|---|
| Q1 표지 | 지금 표준 순서 그대로(포스터 → 홈 배너 → 행사 카드 배너). 글자가 박힌 그림이라 **덮지 않는다** = 원본 비율(그 그림의 링크) + 아래 제목 |
| Q2 혜택 | 첫 **면허** 행사 카드 제목 원문(30자 넘으면 혜택 없음 · 자르지 않음) + 그 카드 본문(구매 조건)을 조건 글로. 면허 없으면 0 |
| Q3 행사 | 행사 목록(≤3)을 마무리 장 앞 한 장으로. 배너 = 그림(제목 · 본문 · 기간 캡션) · 없으면 글 카드 · 상세 그림 ≤3 |
| Q4 자격 | 혜택 있음 → 빅세일(혜택에 세일 · 할인 말) · 특별 이벤트 / 혜택 없음 + 상품 → 신상품(행사 제목 · 상품 이름의 신상 근거) · 계절 / 둘 다 없음 = 표준 조립 |
| Q5 스위치 | 별도 ENV 축 `OUTREACH_LINE_TEMPLATES=1`(고객 스위치와 따로) |
| 2단계 | AI 가 페이지 글 · 업종 · 행사 · 상품 · 혜택을 읽고 **자격 템플릿 중 하나 + 칸마다 업종 문구 묶음의 번호**를 고른다(쓰지 않는다) |
| 품질 | 문구 묶음 = 템플릿 × 칸 × 업종 결(뷰티 · 패션 · 식품 · 커머스) · 업종마다 칸마다 둘 이상 · 브랜드 · 상품 이름 채움 |

## §3 흐름

1. DM 단계 — 표준 재료가 있고 스위치가 켜져 있으면: 재료 변환 → **자격**(코드) → **추천**(AI 1회 · 계측 호출기 · 20초 상한) → 검증(자격 · 결 · 마감 근거 · 채움 · 상한) → 조립 → 관문. AI 실패 · 시간 초과 · 해석 실패 = 자격 1순위 + 기본 문구(by rule). 자격 0 · 관문 실패 · 예외 = 지금 표준 조립(로그 `[sales-outreach] 템플릿 …`).
2. DM 산출물에 기록(`lineTemplate` = 템플릿 · 자격 이유 · 추천 주체 · 칸 번호). 숨김 재실행은 직전 기록 승계. 학습 레시피에 원문 없이 {템플릿 · 추천 주체 · 칸 번호 · 결}.
3. 이메일 단계 — DM 기록이 있으면 같은 템플릿 · 같은 칸 번호로 이메일(AI 0). 지금 재료로 그 템플릿 자격이 없으면 표준 조립. 제목 = 표준 조립과 같은 규칙(첫 행사 제목).
4. 영업 제안 메일은 지금처럼 브랜드 이메일의 머리 · 첫 그림만 싣는다(무변경).

## §4 불변

- 결과물의 글 = 문구 묶음(채운 것) · 템플릿 기본 문구 · 재료 원문뿐(AI 글 0).
- 값(혜택 원문 · 조건 글 · 기간 · 가격 · 행사 제목 · 표지 그림)은 코드가 재료에서 그대로 놓는다.
- 주 버튼 하나 = 그 템플릿이 말하는 대상의 주소(빅세일 · 특별 이벤트 = 혜택 카드 행사 · 신상품 = 근거 행사 · 상품 · 계절 = 쇼핑몰). 그림 없는 행사가 갈 길이 없으면 그 행사 아래 작은 테두리 링크 버튼.
- 마감 · 끝을 말하는 문구 = 면허 카드 종료일이 있을 때만. 「세일」 = 빅세일만 · 「새로 · 신상」 = 신상품만.
- 같은 그림 두 번 0 · brand_kit 키 = 주색 · 아트 디렉션만(아웃리치 불변 그대로).
- 고객 경로(한 줄 템플릿 캠페인) 출력 무변경 — 조건 글 · 행사 장 · 테두리 링크는 AI 영업 재료에만 있다. 관문은 주 버튼만 센다(고객 경로 버튼은 전부 주 버튼).

## §5 하지 않는 것

- (→ §12 에서 같은 날 구현) 승격된 레시피를 업종 결별 베스트로 읽어 추천에 넣는 것.
- 고객사 AI 자동 제작(C) · 인앱 앱 채널 템플릿 · 발송 화면 「방금 쓴 문자로 DM 만들어 보기」 = 추가 과제.
- 고객 경로 혜택 교차 조합 = [B-1018-1](../status/BUGS.md)(등재만).

### §11-5 실측 시나리오 (배포 · 스위치 뒤)

1. 스위치 켠 뒤 AI 영업 새 건 3건(뷰티 · 의류 · 요식업 · 면허 행사 있는 건 1건 이상).
2. 각 건 DM = 표지 그림이 잘리지 않고 그 아래 제목 · 혜택 건은 혜택 원문 + 조건 글 · 업종 결에 맞는 문구 · 주 버튼 목적지 = 그 대상.
3. 검토 화면 근거 = 레시피 `lineTemplate`(추천 주체 ai/rule) · pm2 로그에 `템플릿 추천 불가 → 규칙` / `템플릿 관문 실패 → 표준 조립`이 있으면 사유 확인.
4. 영업 제안 메일 미리보기 = 브랜드 머리 + 첫 그림이 DM 표지와 같다.

## §12 3단계 — 승격 레시피로 업종 결별 학습 베스트 (Harold 1018 「이거까지 다 하고 한 번에 배포」)

- 원천 = 운영자가 검토 창 「이 건의 레시피를 학습에 올리기」로 승격한 레시피(`best_copy_assets` kind `recipe`)의 `meta.recipe.lineTemplate` = {템플릿 · 추천 주체 · 칸 번호 · 결}(원문 0).
- 컬럼 확인 = 운영 DB `information_schema` 실측(Harold 1018) — `kind` · `industry_code` · `meta` · `created_at` 실존. 같은 실측에서 승격 레시피 = 뷰티 1건 · 템플릿 기록 든 것 **0건** → 배포 직후 효과 0(지금 동작 그대로) · 운영자가 템플릿 결과를 승격할수록 쌓인다.
- 결정(Harold 동의 · 추천안) = 집계 단위 **문구 결**(업종 코드 여럿 · 표본이 모이고 문구 묶음과 맞물린다) · 쓰는 곳 **힌트 + 규칙 대체**.

| 자리 | 동작 |
|---|---|
| 조회(`best-copy-assets.ts` `listOutreachRecipeTemplates`) | 결의 업종 코드들 · 템플릿 기록 든 레시피만 · 최신 200 · 5분 캐시 · 승격(`insertOutreachRecipe` = 레시피 쓰기 유일 길목)에서 캐시 비움 · 테이블 없음 = [] · 오류 = null(캐시 안 함) |
| 집계(`outreachBestOf` · 순수) | 기록 읽기로 모양 검증 · 템플릿 횟수 · 칸별 번호 횟수(빠진 칸 = 0번) · 묶음 밖 번호 버림 |
| 프롬프트 힌트(`outreachBestHint`) | 자격 템플릿 · 지금 쓸 수 있는 번호만 · 횟수 그대로 · 「참고만」 · AI 출력은 기존 검증 그대로 |
| 규칙(`outreachRuleOf`) | AI 실패 때 — 자격 안 같은 템플릿 **2건 이상**이면 그것(by `best`) + 2회 이상 오른 번호 · 아니면 자격 1순위 + 기본(by `rule`) |
| 대기 | 학습 읽기 3초 · AI 추천 20초 상한(같은 경주 helper) · 자격 0 이면 DB · AI 둘 다 안 부른다 |

- 시험 = 이 파일 45 · 백엔드 전체 9,013 통과 · 변이 10 전부 잡힘(캐시 비움 · 문턱 · 자격 · 쓸 수 있는 번호 · 0번 셈 · 읽는 순서 · 오류 캐시 · 결 단위 · 힌트 실림 · 잡별 중복 제거).
- 실측(배포 뒤) = 템플릿 결과 1건을 「학습에 올리기」 → 같은 결의 새 건 1건 → 레시피 `lineTemplate.by` 와 pm2 로그(`템플릿 추천 불가 → best`가 나오면 규칙 대체가 탄 것) 확인. 실측 SQL = `SELECT industry_code, meta->'recipe'->'lineTemplate' FROM best_copy_assets WHERE kind='recipe' ORDER BY created_at DESC LIMIT 5;`
