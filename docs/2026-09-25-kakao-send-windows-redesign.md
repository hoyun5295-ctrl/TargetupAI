# 알림톡 · 브랜드메시지 발송 창 개편 (2026-09-25)

> Harold 지시(0925): "알림톡이랑 브랜드메세지도 통일성 있고 깔끔하고 모던한 디자인으로 전면 개편 · 둘 다 전체화면으로" →
> "브랜드메세지 유형 기준으로 창을 맞추고 · 알림톡은 템플릿 선택을 누르면 예시를 보여 주는 창 · 브랜드도 유형·등록 템플릿을 각각 창으로" →
> 목업 v2 승인("추천하는 방향으로 끝까지") → "발송에 지장 전혀 없도록 코덱스 리뷰 돌려서 문제없을 때까지".

## 0. 한 줄

두 창을 직접발송과 같은 전체화면 틀(작성 · 받는 화면 · 수신자 3열 + 발송 바)로 바꿨다. **보내는 값 · 보내기 조건 · 검증 순서는 한 글자도 바꾸지 않았다**(화면만).

## 1. 불변

1. **발송 무변경** — 알림톡 `handleSend`(상태·파일·적재·확인 창 값) · 브랜드 `handleSend`·`canSend`·`blockReason`·payload 투영 · 브랜드 수신자 단일 통로(`setRecipients` · 늦은 AI 응답 무효화)는 원문 줄 그대로 옮겼다(조립 스크립트가 원문 토막을 글자 대조).
2. **공용 부품 영향 0(B안)** — `AlimtalkChannelPanel`(6곳 공용)은 로직을 훅(`useAlimtalkChannel`)·`AlimtalkFallbackEditor`·`buildAlimtalkPreviewProps`로 나누되 **기본 렌더가 바이트 단위로 같다**(서버 렌더 8상태 대조). `AlimtalkVariableMappingPanel`(4곳 공용)은 `layout="rows"`를 줄 때만 새 모양(기본 4상태 대조 동일).
3. **창 크기 = 가장 큰 유형 기준** — 작성 520 · 받는 화면 380(카카오 말풍선 최대 352 + 여백) · 수신자 = 남는 폭. 유형·템플릿이 바뀌어도 창 크기는 그대로(넓은 카드는 받는 화면 안에서 옆으로, 긴 목록은 위아래로).
4. **고르기 창은 보내는 쪽이 싣지 못하는 것을 고르게 두지 않는다** — 알림톡 = 승인 템플릿만(`isApprovedAlimtalkTemplate` 한 벌). 브랜드 등록 템플릿 = 어디든 `#{...}` 변수 있음 · 발송이 열리지 않은 유형(기본형은 시험 허용 없이 유형 검사) · 못 쓰는 발신프로필이면 막는다.
5. **등록 템플릿 선택 = 코드 · 발신프로필 · 유형 · 이미지 한 묶음** — 고를 때 함께 맞추고(직접 넣은 이미지는 비움 · 고른 동안 이미지 칸 숨김), 어긋나면 풀고(코드 비움), 어긋난 채로는 못 보낸다. 자유형에서 넣은 이미지가 남아 돌아오면 이유 + [이미지 비우기](Codex 1R · 6R).
6. **옛 공용 틀이 하던 일 유지** — 브랜드 창 = 문서 몸통 포털 · 겹침 2000(확인 창·요금제 안내 2100이 위) · ESC 닫기 · 닫혀 있으면 그리지 않음.
7. **닫힌 알림톡 창은 공유 상태를 바꾸지 않는다** — 훅이 창 맨 위라 닫혀도 돌기 때문에 발신프로필 목록을 빈 목록으로 준다(하나뿐 자동 선택이 대시보드 상태를 바꾸지 않게).
8. **수신자 목록 선택 = 보이는 목록** — 머리 체크박스는 검색 결과 줄만 · 검색어를 바꾸거나 명단이 바뀌면 선택을 비운다(알림톡·브랜드·직접발송 세 창 · Codex 3R · Harold "같은 문제면 같이").
9. **늦게 끝난 읽기는 사람이 고친 명단을 덮지 않는다** — 브랜드 파일 읽기도 AI 추출과 같은 세대 규칙(읽는 동안 명단이 바뀌면 버림 · Codex 4R 범위 밖 지적을 같은 뿌리로 닫음).
10. **문자 발송으로 전환 = 카카오 명단을 들고 간다(`utils/send-checks.ts` `carryPhonesToDirectRecipients` 한 벌)** — 결과 수·순서 = 카카오 명단. 알림톡은 문자 명단의 줄 객체를 그대로 받아 지우기만 하므로 **줄 자체**를 넘겨 같은 줄은 그 줄 그대로(같은 번호 여러 줄도 어느 줄을 지웠는지 정확), 나머지는 번호만. 브랜드는 번호 목록(중복 제거) — 번호 집합이 같으면 문자 명단을 그대로 두고, 다르면 순서대로 하나씩 짝짓는다. 새 줄은 언제나 번호만(카카오 쪽 파일 머리글 칸 유입 금지). 빈 명단·변화 없음이면 덮지 않고 안내도 없다(Codex 8R · 9R).
11. **확인한 명단 = 보내는 명단** — 브랜드는 확인 창을 여는 순간 명단을 떠 두고(`pendingPhones`) 확인 창 건수와 실제 발송 모두 그 명단을 쓴다. 확인 창이 떠 있는 동안 늦게 끝난 담기나 키보드로 닿는 뒤쪽 버튼이 화면 명단을 바꿔도 나가는 것은 확인한 명단. 확인을 기다리는 동안(`pending`)은 새 보내기를 받지 않는다 — 공용 확인 창이 포커스를 옮기지 않아 Enter 가 뒤쪽 보내기로 다시 들어가 떠 둔 명단을 바꿨다(공용 창은 무변경 · 호출부에서 막음). 문자·알림톡은 원래 확인 창 전에 서버에 적재하고 확인은 그 적재분(`stagingId`)만 확정하며, 다시 누르면 다시 적재해 확인 창 건수도 따라 바뀌므로 같은 결함이 아니다(Codex 10R·11R·12R · 10R 때 넣은 "확인 창 열 때 세대 올리기"는 떠 두기로 대체되어 걷었다).
12. **늦게 끝난 불러오기는 사람이 고친 명단을 덮지 않는다(세 창 공통)** — 주소록 불러오기(그룹 [불러오기] · 선택 그룹 일괄 · 문자·알림톡 창 공용) = 불러오는 동안 가림막 + [불러오기 취소] · 취소·닫힘·언마운트·새 불러오기면 앞 응답 버림 + 실패 안내. 문자 발송 파일 매핑 = 닫기·취소 = 취소(세대) · 패널이 사라지면 결과 버림. ⛔ **닫기를 잠그지 않는다** — 응답이 끝나지 않거나 처리가 예외로 멈추면 영구히 갇힌다(Codex 12R · 시간 제한 권고는 임의 상수라 불수용). 브랜드 = 명단 세대(담기·파일 읽기)와 추출 세대(타겟 추출)를 나눠 명단을 고쳐도 추출이 안 버려지고 [추출 중]이 멈추지 않음 · 새 추출은 앞 담기를 무효로 하고 그 표시를 내림(Harold "주소록 경합도 같이 · 브랜드창도 같이").

## 5. 추가 과제(착수 안 함)

- **B-0925-6** 등록 화면 수정 폼이 `attachment_json`·`carousel_json`으로 읽는다(실제 칸 = `attachment`·`carousel`) — 수정하려고 열면 이미지·캐러셀이 비어 보일 수 있다(미검증 · BUGS).
