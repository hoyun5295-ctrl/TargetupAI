## Q1. 포스터 3칸과 혜택 검증

**처방**

"단일 검증 행사 객체 → 서버 타이포 합성" 방향에 동의합니다. 여기에 **문구별 출처·조건·유효기간**을 추가해야 합니다. 면허는 이미지 전체에 주는 허가가 아니라, 특정 행사 문구를 정해진 조건으로 표시하는 허가여야 합니다.

**구현 규칙(입력·출력·판정·폴백)**

- **입력:** `event{id, sourceUrl, collectedAt, title, quote, periodRaw, startAt, endAt, evidenceRefs}`와 선택 상품의 `id·원문 이름·이미지·상세 URL·행사 귀속 근거`. `benefitLicensed`만 전달하지 말고 서버가 증거에서 다시 판정합니다.
- **출력:** 각 칸의 `text·sourceRef·원문 구간`, `validUntil`, `droppedReasons`, 최종 이미지의 `검사 상태·해시`. 이미지를 채택하지 못하면 URL은 `null`입니다.

| 칸 | 배치 규칙 |
|---|---|
| label | 카드 제목의 행사명 또는 원문에서 확인한 행사 성격. title과 중복되면 생략합니다. |
| title | 면허가 있는 **완결된 혜택 구절 그대로**. "최대", 적용 대상, 구매 조건을 제거하거나 다른 행사 문구와 결합하지 않습니다. |
| subtitle | 혜택을 썼으면 기간·필수 조건 우선. 혜택이 없으면 선택 이미지와 일치하는 상품명. 공간이 부족하면 혜택을 포기하고 상품은 아래 큐레이션으로 보냅니다. |

- **문구 판정:** 공백 정규화 후 원문 구간을 대조하되 숫자·단위·조건 표현은 보존합니다. 기간도 원문 증거가 필요합니다. 시작 전 행사를 "진행 중"으로 표시하지 않고, 연도·종료일을 추정하지 않습니다.
- **이미지 판정:** 배경은 문구 없이 생성하고, 합성 결과 OCR을 예정 문구 및 원본 상품 이미지의 확인된 글자와 대조합니다. 추가·누락·변형된 혜택을 검사하며, 숫자 존재 자체를 실패로 삼지 않습니다. 별도 16:9 배너에도 동일하게 적용합니다.
- **폴백:** 검증된 혜택 포스터 → 혜택 없는 행사명 포스터 → 검사 통과한 홈/카드 배너 → 이미지 제외. OCR 장애·불명확은 자동 통과시키지 않습니다.

**근거**

현재 계약에는 기간·면허 증거가 없고 숫자 앞에서 제목을 자릅니다. `packages/backend/src/utils/sales-outreach-produce.ts:649`(`buildOutreachPosterTexts`). 현재 검사는 숫자 존재 여부이며, 재검사 불명확도 채택할 수 있고 양쪽 모두 숫자가 검출되면 첫 이미지를 저장합니다. `sales-outreach-produce.ts:708, 921`.

**위험**

인용문이 실재해도 종료일이 검증됐다는 뜻은 아닙니다. 현재 후보 생성은 AI가 반환한 날짜를 원문에서 찾은 날짜보다 우선합니다(`sales-outreach-jobs.ts:488`). 날짜까지 출처를 결속하지 않으면 새 계약에도 같은 약점이 남습니다.

## Q2. 이미지 적합성과 채널별 품질 판정

**처방**

이미지 종류 분류에는 동의하지만, **실제 배치 역할에 대한 적합성 검사**를 추가해야 합니다. 행사 슬라이스로 적합한 이미지가 히어로로도 적합하다고 판단하지 마십시오. 혜택 안전성은 품질 점수와 별도로 통과해야 합니다.

**구현 규칙(입력·출력·판정·폴백)**

- **입력:** 잠정 조립 결과의 `{이미지 해시, 역할, 채널, 표시 폭, 행사/상품 참조, 목적지, 주변 제목}`.
- **출력:** 배치별 `통과/제외/검수`, 이유 코드, 검사 버전과 `quality.dm`, `quality.email`.
- **이미지 임계 제안:** 관련성·역할 적합성·주 피사체 식별·표시 폭 가독성·의미 완결성을 각각 `명확/불명확/부적합`으로 판정. 전부 명확해야 자동 통과, 하나라도 부적합이면 제외, 나머지는 검수.
- **검사 범위:** 히어로 → 행사 카드 → 상품 → 보조 슬라이스 순 예산 배정. 14장 상한 밖은 미검사 상태로 자동 채택 금지.
- **DM 판정:** 375폭 첫 화면 브랜드·행사/상품 메시지 식별, 잘림·중복·상품 식별·CTA 검사. 링크 귀속·스와이프는 코드·동작 검사로 확인.
- **이메일 판정:** 600폭·375폭 실제 렌더 각각 검사. 가격 미확인 상품의 가격 줄 생략은 정상.
- **폴백·사람 검수:** 부적합 보조 이미지 제거·대체. 새 레시피·미검사·판정 불명확은 전수 검수. 반복 확인 조합만 표본 검수로 전환.

**근거**

현재 분류는 종류와 글자 유무뿐이고, 슬라이스 뒤에 홈 갤러리를 넣어 14장으로 자릅니다. `sales-outreach-produce.ts:83`(`classifyOutreachImages`), `:507`, `:2014`(`heroBannerCopyOf`). 현재 채점은 가격 쌍과 섹션 수를 요구해 DM/이메일 렌더 구조 차이를 무시합니다. `sales-outreach-produce.ts:773`(`scoreDmCapture`), `dm-section-renderer.ts:773`, `email-section-renderer.ts:782`.

**위험**

현재 자료로 검수 절감률·자동 합격 정확도를 산정할 수 없습니다. 브라우저 캡처만으로 전 메일 클라이언트 표시까지 검증했다고 표시하면 안 됩니다.

## Q3. 직원 예시와 결과를 표준 조립에 연결하는 학습

**처방**

마스킹 예시와 jsonb 원장 방향에 동의합니다. 먼저 **직원 판단을 제한된 조립 파라미터로 옮기는 절차**를 연결하십시오. 문장 예시를 더 넣는 것만으로는 AI를 거치지 않는 표준 조립이 달라지지 않습니다.

**구현 규칙(입력·출력·판정·폴백)**

- **입력:** 직원 예시를 채널별로 나눠 상품 수·배치 순서·이미지 역할·슬라이스 수·문구 길이를 사람이 라벨링. 마스킹 텍스트로 확인 불가한 항목은 `미확인`.
- **저장:** `recipe.v2`에 `context{channel, industry, materialBand}`, `available`, `applied{productCount, productOrder, heroKind, heroTreatment, slicesByEvent, copyLimits}`, `policyVersion`.
- **수정·결과:** `stage_results.edits[]`에 `assetRevision·beforeParams·afterParams` 추가. 별도 jsonb 결과 항목에 실제 외부 전달 확인·열람·수신 회신·상담 전환의 시각·출처. 원문·타사 이미지는 원장에 복제하지 않음.
- **판정:** 초기엔 직원 라벨·사람 승격 결과 기준. 이후 같은 채널·재료 유형에서 한 변수만 비교. 봇·검수·미리보기는 성과 제외, 재생성은 독립 표본으로 세지 않음.
- **폴백:** 업종+채널 근거 부족 시 채널 전체 → 확인된 직원 기준 → 현재 기본값. 상품 6·행사 3·행사별 슬라이스 3 상한과 사람 선택 순서 유지.

**근거**

19건은 DM 10건·이메일 9건입니다. 표준 경로는 예시 조회를 건너뜁니다. `sales-outreach-exemplars.ts:5`, `sales-outreach-produce.ts:2182`. 현재 승격은 recipe와 편집 집계를 저장하며 `reply`는 실제 수신 회신이 아니라 회신 유도 문장 편집입니다. `sales-outreach-jobs.ts:2100, 2074`.

**위험**

먼저 학습 라벨 오류를 고쳐야 합니다. `so-std-hero`는 실제 배너·카드 폴백이어도 recipe에서 `poster`로 기록됩니다(`sales-outreach-jobs.ts:1312`, `buildOutreachRecipe`). 이 상태로 학습하면 히어로 선택 효과를 잘못 해석합니다. 또 자사 수신 후 사람 전달 흐름이 있으므로(`docs/FEATURE-SALES-OUTREACH.md:17`) SMTP 성공을 담당자 노출로 계산하면 안 됩니다.

## Q4. preset 우회와 homeLinked 예외의 최소 변경

**처방**

표준 조립에는 동의하지만 **"코드가 조립했으므로 검사를 생략한다"는 판단에는 반대**합니다. 원문 상품명·배너도 검증 대상입니다. `homeLinked`는 수집 당시 홈 노출의 증거로만 남기고 혜택 면허에서 분리하십시오.

**구현 규칙(입력·출력·판정·폴백)**

- **입력:** 아웃리치 전용 검증기 하나에 `채널·최종 섹션·제목·문자 문안·행사별 증거·상품별 사실·이미지 검사 결과·현재 시각·자산 버전` 전달.
- **출력:** `통과/차단`, 제거·교체 내역, 증거 참조, `contentHash·validUntil·policyVersion`.
- **적용 위치:** 최초 조립과 저장본 재사용·숨김 적용 뒤, DM 발행 및 이메일 HTML 렌더 전에 동일 검증기 호출. 공용 엔진에만 넣으면 표준 이메일 직접 반환 경로가 남습니다.
- **텍스트 판정:** 버튼·제목뿐 아니라 `products[].name` 등 배열 내부도 검사. 상품명 규격 숫자는 상품 증거로 보존하되 `1+1` 등 혜택은 해당 행사 증거 요구.
- **homeLinked 판정:** 종료일 미확인은 일반 소개로 강등. 배너·슬라이스 속 혜택도 Q1 검사 통과 필요.
- **발송 판정:** 조회·발송이 동일 검증 자산·유효기간 사용, 발송 선점도 해당 버전과 결속. 만료·미검증 자산은 발송 가능한 조립본으로 인정하지 않음.

**근거**

DM preset은 sanitize를 건너뛰며, 표준 이메일은 바로 반환합니다. `campaign-engine.ts:150`, `sales-outreach-produce.ts:2325`(sanitize도 문자열·버튼만 다룸, `:1797` `sanitizeDmCopyBenefits`). 현재 homeLinked는 면허가 되고 발송 잠금에는 만료 검사가 없습니다. `sales-outreach-jobs.ts:535, 1411`, `:147`(`computeSendLock`).

**위험**

홈 링크 예외를 제거하면 기간 없는 몰의 행사 재료가 줄어듭니다. 이를 무관한 이미지나 추정 기간으로 보충하면 안 됩니다. 아웃리치 계약과 고객 직접 입력 계약은 다르므로 아웃리치 경계에만 적용해야 합니다. `docs/FEATURE-SALES-OUTREACH.md:58`.

## Q5. 제안 메일을 "한 장면"으로 재구성

**처방**

완성 시안으로 제품을 증명하는 방향에 동의합니다. **상단의 주인공을 실제 완성된 DM으로 바꾸고**, 기능 설명과 브랜드 이메일 전체는 공개 시안 페이지로 옮기십시오.

**구현 규칙(입력·출력·판정·폴백)**

- **출력 순서:** 작은 발신 브랜드 표시 → 개인화 한 문장 → 완성 DM의 첫 장면 → "전체 시안 보기" 버튼 하나 → 짧은 회신 요청 → 필수 푸터.
- **이미지 배치:** 캡처 안에 포스터가 있으면 별도 포스터를 반복하지 않음. 브랜드 이메일 전장·기능 카드 묶음은 공개 페이지로.
- **판정 임계 제안:** 375폭 첫 900px 안에 회사명·무엇을 만들었는지·완성 시안 일부·주 CTA가 모두 나타나야 함.
- **폴백:** 실제 DM 캡처 → 검사 통과한 대표 시안 이미지+설명 → 텍스트와 공개 링크. 대체 이미지를 DM 전체 캡처인 것처럼 표시하지 않음.

**근거**

현재 조립은 포스터·서두·자동 생성 설명 뒤에 DM 캡처를 배치하고 브랜드 이메일 전체·추가 기능 블록을 이어 붙입니다. `sales-outreach-produce.ts:2503, 2547`. 375×900 캡처는 이미 저장 중(`:747` `captureAndScoreDm`), 필수 고지 유지 계약도 있습니다. `docs/FEATURE-SALES-OUTREACH.md:37`.

**위험**

375×900 캡처를 모바일 메일에 그대로 전폭 삽입하면 CTA가 다시 아래로 밀릴 수 있습니다. "5초 이해"는 배치 목표일 뿐 현재 자료로 달성됐다고 주장할 수 없습니다.

## Q6. 전체 설계에서 틀렸거나 과한 것

**처방**

표준 순서·사본 저장·사람 발송·가격 미확인 시 생략은 유지할 만합니다. 우선순위는 **검증 우회 제거 → 실제 폴백 연결 → 기록 정확성 → 품질 판정 → 학습 → 비용 최적화**입니다.

**근거 / 지적**

- 상품명이 포함된 AI 문안 줄은 혜택 검사를 통째로 건너뜁니다. `sales-outreach-jobs.ts:1430`.
- 포스터 생략은 비활성화돼 있고 생성 예외는 바깥 catch에서 `markFailed`로 끝나, 브리핑의 "실패하면 홈 배너" 설명과 구현이 다릅니다. `sales-outreach-jobs.ts:1483, 1741`.
- 홈은 기본폭 재료 렌더와 375폭 캡처를 각각 요청하며 재료 게이트는 분석 단계에서 계산됩니다. `sales-outreach-jobs.ts:716, 741, 1127`.

**위험**

안전성을 강화하면 일부 몰의 결과가 짧아지거나 검수 대상으로 남습니다. 반대로 이를 피하려고 면허·미검사 폴백을 넓히면 톤28에서 확인된 "재료는 있지만 쓸 만한 시안은 아닌" 문제가 반복될 수 있습니다. 두 브랜드 실측과 마스킹 예시 19건만으로 모든 몰에 맞는 규칙을 확정하기는 이릅니다.
