## §1 미가입 · 직접발송만 쓰는 회사 = 변화 0 (맨 앞 기준 · 메모리 `feedback_free_direct_send_zero_change`)

## §4 처방

### §4-1 판정 한 곳 — 새 CT `utils/column-width.ts`

```ts
export const PHONE_COLUMN_WIDTH = 20;                                   // 운영 information_schema 1125(번호 · 회신 칸 전부 20)
export const ADDRESS_BOOK_WIDTH = { groupName: 100, name: 50, extra: 100 } as const;
export function fitsVarchar(text: string | null | undefined, width: number): boolean;  // 글자 값 전용 · PG 대입 규칙(코드 포인트 · 넘는 부분이 ' ' 뿐이면 받음)
export function fitsPhoneColumn(text: string | null | undefined): boolean;             // = fitsVarchar(text, 20) · 하한 없음(하한이 없던 입구용)
export function isAcceptablePhoneDigits(digits): boolean;                // 10자 이상 + 칸 폭(옛 `length >= 10` 자리를 바꾼다)
export function varcharFitsSql(expr: string, width: number): string;     // SQL 판정식 `(expr IS NULL OR char_length(rtrim(expr, ' ')) <= width)`
```

- **판정 = 실제로 칸에 들어가는 값으로**(Codex 설계 1R #1 · #4 · #5 의 같은 뿌리). 받은 값이 문자열이 아닐 수 있는 자리(적재 라우트 · 주소록 적재 CT = 요청 본문을 그대로 묶어 보낸다)는 **SQL 안에서 PG 가 보는 글자로** 판정한다(node-pg 직렬화 · 배열 · 객체와 무관하게 정확). JS 판정은 숫자 글자(정리 함수를 지난 값)에만 쓴다.
- 두 판정이 PG 와 같은지 = 실 PG 시험이 같은 글자 묶음(끝 공백 · 탭 · 이모지 · 21자)을 실제 varchar 칸에 넣어 받는지와 JS · SQL 판정을 대조한다.
- `extraction-keep.ts` 의 `STAGING_TEXT_MAX` = `PHONE_COLUMN_WIDTH` 를 가리킨다(값 20 그대로).
- 회신 하한 8자(`cb.length >= 8`)는 바꾸지 않는다 — 그 값은 넣기 전 등록 발신번호 대조를 지나야 하고 등록 표가 varchar(20)이다(D5' · 계약 면제 이유).
