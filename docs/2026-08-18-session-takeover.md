## 2) 불변 원칙

1. **⛔ 동의가 없으면 세션 테이블에 쓰지 않는다.** conflict 응답 경로의 `INSERT/UPDATE user_sessions` 호출은 **0회**여야 한다. 취소했을 때 기존 접속이 멀쩡한가 = 이 기능의 전부이고, 쓰기가 한 번이라도 새면 기능이 통째로 무의미해진다. (계약 테스트가 고정 — `session-takeover.test.ts`)
2. **⛔ 게이트는 호출부가 아니라 세션이 만들어지는 함수 안에 둔다.** 판정을 `routes/auth.ts` 3곳에 인라인으로 흩으면 네 번째 호출부가 생기는 순간 조용히 옛 동작(말없이 끊기)으로 돌아간다. `rotateUserSession`의 반환형을 바꿔 **tsc가 호출부를 강제**하게 만든 것이 그 장치다.
3. **⛔ 만료된 세션 행을 접속 중으로 세지 마라.** 브라우저를 그냥 닫으면 `is_active=true`인 행이 남는다. `expires_at > NOW()`가 빠지면 사용자가 **자기 죽은 세션에 막혀** 영영 못 들어온다.
4. **⛔ 인계 티켓은 API 인증 토큰이 아니다.** 같은 비밀키로 서명되므로 가드가 없으면 Bearer로 그대로 통과한다(1-7 분기). 토큰 종류를 하나씩 나열해 막지 말고 **API 인증 토큰이 반드시 갖는 값(`userId`+`userType`)**으로 판정한다 — 열거는 새 토큰이 늘 때마다 뚫린다.
5. **티켓은 그 순간의 세션 id에 묶는다.** 재사용해도 그 뒤에 생긴 다른 사람의 세션은 밀어내지 못하고, 그때는 새 안내가 다시 뜬다.
6. **원본 IP·user_agent를 화면으로 내보내지 않는다.** 같은 계정이라도 접속지 전체를 노출할 이유가 없다 — 기기 요약과 IP 앞 2옥텟까지만.
7. **409는 인증 실패가 아니다.** brute-force 카운터에서 제외하지 않으면 안내 모달을 몇 번 보는 것만으로 정상 사용자가 차단된다(사무실 공용 IP는 더 빠르다).
8. **⛔ 로그아웃은 서버 세션을 실제로 끊는다.** 클라이언트가 토큰만 지우면 `user_sessions` 행이 살아남고,
   그 유령 세션이 **본인의 재로그인을 막는다**(0818(2) 실사고 — 로그아웃했는데 인계 안내가 떴다).
   `/auth/logout`에는 `authenticate`를 걸지 않는다 — 만료 토큰이 401에 막히면 세션이 영영 안 끊긴다.
9. **⛔ 유휴 세션은 접속 중이 아니다.** 브라우저를 그냥 닫으면 로그아웃 호출이 가지 않는다.
   `expires_at`은 로그인 시 24시간으로 잡히므로 그것만으로는 유령 행을 못 거른다.
   활성 판정에 **유휴 30분**(기본 세션 타임아웃과 같은 값)을 함께 본다. 창이 열려 있으면 미들웨어가 5분마다 활동을 갱신한다.
10. **재시도는 1클릭이다.** 아이디·비밀번호·OTP를 다시 입력받지 않는다 — 화면에 남아 있는 값으로 그대로 재요청한다.

## 3) 구조

```
로그인 요청
  └ 비밀번호(슈퍼는 OTP까지) 검증 통과
      └ rotateUserSession()          ← 판정은 여기 한 곳
          ├ 살아 있는 세션 없음            → 회전(기존 동작)
          ├ 있음 + 유효한 인계 티켓        → 회전 (takeover: true)
          └ 있음 + 티켓 없음/불일치        → conflict (세션 쓰기 0)
                └ 409 { code:'SESSION_IN_USE', activeSession, takeoverTicket }
                     └ 화면: "이미 접속 중인 아이디입니다"
                          ├ [기존 접속 종료하고 로그인] → 티켓 실어 같은 요청 재실행
                          └ [취소]                      → 서버 상태 변화 0
```

| 무엇 | 소유 |
|------|------|
| 활성 세션 판정 · 티켓 발급/검증 · 표시용 마스킹 | `packages/backend/src/utils/session-manager.ts` (CT) |
| 비인증 토큰 Bearer 차단 | `packages/backend/src/middlewares/auth.ts` |
| 409 응답 · 감사 로그(`login_session_conflict` / `login_takeover`) · rate-limit 예외 | `packages/backend/src/routes/auth.ts` (3경로 동일) |
| 안내 모달 · 1클릭 재시도 | `packages/frontend/src/pages/LoginPage.tsx` |
| 로그아웃 세션 무효화 | `packages/backend/src/routes/auth.ts` `POST /logout` · `packages/frontend/src/stores/authStore.ts` |
| 계약 13건 | `packages/backend/src/utils/session-takeover.test.ts` |

티켓 유효시간 120초. 밀려난 쪽의 안내(30초 폴링 · 탭 포커스 · `storage` 이벤트)는 종전 그대로다 —
취소하면 새 토큰이 저장되지 않으므로 다른 탭도 흔들리지 않는다.

**"살아 있는 세션"의 정의 (0818(2) 정정)**

```
is_active = true
AND expires_at > NOW()                          -- 만료 행 제외
AND last_activity_at > NOW() - INTERVAL '30분'  -- 유휴 행 제외 (브라우저를 그냥 닫은 경우)
```

세 조건이 다 필요하다. 하나라도 빠지면 유령 세션이 본인을 막는다.
`/auth/logout`(신설)이 명시적 로그아웃을 즉시 끊고, 유휴 조건이 브라우저를 그냥 닫은 경우를 받는다.

## 6) 뒤집힌 판단

- **처음 안**: 인계 전용 endpoint를 새로 만든다 → **접었다.** 로그인 성공 응답 조립이 2벌이 된다. 같은 endpoint에 티켓 파라미터를 더하니 분기 한 줄로 끝났다.
- **처음 안**: 티켓이 인증 결과를 담아 재검증 없이 세션만 발급한다 → **접었다.** 그 순간 티켓이 곧 로그인 권한이 된다. 재시도는 비밀번호를 다시 검증하게 두고, 티켓은 **동의**만 나르게 했다.
- **처음 안**: 미들웨어에서 `purpose` 클레임만 막는다 → **넓혔다.** 토큰 종류를 열거하는 방식이라 2FA 등록 토큰은 그대로 뚫려 있었다.
