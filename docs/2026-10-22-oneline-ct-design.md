## §2 CT 하나 — 다섯 단계

위치 = `packages/backend/src/utils/one-line-ct/`(컨트롤타워 등재). 입구는 이 CT 의 함수만 부른다. 라우트 안 인라인 판단 0.

| 단계 | 함수 | 입력 → 출력 | 누가 판단 |
|---|---|---|---|
| ① 듣기 | `listenLine(line, ctx)` | 한 줄 → **의도**(목적 · 혜택 원문 · 기간 · 상품 낱말 · 대상 단서 · 주소 · 업종) | 규칙(숫자 · 날짜 · 주소는 규칙이 뽑는다) + 두뇌(목적 · 대상) |
| ② 판단 | `judgeLine(intent, company)` | 의도 + 회사 → **계획**(그릇 · 구성 · 대상 · 형태) | 두뇌 · 사람이 바꿀 수 있다 |
| ③ 진단 | `diagnoseLine(plan, materials)` | 계획 + 가진 재료 → **빈 칸 목록**(칸마다 이유 · 채우는 방법) | 코드(구성의 칸표 대조 · 추측 0) |
| ④ 채우기 도움 | `gatherMaterials(company, plan)` + 칸별 채움 API | 회사 → 자동으로 채운 재료 / 화면 → 칸 하나씩 | 코드 |
| ⑤ 요리 | `cookLine(plan, materials, prefs)` | 재료 + 요구 → **결과물**(그릇별) | 두뇌(문구) + 코드(구성 · 조립) |

### 2-1 두뇌 자리 = 한 곳 (`LineBrain`)

두뇌가 하는 일은 넷뿐이다. 이 넷만 인터페이스로 두고, 지금은 AI 모델 호출로 채운다. 아람이 준비되면 이 구현만 바꾼다(CT 바깥 변경 0).

| 두뇌 함수 | 하는 일 | 지금 쓰는 것 |
|---|---|---|
| `readIntent` | 한 줄의 목적 · 대상 단서 읽기 | recommendTarget 의 한 줄 읽기 · one-line-facts 규칙 |
| `pickPlan` | 그릇 · 구성 고르기(+ 이유 한 줄) | 템플릿 match 정규식(규칙) → 두뇌 + 규칙 대체 |
| `writeCopy` | 구성의 문구 칸 채우기(실물 예시 참고) | fillLineTemplateCopy |
| `judgeVisual` | 헤드라인 템플릿 고르기 | pickLineHeadlines |

규칙: 두뇌가 실패하면 규칙 대체로 내려간다(빈 결과 0). 숫자 · 날짜 · 혜택 원문은 두뇌를 지나지 않는다(지어낸 혜택 0 · 기존 원칙).

### 2-2 의도(LineIntent) — 모든 입구가 같은 모양을 받는다

```
goal: 'make' | 'ask'            // 만들어 달라 / 물어보는 말
purpose: 'sale' | 'launch' | 'event' | 'season' | 'menu' | 'notice' | 'retention'
benefit: 원문 | null            // 사람이 적은 글 그대로
period: { end: YYYY-MM-DD | null, mentioned: boolean }
productTerms: string[]          // 한 줄 속 상품 낱말(최대 3)
audienceHints: string[]         // "30대 여성" "지난달 구매" 같은 대상 단서
urls: string[]                  // 붙인 주소(읽기 대상)
plateHint: 'sms' | 'dm' | 'email' | 'inapp' | 'journey' | 'auto' | null   // 들어온 입구
```

## §3 재료 — 어디서 채우나 (연동 회사 / 비연동 회사)

구성의 칸표(§4)가 「무엇이 필요한가」를 정하고, 이 표가 「어디서 채우나」를 정한다. 위에서부터 채우고, 그래도 빈 칸만 묻는다.

| 칸 | 자사몰 연동 회사 | 비연동 회사 | 그래도 비면 |
|---|---|---|---|
| 상품(사진 · 이름 · 가격 · 링크) | 몰 상품 자동 추천(한 줄 상품 낱말 · 최근 판매) → 고르기 한 번 | 사진 올리기 + 이름 · 가격 칸 / 상품 페이지 주소 붙이면 읽어서 채움 | 묻는다(필수 칸이면 만들기 막음) |
| 대표 사진 · 분위기 사진 | 몰 상품 사진 · 몰 배너 | 올리기 / 페이지 주소 읽기 | 스튜디오로 만들기(크레딧 · 사람이 누를 때만) |
| 첫 화면 헤드라인 | 스튜디오 템플릿 3안(1021 구현) | 같음 | 건너뛰면 색면 표지 |
| 특징 · 코디 · 맛 꼬리표 | 몰 상품 설명에서 두뇌가 뽑아 제안 → 고치기 | 한 줄씩 적기(두뇌가 예시 3개 제안) | 그 구역 없음 |
| 사용 단계 | 두뇌 제안 → 고치기 | 같음 | 그 구역 없음 |
| 후기 | 몰 후기(연동된 곳만 · 미검증: 몰마다 후기 API 유무) | 붙여 넣기 | 그 구역 없음 |
| 혜택 · 쿠폰 코드 · 마감 | 한 줄에서 뽑은 원문 → 확인 | 같음 | 세일 · 이벤트 구성이면 묻는다 |
| 매장 정보 | 브랜드 키트 | 브랜드 키트 / 한 번 적으면 저장 | 메뉴판 구성이면 묻는다 |
| 브랜드(이름 · 로고 · 색) | 브랜드 키트 | 같음 | 회사 이름 |

원칙:
- 이미 가진 것은 다시 묻지 않는다(브랜드 키트 · 몰 · 지난번 입력).
- 묻는 말은 칸마다 한 줄 · 왜 필요한지 한 줄 · 채우는 버튼 하나(몰에서 고르기 / 올리기 / 붙여 넣기 / 만들어 줘).
- 필수 칸이 비면 「이대로 만들기」를 막고 그 칸으로 데려간다. 선택 칸은 비어도 만든다(그 구역만 빠진다).

## §4 요리 틀 — 구성 5종 (시안 1022 · `utils/line-compositions.ts`)

| 구성 | 목적 | 구역 순서(포스터 아래) | 필수 칸 |
|---|---|---|---|
| 주인공 상품 | launch | 대표 상품 크게 → 특징 3 → 사용 단계 → 후기 → 함께 쓰는 상품 → 혜택 → 코드 → 마감 | 상품 1 · 특징 3 |
| 세일 진열장 | sale | 마감 → 혜택 → 인기 순위 4 → 종류별 진열 → 코드 | 혜택 · 마감 · 상품 4 |
| 룩북 | launch(패션) · season | 분위기 사진 3 → 종류별 진열 → 코디 제안 2 → 혜택 | 분위기 사진 3 · 상품 4 |
| 메뉴판 | menu · season(외식) | 대표 메뉴 크게 → 맛 꼬리표 → 메뉴 진열 → 사진 → 후기 → 매장 안내 → 혜택 | 대표 사진 1 · 메뉴 4 · 매장 |
| 이벤트 | event | 참여 방법 1·2·3 → 혜택 → 코드 → 마감 → 상품 | 참여 방법 3 · 혜택 · 마감 |

- 고르기 = 두뇌가 목적 · 업종 · 가진 재료로 하나 추천(이유 한 줄) · 사람이 바꿀 수 있다.
- 칸표 = 진단의 기준(`compositionMissing`). 구성마다 문구 칸(제목 · 소제목 · 구역 제목 · 마무리 · 버튼)을 두뇌가 채운다.
- 시안에서 고칠 것: 후기 별 색(강조색이 옅으면 안 보임) · 혜택 조건 글 노출 · 기존 4종(빅세일 · 신상품 · 이벤트 · 계절)을 이 5종으로 흡수(옛 구성 삭제).

## §6 화면 — 한 흐름

1. 한 줄 입력 → ①② (2~4초 · 로딩 막) → **판단 카드**: "세일 진열장으로 만들게요 · 이유 한 줄 · 바꾸기"
2. **재료 판**: 구성 미리보기(왼쪽) + 칸 목록(오른쪽 · 채워진 칸 = 출처 없이 그림으로 · 빈 칸 = 채우기 버튼). 연동 회사는 대부분 이미 채워져 있다.
3. 필수 칸이 다 차면 「만들기」 → ⑤ → 결과(편집 가능 · 다시 만들기 0원 규칙은 지금 과금 그대로).
- AI 존 틀 · 모바일 반응형 · 커스텀 모달 · 모델명 0 · 출처 줄 0(디자인 하한).
- 지금 단계식 창(LineStepsModal · 질문 하나씩)은 이 재료 판으로 바뀐다. 「한 번에 하나」가 아니라 「한 화면에 빈 칸만」.
