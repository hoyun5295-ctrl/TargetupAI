## 1. 배경·근거

- 벤치마크 실측(스샷 4장): 쿠팡이츠 = 큰 이미지 + 흰 바닥 + "확인" 1버튼. 스타벅스 = 풀블리드 이미지 카드 + "오늘 하루 보지 않기 / 닫기" 텍스트 2개 + 카드 페이징(1/5). 공통점 = **이미지가 전부, 나머지는 극단적으로 심플**. 이미지 클릭 = 해당 이벤트로 바로 이동(자사 앱이라 딥링크를 스스로 앎).
- 현행 한줄로 인앱: theme 6종(auto/light/dark/brand/vibrant/minimal) + card_style 4종(classic/bubble/ticket/poster) + design(treatment 4종·motion·backdrop) + 13 콘텐츠 블록 + 템플릿 8종. 선택 축이 많을수록 마케터 산출물 품질 하한이 내려간다 — 벤치마크와 정반대 방향이었음.
- 실전 사고 증거(2026-07-18 팝폰): CTA action_url에 수기 입력된 `m/drdifferent`(스킴 없는 비도메인) → 앱에서 무반응. **URL 수기 입력 자체가 사고 축** — 자동 연결이 근본 해결.
- 승리 공식(영구 원칙): 편리함(1클릭) + AI 풍부 활용. 스튜디오·라이브러리는 "만들고 끝"(캔바·GPT)이 아니라 "만들고 → 그 자리에서 발송"까지 이어져야 차별화가 성립한다.

## 2. 인앱 단순화 — 템플릿 2종

> ★ 2026-07-18 정정2 (Harold 최종 확정): 채널별 구도 —
> **웹** = 기존 다양성(모달·슬라이드·토스트·플로팅 + 테마·정예 템플릿·블록) 전부 유지 + **포스터형 추가 옵션(5번째)**.
> **앱** = 2종 구도: **기본형**(이미지·문구·버튼 — 위치를 중앙 모달/바텀 시트로 분기) + **포스터형**(전면 이미지 — 신규).
> 포스터형은 웹·앱 공용 template 값(full_image) 하나로 저장·서빙되고, 앱 네이티브 렌더는 통합 계약에 명시
> (구버전 앱 = 바텀 시트 안전 폴백, 팝폰 구현은 디자인 개선 재빌드에 동승). 흰 바닥·버튼 브랜드색·이미지 필수·CTA 1개는
> 포스터형 내장 규칙. "웹 신규 UI 2종 한정·테마 UI 제거" 문구는 폐기.

### 2-1. 템플릿 정의

| | A형 — 미디어+텍스트 (현 팝폰형) | B형 — 이미지 풀블리드 (쿠팡이츠·스벅형) |
|---|---|---|
| 구성 | 이미지(상단) + 배지 + 제목 + 본문 + CTA 버튼 스택 | 이미지가 카드 전체. 텍스트는 이미지 위 오버레이(선택) |
| 하단 | 흰색 고정 + CTA 1~2개 + "다시 보지 않기/닫기" | 흰색 고정 + CTA 1개(또는 버튼 없이 "다시 보지 않기/닫기" 텍스트만) |
| 색 | 버튼색만 브랜드 컬러 | 버튼색만 브랜드 컬러 |
| 용도 | 문안 중심 공지·혜택 안내 | 이벤트·시즌 비주얼 소재 (스튜디오 산출물의 주 소비처) |

- 색 정책: `background_color` 계열 선택 UI 제거 → 흰색 고정. 버튼색 기본값 = 브랜드 키트 주 색상 자동 주입, 직접 변경 허용. 텍스트색은 배경 대비 자동(흰 바닥=진한 글씨).
- 유지되는 마케팅 축(변경 없음): 트리거·빈도·시간대/요일/한도·세그먼트·A/B variant·개인화 변수·채널(web/app).
- 신규 생성 UI에서 제거(비노출): theme 선택, card_style 선택, design treatment/motion/backdrop, animation, 13블록 자유 조립 진입(A/B형 프리셋 구성으로 대체).

### 2-2. 비파괴 호환 규칙 (필수)

### 2-3. B형 구현 (렌더 계약 신설)

- `template` 축에 신규 값 1개 추가(가칭 `full_image`). 기존 8종은 발행물 호환용 유지, 신규 UI에서는 A형(center_modal 프리셋)·B형(full_image)만 노출.

## 3. CTA 자동 연결

- **웹(SDK 연동 몰)**: URL 입력창 대신 "연동 몰에서 선택" 픽커 — 이벤트 페이지·상품 목록을 싱크 데이터에서 검색/선택 → action_url·이미지·상품명 자동 주입. **모바일 DM의 기존 자산(이벤트·상품·이미지 후보 자동 끌어오기) 재사용**(신규 개발 아님 — 소비처 확장). 정확한 공용화 지점은 착수 시 grep으로 확정.
- **앱(네이티브)**: 계약 규칙 1건 추가 — "CTA는 연동 몰 웹 URL 기준. 앱은 자체 라우팅 규칙으로 매핑하고, 매핑 불가 시 인앱 브라우저로 연다." 몰마다 제각각인 앱 내 경로 문제 종결.
- 수기 URL 입력은 유지하되 검증 강화: 스킴 없는 비도메인 값(`m/xxx`류)은 저장 시 경고 표시(0718 팝폰 사고 재발 방지). 자동 보정은 도메인 형태만(기존 sanitizeActionUrl 유지).

## 4. AI 이미지 스튜디오 (마케팅 캘린더 대체)

### 4-1. 기능 구성

| 기능 | 내용 | 원가 성격 |
|---|---|---|
| 프롬프트 생성 | 자연어 → 이미지 생성(외부 이미지 생성 모델 API). 채널 규격 프리셋(인앱 B형·DM 카드·이메일 히어로·MMS·카카오)으로 비율/해상도 맞춰 생성 | 건당 실원가 → 크레딧 |
| 누끼(배경 제거) | 상품/피사체 배경 제거. 자가 호스팅 모델 우선 검토(저원가) | 저원가 → 정책 결정 |
| 텍스트 오버레이 편집 | 이미지 위 문구 레이어(서체·색·정렬) — AI 아님, 에디터 기능. DM/인앱 에디터 자산 재사용 | 무료 |
| 상품 배너 1클릭 | 연동 상품 선택 → 누끼 → AI 배경 생성 → 규격별 소재 완성. **간판 시나리오** | 크레딧 |
| 시즌 선제 제안 | 마케팅 캘린더에서 유일하게 살릴 지능 — "다가오는 시즌 소재 미리 생성" 제안 카드 | 제안=무료, 생성=크레딧 |

### 4-2. 가드레일 (영구 룰 상속)

- **혜택 문구를 이미지 픽셀에 AI가 새기지 않는다.** 생성은 비주얼(배경·연출)만. "30% 할인" 같은 혜택 문구는 반드시 텍스트 오버레이 레이어로 사용자가 직접 입력 — feedback_ai_no_arbitrary_benefit(AI 임의 혜택 생성 금지) 룰의 이미지판. 픽셀에 구우면 검증·수정·차단이 불가능해진다.
- 모델명 UI 노출 금지 — "AI 이미지 생성"류 추상 명칭만.
- 지표·미리보기에 목업 값 금지.

### 4-3. 크레딧·과금

- 생성 = 크레딧 차감(표시 = 실차감). 20크레딧 이상 작업 = 사전 확인 모달(기존 룰).
- "GPT면 공짜" 반발 대응: 월 소량 무료 쿼터 + 초과분 크레딧. 판매 정체성은 생성 도구가 아니라 **"브랜드 에셋 라이브러리 + 전 채널 1클릭 소재 공급"**.
- 단가·쿼터 수치 = Harold 결정 항목(§8).

### 4-4. 메뉴 전환

- 마케팅 캘린더 자리 대체(제거가 아닌 대체). 착수 전 캘린더 실사용 데이터(생성·조회 이력)와 소비처 영향표 확인 후 전환.
- 신규 메뉴 = NEW 뱃지(4~6주 후 제거), Journey Builder 동급 디자인 기준, 1클릭 UX 원칙 적용.

## 5. 에셋 라이브러리

### 5-1. 저장 모델 (테이블 설계안 — DDL은 착수 시 information_schema 검증 + Harold 직접 실행)

신규 테이블(가칭 `cdp_assets`): id, company_id, kind(uploaded/generated/nukki/variant), source_asset_id(원본 FK — 누끼·변형본의 계보), url/storage_path, width/height/bytes, format, prompt(생성물), channel_spec(변형본의 대상 규격), created_by, created_at. 회사별 용량 합산 = bytes SUM.

### 5-2. 동작

- 축적원: 스튜디오 생성물 + 각 채널 에디터의 업로드 이미지(업로드 시 자동 등재) + 누끼/규격 변형 결과.
- 소비처: DM·이메일·MMS·카카오·인앱 에디터에 "라이브러리에서 선택" 진입점 통일.
- **규격 자동 변환**: 꺼낼 때 대상 채널 스펙으로 크롭·리사이즈·용량 압축(MMS 용량 제한·카카오 검수 규격이 체감 최대 지점). 채널별 스펙 표는 구현 시 실측 규격으로 확정.
- 용량 한도 = 플랜 축(자연스러운 업그레이드 동선). 수치 = Harold 결정 항목.

### 5-3. 소재 성과 루프 · A/B

- 발송/표시 기록에 asset_id 연결 → 라이브러리 카드에 실성과(사용 캠페인 수·클릭률) 표시. 데이터 소스 명시(목업 금지), cold start 안내.
- 인앱 A/B: 기존 variant 스키마(parent_message_id·variant_weight) 재사용 — 이미지 2장으로 A/B 자동 분배. 스키마 추가 없음.
- 성과 좋은 소재 스타일을 다음 생성 제안에 반영(AI 메모리 결) — P5 이후 고도화.

## 8. 확정 결정 (2026-07-18 Harold)

1. **크레딧**: 생성 1회 = 1크레딧(500원) = 프로급 2K 후보 2장(원가 약 380원 — 박리 원칙). 4K 고해상 = 2크레딧. 재생성 동일 과금. **누끼 = 무료**(자가 호스팅 전제 — 외부 유료 API 전환 시 재검토). **무료 쿼터 = 월 10회**.
2. **용량**: 하위 0.5GB / 중위 2.5GB / 최상위 5GB(+협의) — 플랜명 매핑은 구현 시 확정. **임시 생성물(라이브러리 미저장) = 7일 후 자동 삭제(화면 명시)**. 저장 에셋 = 한도 내 보관, 캠페인 사용 에셋 = 자동 삭제 제외, 한도 초과 = 생성·업로드 차단 + 정리 유도.
3. **표기명**: A형 = "기본형"(이미지·문구·버튼), B형 = "포스터형"(전면 이미지, 내부값 full_image — card_style 'poster'와 코드 분리). 선택 UI = 실물 미니 미리보기 카드 2장.
4. **마케팅 캘린더 = 즉시 전환**(현 사용자 0). 스튜디오 퀄리티 = 프로급 생성 모델 + 한글 오버레이·규격 프리셋·브랜드 키트(체감 퀄리티의 절반). UI 모델명 노출 금지.
5. **팝폰 재빌드 = 즉시 병행 트랙**: app.json `name` "poppon-app"→"팝폰"(홈화면 라벨 — slug는 EAS 연결 축이라 유지), **업데이트 안내 모달 신설**(그 안내는 OS 기능이 아니라 앱 자체 구현 — 서버 최신버전 설정값 비교 → 커스텀 모달 → 스토어 딥링크), B형 네이티브 렌더, 로그인 콘솔 설정 2건.
