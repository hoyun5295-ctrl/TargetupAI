### 3-0. 방식 = 등급표 교체 (Harold 「등급표를 교체하면 되잖아」)

### 3-1. 막는 곳 · 보이는 곳

## 5. E. AdminDashboard 분리

### 5-1. 목표 구조

```
pages/AdminDashboard.tsx            본체: 머리 · 요약 카드 · 메뉴 · 공유 상태 · 「이 key 면 이 화면」 연결 자리

components/admin/tabs/<기능>Tab.tsx  기능 화면 하나 = 파일 하나(상태 · 요청 · 모달 · 화면을 함께)
components/admin/company-detail/    고객사 상세 설정 모달 + 하위 탭 9
```

- 본체가 화면에 넘기는 것(interface)은 작게: 공유 상태(고객사 목록 · 요금제 · 라인그룹 등 16개 중 그 화면이 쓰는 것)와 「목록 새로고침」 같은 알림 함수뿐.
- 이미 빠진 8개 탭과 같은 모양이다. 새 방식을 만들지 않는다.

### 5-2. 옮기는 방법 (동작 변경 0)

1. **손으로 다시 쓰지 않는다.** 스크립트가 줄 범위를 잘라 새 파일로 옮기고, 옮긴 줄 전부를 원본과 글자 대조한다(공백 · 들여쓰기만 다를 수 있음 → 대조는 들여쓰기 제거 뒤).
2. 한 화면을 옮길 때 그 화면의 **상태 · 처리 함수 · 효과(useEffect) · 모달 · 화면**을 한 번에 옮긴다. 처리 함수가 어느 화면 것인지는 「그 함수를 부르는 화면 줄」로 정하고, 둘 이상 화면이 부르면 본체에 남긴다.
3. 옮긴 화면이 본체 상태를 쓰면 props 로 받는다. 받는 목록은 스크립트가 「옮긴 코드 안에서 쓰는데 옮긴 코드 안에 선언이 없는 이름」으로 뽑아 사람이 확인한다.
4. 효과(useEffect)의 실행 조건(`activeTab === 'x'`)은 그대로 옮긴다. 화면 파일이 「열렸을 때만 그려지는」 구조로 바뀌면 진입 시점의 조회 타이밍이 같아야 한다 → 지금 「탭 진입 때 조회」 · 「처음 한 번」 · 「60초 주기」 가 바뀌지 않게, **주기 · 뱃지 조회는 본체에 남긴다.**
5. 한 화면 = 한 단계. 단계마다 tsc 0 · 계약 시험 전체 · 렌더 실측(§6)을 통과해야 다음 화면으로 간다.
