## 왜 되풀이됐나 (2026-10-24 플래너 9건을 생긴 때로 가른 결과)

1. **새 규칙을 그 규칙이 생긴 기능에서만 고쳤다** — 1020 출처 0 · 1024 발송 직전 차감 · 지문에 번호 · 한 줄 + 질문 · 1019 이미지 스튜디오 서버 요금제 문 · 1018 검사 3분할이 다른 기능에 퍼지지 않았다.
2. **검토가 바뀐 줄만 본다** — Codex 증분 · 요청받은 기능만 구조체크라, 손대지 않은 옛 경로는 검토를 한 번도 받지 않는다.
3. **막은 것을 지키는 기계 장치가 없었다** — 기능마다 손으로 다시 막았다. 손으로 등재한 표는 등재한 것만 지킨다(LESSONS_BACKEND 1014).

그래서 시험은 **소스에서 기계로 대상을 뽑는다**(주소 · 호출 · 화면 파일). 표에 적은 예외만 통과하고, 새 주소 · 새 호출은 분류 없이 들어오면 실패한다.

## 점검표 (기계로 못 잡는 것 · 구조체크 · Codex 요청문에 의무)

- R18 판정 시계 — 기간 · 달 · 만료를 재는 칸이 그 사건의 시각인가(생성 · 갱신 시각이면 예약 · 다시 시도 · 대조가 시계를 옮긴다 · 1026).
- R4 쓸 결과 — 돈을 걷는 판정(accept · 정산 직전)이 정규화가 끝난 최종 글을 보는가(빈 항목 · 객체 칸 · 기본값으로 채운 항목은 결과가 아니다 · 1026 같은 부류 두 번).
- R21 외부 부품 보안판 — 운영 의존성 `npm audit --omit=dev` = 0 인가 · 서버 Node 가 지원 중인 LTS 인가(지원 끝 = 보안판이 더 안 나온다) · 의존성 판을 올리면 서버 `npm ci` 단계와 설치 스크립트 허용(`allowScripts`)을 배포 안내에 적었는가(1026 · 기계 시험은 오프라인이라 경보 목록을 못 본다) · ★1029 고객 PC 에 실리는 싱크에이전트 Node 도 지원 중 LTS 의 보안판인가(판 = `release/build-manifest.json` `nodeVersion` · exe 안에서 읽은 값 · modern = Node 24 · 구형 티어 16 · 12 는 OS 바닥 때문에 못 올림 → R28 입구 거름이 그 티어의 처방).
