### 1-3. 교차검증 프로토콜 (Closed 조건)

버그가 "해결됨"이 되려면 반드시 아래 **2단계를 모두 통과**해야 한다.

**1단계 — 코드 검증 (Claude):**
- 수정 코드가 관련 경로 **전부**에 일관 적용되었는지 확인
- 발송 관련이면 5개 경로 전수 점검 매트릭스 필수
- AI 관련이면 한줄로 + 맞춤한줄 양쪽 확인
- TypeScript 타입 체크 통과 근거 제시

**2단계 — 실동작 검증 (Harold님):**
- 실서비스(app.hanjul.ai)에서 점검 방법대로 실행
- 기대 결과와 실제 결과 일치 확인
- 스크린샷/로그 등 증거 확보 (가능한 경우)

**판정:**
- 2단계 모두 통과 → ✅ Closed
- 하나라도 실패 → 🔄 Reopened + 실패 원인 분석 → 재수정

### 1-4. 에러 대응 프로토콜 (신규 버그 발생 시)

1. **증상 기록:** 기대 결과 / 실제 결과 / 재현 절차 / 환경
2. **원인 특정:** 3줄 이내로 근본 원인 요약
3. **해결 옵션:** 2가지 이상 제시 (장단점/리스크/소요) → Harold님 선택
4. **최소 수정:** 선택된 옵션으로 수정 + 관련 경로 전수 점검
5. **교차검증:** 1-3의 2단계 프로토콜 실행

### 🟠 B-0904-1 이메일 캠페인 히어로 — 구도 '기본'으로 넣은 메인 이미지가 수신함에서 통째로 사라진다 (🟡 코드 수정 완료·배포 대기) — 2026-09-04 접수 `cmtl5wq5v0800jnotk46ozykf`(남지현 P1)

> **증상**: 히어로(메인 비주얼) 이미지를 구도 **기본**으로 넣으면 편집 화면 미리보기(모바일·PC)는 정상인데, 실제 발송(테스트 발송) 수신 시 그 자리가 **검정 화면**으로만 나오고 이미지가 없다. 같은 메일에서 구도 **분할·타이포**는 정상. 환경 = 크롬 · 수신 확인은 하이웍스(Harold 확인).
> **원인(코드 실측)**: 기본 구도만 사진을 CSS `background-image`로 내보내고 있었다([`renderHero`](../packages/backend/src/utils/email/email-section-renderer.ts:150) 옛 161행). 분할 구도는 같은 URL을 `<img>`로 내보낸다(141행). **같은 수신함·같은 URL인데 태그가 갈랐다** — 접수 원문의 "분할·타이포는 정상"이 그대로 판별식이었다. CSS 배경을 지우는 클라이언트에서는 폴백색 `background-color:${b.text}`(어두운 본문색)만 남아 검정 면이 된다. 그 줄의 주석에도 "아웃룩은 배경이미지 미지원 → bg색 폴백"이라고 이미 적혀 있었다.
> **왜 VML로 안 고쳤나**: MSO 조건부 주석(`<!--[if mso]>`)은 워드 엔진 아웃룩만 해석한다. 웹메일이 CSS 배경을 지우는 경우는 못 막으므로 **수신 클라이언트를 확정하지 않아도 닫히는 처방**을 택했다.
> **수정**: 기본 구도를 **`<img>` 한 장 + 그 아래 텍스트 밴드**로 재구성하고 분할 구도의 이미지 셀 배관을 세로로 재사용했다(높이·맞춤·초점이 같은 식이라 `EMAIL_HERO_PROPS` 계약이 그대로 통과). 오버레이 토글(`overlay_gradient`)은 "밴드를 어둡게"로 이어받아 **색을 지정하지 않은 기존 캠페인의 흰 글씨가 옛 스크림 위와 같은 대비로 그대로 읽힌다**(밴드를 끄면 본문색으로 내려간다 = 흰 글씨가 흰 배경에 묻히지 않는다). 사진 위 텍스트 섀도는 사진 위가 아니게 되어 제거.
> **바뀌는 것(승인 완료)**: 기본 구도 + 이미지 캠페인은 조판이 "사진 위 글자"에서 "사진 아래 글자"로 바뀐다. 사진 위에 글자를 얹는 조판은 이메일에서 신뢰할 수 없어(이 접수가 그 증거) 남겨 두지 않았다.
> **계약**: `email-property-contract.ts` `EMAIL_PHOTO_AS_IMG_TAG` 신설 — **이메일에서 사진은 반드시 `<img>`로 나간다**(장식용 `linear-gradient`는 대상 아님 · 금지 대상은 `url(...)`뿐). 파리티가 구도 2종에서 `<img>` 존재와 `background-image:url(` 0건을 함께 밟는다. "이미지 URL이 문자열에 들어 있다"만 보는 계약은 이 형태를 못 잡는다.
> **검증**: BE tsc 0 · FE tsc 0 · **backend 전체 226파일 3,584건 통과**(골든 스냅샷 회귀 0 — 스냅샷 fixture에 이미지 있는 히어로가 없어 무접촉) · 실렌더 실측 = `<img src="…" width="600" height="320" style="…object-fit:cover…">` + `background:#171717` 밴드, 문서 전체 `background-image:url(` **0건**.
> **실측(배포 후 Harold님)**: 하이웍스 계정으로 기본 구도 히어로 테스트 발송 1건 — 사진이 나오면 종결.
> **추가 과제(범위 밖 · 착수 판단은 Harold님)**: 히어로 편집기의 **오버레이 프리셋**(`overlay` = 없음·소프트·강하게·브랜드 틴트·상단)은 이번 변경 이전부터 이메일 렌더러가 한 번도 읽지 않는 죽은 컨트롤이다(DM 전용). 이번 축이 만든 것이 아니라 기록만 한다.
